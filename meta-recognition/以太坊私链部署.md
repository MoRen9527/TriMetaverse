# 以太坊私链部署（Geth + Prysm，源码编译到联调启动）

本文档整理自 share 对话《部署私链 Geth Prysm》，目标是把“正确做法”串成一条主线，同时把对话中遇到的典型错误与修复路径作为分支，便于复现与排障。

> 说明：在以太坊合并（The Merge）之后，PoS 网络需要执行层（EL）与共识层（CL）协同。只跑 Geth 只能得到执行层，并不是完整 PoS 链。

---

## 0. 你要部署的“完整私链”包含哪些组件

- Execution Client（执行层客户端）：Geth（也可替换 Nethermind / Besu / Erigon）
- Consensus Client（共识层客户端）：Prysm（也可替换 Lighthouse / Nimbus / Teku / Lodestar）
- Validator Client（验证者，可选但通常需要）：Prysm Validator 可单独运行
- JWT Secret（必须）：EL 与 CL 通过 JWT 共享密钥文件鉴权通信

结论：**完整 PoS 私链 = Geth + Prysm（Beacon）(+ Validator) + JWT**。

---

## 1. 方法总览（本对话覆盖的路径）

本对话主要覆盖了这条路径：

1) 确认版本与构建环境（Go 等）
2) 源码下载并编译：先 Geth，再 Prysm
3) 解决 Prysm 构建目标/输出路径的坑（Bazel target 与产物路径）
4) 启动顺序：Bootnode → Geth → Beacon Node(s) → Validator
5) 用 RPC/API 验证链是否在出块（EL 区块号、CL slot/head/finality）
6) 遇到不出块/slot=0 时，根据日志做定位（典型：Deposit 合约未部署/不可读）

## 2. 主线：一步一步从源码到可运行

### Step 1：准备 Go 编译环境

检查 Go：

```sh
go version
```

（对话示例输出：`go version go1.23.6 linux/amd64`）

---

### Step 2：下载并编译 Geth

克隆（对话中使用了 `latest` 思路；也可直接用具体 tag/branch）：

```sh
git clone --depth 1 --branch latest https://github.com/ethereum/go-ethereum.git
cd go-ethereum
```

编译：

```sh
make geth
```

验证：

```sh
./build/bin/geth version
```

---

### Step 3：下载 Prysm 源码

克隆（建议带 `--recursive`；对话中也强调子模块）：

```sh
git clone --recursive https://github.com/prysmaticlabs/prysm.git
cd prysm
```

若你已克隆但不确定子模块是否齐全：

```sh
git submodule update --init --recursive
```

---

### Step 4：安装/确认 Bazel（Prysm 构建工具）

对话中采用 apt 安装 Bazel，并要求检查版本：

```sh
bazel --version
```

---

### Step 5：编译 Prysm（关键：不要在错误目录/错误 target 上死磕）

#### 5.1 常见错误：`//beacon-chain` 找不到包

对话里出现过：

- `bazel build //beacon-chain` → `no such package 'beacon-chain': BUILD file not found`

原因：你当前 Prysm 版本/目录结构里，`beacon-chain` 并不是 Bazel 的顶层 target。

#### 5.2 修复：在 Prysm 根目录构建正确的 target

对话最终验证可行的命令是：

```sh
bazel build //cmd/beacon-chain
```

提示：构建完成后，Bazel 输出的可执行文件路径可能不是你直觉中的 `bazel-bin/cmd/beacon-chain/beacon-chain`，而是带下划线目录。

#### 5.3 验证方式 1：用 `bazel run`（最稳）

对话中验证成功的方式：

```sh
bazel run //cmd/beacon-chain -- --version
```

（示例输出：`beacon-chain version Prysm/Unknown/Local build...`）

---

### Step 6：生成并配置 JWT Secret（不需要单独“部署”服务）

结论：JWT 只是一个共享密钥文件。

对话中给的生成命令：

```sh
openssl rand -hex 32 | tr -d "\n" > /path/to/jwtsecret
```

curl -X POST http://127.0.0.1:8545 -H "Content-Type: application/json" \

## 4. 验证：怎么确认“链在出块”

### 4.1 执行层（Geth）区块高度

对话给出的 `eth_blockNumber`：

```bash
curl -X POST http://127.0.0.1:8545 \
  -H "Content-Type: application/json" \
  --data '{"jsonrpc":"2.0","method":"eth_blockNumber","params":[],"id":1}'
```

返回的 `result` 是十六进制（例如 `0xa` 表示 10）。

### 4.2 共识层（Beacon）slot / head

对话给出的 headers 查询：

```bash
curl -X GET http://127.0.0.1:4501/eth/v1/beacon/headers | jq
```

### 4.3 Finality（最终确定）

```bash
curl -X GET http://127.0.0.1:4501/eth/v1/beacon/states/head/finality_checkpoints | jq
```

## 5. 分支：典型错误与修复（来自对话）

### 分支 A：Bazel target 找不到 / 目录结构变化

现象：

- `bazel build //beacon-chain` 报 `no such package` / `BUILD file not found`
- 你发现 `cmd/prysm-beacon-chain` 不存在，只有 `cmd/beacon-chain`

修复：

- 在 Prysm 根目录使用：

```sh
bazel build //cmd/beacon-chain
```

- 验证时优先用：

```sh
bazel run //cmd/beacon-chain -- --version
```

### 分支 B：编译成功但找不到可执行文件路径

现象：

- Bazel 输出提示产物类似：`bazel-bin/cmd/beacon-chain/beacon-chain_/beacon-chain`
- 你执行 `./bazel-bin/cmd/beacon-chain/beacon-chain` 报 `No such file or directory`

修复：

- 直接 `bazel run`（对话中最终就是靠它验证成功）

或（如果你一定要手动执行）按 Bazel 提示的真实路径运行。

### 分支 C：slot 一直是 0 / 日志出现 `no contract code at given address`

对话里出现的日志特征：

- bootnode / beacon chain：`Unable to process past deposit contract logs... no contract code at given address`
- validator：`Waiting for beacon node to sync to latest chain head`

对话给出的判断：**很可能是 Deposit Contract（质押存款合约）未部署或配置不一致**，导致共识层读不到存款日志，验证者无法正常参与，网络就不出块。

对话中提供的检查方法（示例地址用 `0x4242...`，实际以你的链配置为准）：

```bash
curl -X POST http://127.0.0.1:8545 \
  -H "Content-Type: application/json" \
  --data '{"jsonrpc":"2.0","method":"eth_getCode","params":["0x4242424242424242424242424242424242424242", "latest"],"id":1}'
```

- 返回 `0x`：说明该地址没有合约代码（未部署/地址不对）

对话里还给出了一个极简的 `DepositContract` 示例（用于发出存款事件，供共识层读取）。部署方式包含：

- Remix 部署（对话中标为“最简单”）
- Geth 控制台手动部署（需要 ABI/bytecode）

部署完成后，再重启相关组件并重新检查 slot 是否开始递增。

## 6. 最小Checklist（跑通为止）

- [ ] Geth 启动参数包含 `engine`，并正确配置 `--authrpc.jwtsecret`
- [ ] Prysm（beacon）正确配置 `--execution-endpoint` 与 `--jwt-secret`
- [ ] `bazel run //cmd/beacon-chain -- --version` 能正常输出
- [ ] `curl .../eth/v1/beacon/headers` 中 slot 递增
- [ ] 若 slot=0 且报 deposit contract 相关错误：先确认 Deposit 合约是否存在且地址/配置一致
