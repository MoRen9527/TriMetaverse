## 模式一 · 双源对表断言（渲染面 ⊆ 真源面）

**场景**：被测对象=「代码生成的命令串/配置串」，其真源=另一处注册面（argparse/schema/白名单）。两侧各自演进时，单侧断言防不住「另一侧改了这边没跟上」的漂移。

**形**：正则抽取两侧集合 → 断言 `rendered_set - source_set == ∅`（渲染面旗标 ⊆ 真源注册集）+ 对已知回退形显式 `assertNotIn`（如 --plan-file）。任一侧漂移即红。

**来源锚**：24365ac `test_migrate_cmd_flags_subset_of_weekly_plane_shift_argparse`（cmd_flags ⊆ weekly_plane_shift argparse 注册集·空集防御分支）。

**适用边界**：parser 内联构造无法 import 时采源码文本对表形（重构抽函数=动现役面故降级）——文本对表是次优解，能 import 优先 import。

## 模式二 · 在役实件锚定（fixture 自构族的盲区补位）

**场景**：测试全 fixture 自构时，仓内在役实件（考卷/配置/payload 件）被误改/破结构/权重漂移 → 回归全绿假阴性。fixture 测试验证「逻辑对合法输入正确」，不验证「在役件仍合法」。

**形**：双案配套——①实件 load→validate errors=[]+合计/族号等值面复验（键存在性抽验≠值面验证）；②定谳值快照逐字段 dict 相等（防「合计对但族间漂移」）+红线值对表。快照案=变更审批义务机械化：改件须同窗升改快照，静默漂移直接红。

**来源锚**：7b13699 双案（rubric-firstshoot.json 实件锚定+权重快照 CPO 定谳值）。

**要点**：实件锚定案必须在卷面声明「投影件属性」（正身=md 清单卷·对表锚=定谳注）——防止实件锚定被误认为制造了第二真源。

## 模式三 · 毕报案数声明笔误家族（禁转抄纪律变体）

**场景**：毕报文字「既有 N 案」类声明与基线实况差——把加后总数当既有数（7b13699 毕报「既有12案」·基线机械定谳=10）。文字声明读数禁转抄，机械定谳一条命令：`git show <commit>^:<file> | grep -c 'def test_'`。

**判定要点**：毕报笔误≠测试真值漂移——现役总数自洽（10+2=12）时零判据影响，如实注记即可；但若总数也对不上，则升级为覆盖缺口排查。

**关联纪律**：既有失败定性禁转抄须独立验（全量读数回报纪律）——本条是其案数声明面的自然延伸。

## 模式四 · 在链缺席断言的时窗敏感（并行多席检出环境）

**场景**：多席共享检出+并行施工节奏下，「X 未在链」的缺席断言=**时点快照非稳态**——施工落链速度快于读数回报周期时，回执信里的现势读数发出即过时（实锚：14:0x 回执「verify 增补案未在链」→8 分钟后 γ 施工两笔落链推翻——勘正回执义务随行）。

**形**：缺席断言回执必带时点戳；「落链快于回报周期」风险自知=发信后保留勘正通道；接力面（门禁跑）前重验在链现势不信任旧读数。本日实操：勘正回执+门禁 v3/v4 两轮时序勘验（log mtime vs 落链时戳双证）。

**关联纪律**：manifest 身份验证先于缺席断言——本条是其时窗维度的延伸（身份对了还要时点新）。

## 模式五 · 毕报读数=「数+基面」二元组（同名数字不同语义）

**场景**：registry 笔文「179全绿」vs 机械真值 176=笔误差 3（第三例）；同日 FSD 笔文「176 全绿」=时点真值非笔误——**同一个数字 176 在不同基面下语义不同**：FSD 时点（verify 13 案时代）176=真值；我 v3 log 176=ddda8dcd 面（落链前 11 秒）；b350f9c 面真值=181。毕报文字读数的验证不只验「数对不对」，还要验「数所指的基面/时点」——只对数字会误判真值笔误，只看基面会漏掉真笔误。

**形**：机械定谳三步——①`git grep -c 'def test_' <commit> -- <path>` 快照案数 ②活体 discover 真跑读数 ③log mtime vs 落链时戳对序——三方对齐才能定谳「笔误/时点真值/基面差」。差值不定谳不销项（179-176=3 构成不臆测·注记差值挂账即可）。

**来源锚**：registry ddda8dcd「179」（笔误实锚）vs 337c546「176」（时点真值实锚）同日同族双例。
