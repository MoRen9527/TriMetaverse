# 元宇宙学院（Meta-Recognition Academy）

“元宇宙学院”是三元宇宙（TMV）里 **元认知（Meta-Cognition）** 的第一部分落地：把“学习 → 贡献 → 评测 → 激励”的循环做成可审计的基础设施，让认知资产可以被积累、被复用、被验证，并持续回灌后续的“元虚拟沙盒”和“元现实落地”。

对应 TMV 螺旋：

- 元现实：现实技能/项目需求与约束（要解决什么问题）
- 元认知（本项目）：课程与任务把知识结构化；AI评测把正确性/质量可量化；链上记录把结果可追溯
- 元虚拟：在可控环境做并行试验（后续阶段接入仿真/沙盒）
- 回灌：把被验证的能力与产出沉淀为“可复用模块/规范/课程”，再推动下一轮学习与贡献

---

## 0. 目标与范围（先做成闭环，再谈沉浸）

### 目标（MVP必须达成）

1. **身份与激励可验证**：用户完成任务后能自动获得链上徽章（最小可行激励）。
2. **贡献可评测**：至少支持一种“代码类任务”的自动评测（可由AI+规则结合完成）。
3. **最小入口可用**：用一个“智能体入口”（本地/命令行/编辑器内均可）完成：连接钱包 → 领取任务 → 提交 → 评测 → 发放徽章。

### 非目标（MVP阶段先不做）

- 不追求3D/2D沉浸式空间（作为第二阶段再引入）
- 不做完整代币经济（先用徽章/学分记账即可）
- 不做复杂的治理与多角色权限（先单管理员/多用户）

---

## 1. 最小闭环（你要能在一周内跑通）

闭环定义：

> 用户连接钱包 → 领取一个任务 → 提交产出（代码/文本） → AI/规则评测 → 链上记录贡献 → 铸造并发放徽章

最小数据对象：

- 任务（Task）：题目、输入/输出约束、评测方式、奖励配置
- 提交（Submission）：提交内容哈希、元数据、提交者地址
- 评测结果（Verdict）：通过/失败、评分、证据/日志摘要
- 徽章（Badge）：ERC-1155 tokenId，代表“完成某类能力证明/成就等级”

---

## 2. 技术基建（元认知的“宪章与账本”）

### EVM链（最小可行）

- 优先：Hardhat 本地网络（开发与演示最快）
- 可选：Geth PoA 私有链（需要更强的“长期运行/多节点”时再切换）
- 阶段0/1链选型结论与触发条件：见 [链基础设施选型.md](../%E9%93%BE%E5%9F%BA%E7%A1%80%E8%AE%BE%E6%96%BD%E9%80%89%E5%9E%8B.md)
- 如需贴近合并后的 PoS 私链（Geth + Prysm，含源码编译与联调排障）：见 [以太坊私链部署.md](以太坊%E7%A7%81%E9%93%BE%E9%83%A8%E7%BD%B2.md)

### 核心合约（只做两件事：记录与发放）

1. **贡献记录合约**：记录“谁在什么时候完成了什么任务，评测结果是什么”。
2. **徽章合约（ERC-1155）**：批量管理徽章类型，按任务/能力维度发放。

合约设计原则：

- 记录尽量轻（链上存关键索引与哈希；详细日志可链下保存）
- 评测可追溯（至少要能复现“为什么通过/失败”的证据摘要）

---

## 3. 核心体验（元认知的“国家门户”）

### 智能体入口（第一版先做到“能跑通”）

智能体需要具备三种能力：

1. **钱包**：连接/切换地址，签名确认（用于领取任务、提交与领奖）
2. **学习终端**：展示课程片段与任务说明（Markdown/网页均可）
3. **任务大厅**：列出任务 → 领取 → 提交 → 查看评测与徽章

### 最小化游戏化

- 不做复杂的“答题”UI
- 只做“闯关任务”：产出必须是可验证的（例如：一个可编译/可测试的合约或脚本）
- 通过即发徽章：让“学习成果”立刻变成“可证明的身份资产”

---

## 4. 三阶段实施路线（按可交付推进）

### 第一阶段：立国奠基（1-4个月）——把闭环做扎实

可交付清单（按优先级）：

1. Hardhat 网络 + ERC-1155 徽章合约
2. 贡献记录合约（或先用事件Event记录贡献）
3. 1条任务线：Solidity入门闯关（最少1个任务）
4. 评测器：AI辅助 + 规则校验（例如：编译通过/测试通过/接口满足）
5. 智能体入口：连接钱包 → 领取 → 提交 → 评测 → 发放
6. 冷启动内容：一份“从零到发徽章”的演示路径（脚本或文档）

### 第二阶段：社区扩张（4-12个月）——把“贡献”变成可持续生产

- AI评价引擎升级：从“只评代码”扩展到“教程/报告/关卡设计”等多类型贡献
- UGC模板化：允许导师创建任务/课程并配置奖励
- 轻量空间化：可引入2D/2.5D大厅展示身份与成就（仍以任务与评测为核心）

### 第三阶段：数字建国（12个月+）——双轨制与价值实现

- 国内合规运营：学分+徽章作为能力证明与训练体系
- 海外公链扩展：合约迁移到L2（Arbitrum/Polygon等），逐步探索更复杂的经济模型

---

## 5. 立即执行（建议的四周节奏）

1. 第1周：Hardhat 启链 + 部署 ERC-1155 + 完成一次手动铸造演示
2. 第2周：实现“最小闭环”脚本：领取任务 → 提交 → 评测 → 自动发徽章
3. 第3-4周：把入口产品化（哪怕是最小Web页/CLI），并补齐1-3个可重复的任务关卡

核心判断标准（是否继续扩张）：

> 任何新功能都必须能增强“学习-贡献-评测-激励”的闭环速度、质量或可审计性；否则延后。
