## 为什么不采用“先 packages 调通再迁移”

1. 避免二次迁移：路径、脚本、依赖、CI 配置会重复改动。  
2. 降低耦合风险：核心主控与文档治理仓、前端仓保持边界清晰。  
3. 便于服务域部署：独立仓更容易接入独立发布与运维策略。
