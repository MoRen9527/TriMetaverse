## 1. 概述

本文定义了三项公司级定期周度检查任务。它们本质是 **cron + agent query** 的标准用例：
- Phase 1（copilot-host 练兵场）：总助手工执行，验证数据源和输出格式。
- Phase 2（TriMC 上线后）：由 TriMC 的 Claude Code ScheduleCronTool + daemon 自动化调度。

## 2. 检查一：CEO/总助 待办周度扫描

### 触发
- **频率**：每周一次
- **执行日**：周一
- **负责角色**：CEOChiefOfStaff（Phase 1 手工），TriMC ScheduleCronTool（Phase 2 自动）

### 扫描范围

| 数据源 | 说明 |
|--------|------|
| `docs/workflow/operating-records/<current-week>/OP-*.json` | 当前周经营计划中的 `nextActions`、`carriedItems`、`blockedItems` |
| `docs/workflow/decision-candidates/` | 待决策事项（APPROVE/FREEZE/ESCALATE 待处理） |
| `carryAgingWarnings` | 跨周老化告警（≥4 周 warning，≥8 周 high warning） |
| `meeting-nextActions` | 上一次会议未完成动作项 |
| IPD FREEZE items registry | IPD 中处于 FREEZE 状态的条目 |

### 输出格式
```
本周 CEO/总助待办清单
（按优先级 high → medium → low，同优先级按逾期天数降序）

1. [HIGH] <action> — owner: <角色> — overdue: <天数>天 — due: <日期>
2. [HIGH] <action> — owner: <角色> — due: <日期>（未逾期）
3. [MEDIUM] ...
...

跨周预警：
- CARRY-xxx: <描述> — carryWeeks: <N> — level: <warning/high>
```

## 3. 检查二：产研进展与卡点周度扫描

### 触发
- **频率**：每周一次
- **执行日**：周三
- **负责角色**：CEOChiefOfStaff（Phase 1 手工），TriMC ScheduleCronTool（Phase 2 自动）

### 扫描范围

| 数据源 | 说明 |
|--------|------|
| `TriCompany/docs/product/STATE.md` | 产品状态（active/paused/deferred 切分） |
| `TriCompany/docs/registry/product-state.md` | 产品 registry 状态 |
| `docs/registry/code-state.md` | 代码 registry 状态 |
| `through-pass pipeline` | 审批链最小收口中的待审批项 |
| `blockedItems` in 当前 OP | 被阻塞的条目及其依赖 |
| `docs/workflow/operating-records/<current-week>/OP-*.json` | 各模块本周预计交付物与 blocker |

### 输出格式
```
本周产研进展与卡点
==================

产品侧：
- 本周交付：<item> — <状态>
- 阻塞项：<item> — blocker: <原因> — since: <日期>

技术侧：
- 本周交付：<item> — <状态>
- 阻塞项：<item> — blocker: <原因> — since: <日期>

跨模块卡点：
- <item> — 涉及模块: <A, B> — 阻塞原因: <...>

升级建议：
- <需 CEO/BusinessStrategy 裁决的事项>
```

## 4. 检查三：全项目文档同步周度扫描

### 触发
- **频率**：每周一次
- **执行日**：周五
- **负责角色**：CEOChiefOfStaff（Phase 1 手工），TriMC ScheduleCronTool（Phase 2 自动）

### 扫描范围

| 数据源 | 说明 |
|--------|------|
| 所有 `docs/registry/*-state.md` | 检查 `lastSyncedAt` 是否在 7 天内 |
| 所有模块 `AGENTS.md` | 检查与对应 agent YAML 契约的一致性 |
| `docs/三元宇宙架构与模块说明.md` | 检查模块表与实际模块状态的一致性 |
| cross-reference 一致性 | 模块间文档引用是否存在断链或过期引用 |

### 输出格式
```
全项目文档同步周度扫描
======================

过期注册（lastSyncedAt > 7 天）：
- <文件路径> — lastSyncedAt: <日期> — 过期天数: <N>

Agent 契约不一致：
- <模块/agent> — AGENTS.md vs YAML 差异: <描述>

断链/过期引用：
- <源文件> → <目标文件>: <描述>

同步建议：
- 需要更新的文件列表（按优先级）
```

## 5. Phase 2 自动化需求

### 依赖
- TriMC Claude Code ScheduleCronTool 可用
- Claude Code daemon 可用（当前为 placeholder scaffold，需补齐）
- TriMC 员工编排层（CEOChiefOfStaff agent）可通过 agent query 执行扫描
- 各数据源可被 agent tool 访问（文件系统或 API）

### 自动化流程（Phase 2 目标）
```
Cron trigger → ScheduleCronTool 触发
  → CEOChiefOfStaff agent 按本 spec 执行扫描
  → 输出写入 docs/workflow/operating-records/<week>/weekly-scan-<date>.md
  → 如有 ALERT/ERROR 项，写入 OP blockedItems/nextActions
```
