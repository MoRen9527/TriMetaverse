## 〇、制度一句话

每周日凌晨 13 席轮流重启一次（挂周日 23:00 周平面迁移窗毕后顺带，不新开窗）——回收 auto-compact 无法归还的进程内存，治周级常驻的内存爬高+响应变慢；轮流执行非同时全灭，跳过席 24h 内补；resume 续上下文；sg 面纳入第二批，头两轮观察轮。

## 一、裁量结论（制度核心参数）

| 参数 | 制度值 | 调整规则 |
| --- | --- | --- |
| 频次 | 每周一轮 | 2-4 周数据驱动调整：周中显化退化→加周三 top-N 定点重启轻补救位；两周稳定退化微弱→可议双周化 |
| 窗位 | 周日 23:00 迁移窗毕后，止损线 00:15 | 迁移优先，重启窗永远让位；超时未开批次顺延周一晚 |
| 形态 | 轮流重启（四批预设序+动态跳整） | 批表与跳过规则见执行单 §一/§三 |
| resume | **resume 优先**（`claude -r` 续 transcript） | 全新起仅限 transcript 损坏（走 FADE-007 重建）；resume 内存起点偏高为已知限制，接受不返工 |
| sg 面 | 纳入第二批，头两轮观察轮 | 两轮数据后定常态形态；失败率显著高于本机→sg 改双周或转 SDE 值席窗另议 |
| 度量 | 前后读数+周三只读观察点+月度复盘 | owner=CTO，入工程效能度量线 |

## 四、风险制度位

1. 深夜窗内信件丢失残留——最低活动期选址最小化，发信方窗后未见回音即重发。
2. resume 不可得席位——FADE-007 快照重建兜底，当席次日开工延迟，概率低。
3. 孤儿壳周窗外再生（工具缺陷面，如 VS Code 格式化 runner 泄漏案）——另行治理不并本窗；各席勿在常驻终端批量跑「全仓格式化」类命令。
