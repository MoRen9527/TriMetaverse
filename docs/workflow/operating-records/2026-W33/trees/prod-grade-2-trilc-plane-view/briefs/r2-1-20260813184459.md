## 一、现状事实（摸底结论，r2-2 实现的依据面）

1. **路径契约现状**：TriLC `src/project/multi-project-router.ts`（Phase 3 pipe3-1）把 operating records 定义为**项目隔离**路径 `{projectRoot}/docs/execution/operating-records`（`OPERATING_RECORDS_DIR` 常量），`ensureProjectDirs()` 会**自动创建**该目录；`enforceProjectIsolation()` 只守卫 `.tricompany-cognition/` 存储面。
2. **公司周平面真实路径**：TriMetaverse `docs/workflow/operating-records`（与隔离路径**路径段不一致**：`docs/execution` vs `docs/workflow`）——两套隔离且互不可见，TriCade 安装态因此看不到 W34。
3. **env 现状**：`projectRoot = TRILC_PROJECT_ROOT ?? process.cwd()`；`cwd = TRILC_CWD ?? TRILC_PROJECT_ROOT ?? process.cwd()`（REQ-014b，agent 工具执行目录）。**projectRoot 双重职责**：驱动隔离存储（.tricompany-cognition DBs）+ agent cwd——把 TRILC_PROJECT_ROOT 指向 TriMetaverse 会让存储污染公司仓并改变 cwd 语义，**否决**。
4. **无独立读取代码路径**：TriLC src 内除 router 自身外无 operatingRecordsDir 消费方；server 无周平面专用端点；TriPilot 无 operating-records 引用——当前「读取」实际经由 agent 工具在 `cwd` 下按路径约定访问。修复面 = **路径契约层（env + router）**，不改写消费方逻辑。
5. **既有先例**：`env.ts resolveFromWorkspace()` 已实现「env 显式 → 源码态 workspace 相对发现（`../TriCompany/source-agents`）→ MSI 布局（`../../contracts`）→ fallback」的公司级路径解析模式——本方案复用同一模式。

## 二、四要素定案

### 2.1 配置机制——定案：新增 `TRILC_WEEKLY_PLANE_ROOT` + workspace 自动发现（不扩 TRILC_PROJECT_ROOT 语义）

**依据**：
1. `TRILC_PROJECT_ROOT` 已过载（隔离存储根 + agent cwd + 隔离记录根），指向公司仓会造成 `.tricompany-cognition/` 写入 TriMetaverse 仓（路径污染）且 REQ-014b cwd 语义漂移——否决方案 A。
2. 公司周平面是**只读共享事实源**，与「项目隔离记录」是两种语义（全局 vs 项目级），独立 env 让两轨并存显式化。
3. 先例对齐：`TRICOMPANY_SOURCE_PATH` 已是「公司级源定位走专用 env + workspace 发现」的成功模式。

**解析顺序**（新模块 `src/project/weekly-plane-root.ts`，纯函数 + 测试）：
1. `TRILC_WEEKLY_PLANE_ROOT` env 显式（最高优先，两态通用）；
2. 源码态自动发现：`<TriLC-root>/../TriMetaverse/docs/workflow/operating-records`（workspace sibling 探测，镜像 resolveFromWorkspace）；
3. 发现失败/未配置 → `undefined`（回退旧行为，见 2.4）。

### 2.2 隔离语义兼容——定案：两轨并存，公司轨只读、项目轨不动

路由规则（写入 `multi-project-router.ts`）：
- `ProjectPaths` 新增可选字段 `companyWeeklyPlaneDir?: string`（仅当配置/发现成功时存在）。
- **读取优先级**：周平面类查询（公司周报/周会材料/OP 索引）→ `companyWeeklyPlaneDir` 存在且目录存在 → 用公司轨；否则 → 用项目轨 `operatingRecordsDir`（旧行为逐字节不变）。
- **写方向不变**：`ensureProjectDirs()` 仍只创建项目轨隔离目录；**公司轨绝不自动创建、绝不写入**（周平面写权编排层不变，本树只改读取端——护栏 ⑤）。
- **隔离 REQ 不破**：pipe3-1 的禁令面是「跨项目访问 `.tricompany-cognition/` 存储」，周平面不是 memory store；公司轨 = 用户显式配置的只读共享文档视图（等价于读任意外部路径），`enforceProjectIsolation()` 不改。此边界写进 router 模块头注释，防止未来误读。

### 2.3 安装态 vs 源码态——定案：源码态自动发现；安装态 env 显式 + fallback

| 态 | 定位方式 | 说明 |
| --- | --- | --- |
| 源码态（dev 工作区） | workspace sibling 自动发现（2.1 第 2 层） | 零配置，与 TRICOMPANY_SOURCE_PATH 同模式 |
| 安装态（TriCade / MSI） | `TRILC_WEEKLY_PLANE_ROOT` env 显式 | 安装态无 workspace sibling 可探测；MSI 部署目录下无法推导公司仓位置 |
| 安装态未配置 | `undefined` → 项目轨旧行为 | 不崩、不误读，TriCade 视图提示「公司周平面未配置」日志级提示 |

**登记跟进项（本树不做）**：TriCade 打包侧（TriMetaverse/scripts + MSI 安装链）在安装/升级时注入 `TRILC_WEEKLY_PLANE_ROOT`（指向 CEO 本机 TriMetaverse 检出路径，可配）——归仓 TriCade 打包通道，r2-2 交付后由编排层路由。

### 2.4 向后兼容——定案：默认 undefined = 逐字节旧行为

- 无 env + 自动发现失败 → `companyWeeklyPlaneDir = undefined` → 一切读取走项目轨，行为与现版本一致；`ensureProjectDirs`/`enforceProjectIsolation`/projectId 派生零变化。
- 旧安装版（无新 env 概念）天然不变。
- 新代码对 router 现有 API 全向后兼容：`resolveProjectPaths()` 签名不变，`companyWeeklyPlaneDir` 为可选新增字段；既有 17 个 router 测试不得改预期（r2-2 门禁）。
