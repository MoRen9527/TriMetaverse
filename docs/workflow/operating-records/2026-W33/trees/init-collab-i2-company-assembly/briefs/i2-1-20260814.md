## 一、装配端点契约（POST /internal/v1/init/assemble）

internal localhost 面（与 I1 两端点同族）。**执行主体 = daemon 端点，两入口只发指令不执行**（W30 零本地执行契约）。

**1. 请求载荷**：

```json
{
  "ceoName": "磨人",
  "selections": [
    { "roleId": "ceo-chief-of-staff", "name": "小贾" },
    { "roleId": "full-stack-developer", "name": "小全" }
  ],
  "entry": "tripilot | trilc-chat"
}
```

**2. 校验规则（服务端唯一执行，先校验后动作）**：

| 规则 | 失败响应 |
| --- | --- |
| ceoName 非空白（trim 后 1..64 字符） | 400 |
| selections.length ≥ 1（A4 0 人拦截） | 400 |
| roleId 必须存在于岗位目录（role-catalog 返回集） | 400 |
| roleId 去重（重复项） | 400 |
| name 非空白（每项必填，写入装配产物） | 400 |
| chainState === 'onboarding'（阶段门禁，防错阶段写） | 422 { chainState } |
| 装配运行中（防重入，单执行体互斥） | 409 { busy: true } |

<5 岗不拦截：CEO 裁决口径 = ≥1 岗可开张，<5 岗响应附 `warning: { recommendedMin: 5, current: N }`，提示语义「推荐至少 5 岗，当前可选」由渲染层呈现。

**3. 执行顺序（原子性口径）**：

```
① 校验（上表）→ ② 预写段 → ③ 提交段 → ④ 事件发布
```

- **② 预写段（文件落点白名单内逐文件真原子写）**：全部落点文件先写 `.tmp` 兄弟文件 + 已存在原文件备份至临时 `.bak` 目录 → 逐文件 rename 到位。允许路径白名单（枚举，任何逃逸直接拒绝执行）：
  - `{workspaceRoot}/.claude/agents/<roleId>.md`（roleId 必须来自岗位目录，防路径注入）
  - `{workspaceRoot}/docs/registry/company-state.json`
  - `{workspaceRoot}/docs/registry/business-state.md`（现状真源路径，D2 注记）
  - `{workspaceRoot}/AGENTS.md`
  - `{dataDir}/company/state.json`（运行时真源，经 `CompanyInitState.save()` 机制沿用——REQ-019 baseline commit 随机制触发，git 身份单一纪律不新增）
- **③ 提交段**：`CompanyInitState.save({ state:'initialized', ceoName, employees })` → `InitChain.transitionTo('project-link', entry)`（顺序固定：公司态先、链路态后）。
- **④ 事件发布**：`init:step-event { phase:'onboarding', step:'assembling' }`（开始）→ 成功 `init:step-event { phase:'onboarding', step:'assembled', payload:{ ceoName, employees } }` + transitionTo 自动发布 `init:chain-changed`；失败 `init:step-event { phase:'onboarding', step:'assemble-failed', payload:{ error } }`。

**4. 回滚与幂等**：

- 预写段任一失败 → 用 `.bak` 恢复已覆盖文件 + 删除新增文件 → 500 `{ error, rollback: 'completed' }`（注入失败点单测覆盖）。
- 公司态 save 成功但 transition 失败 → **不回滚文件**；幂等重试路径：重入 assemble 时公司态已 initialized 且链路态仍 onboarding → 跳过文件段与 state save，直接补 transitionTo（employees 与现存一致校验）。
- 文件写入幂等（同载荷重跑内容一致）；防重入互斥 + 阶段门禁保证串行。

**5. 响应**：200 `{ ok: true, chainState: 'project-link', companyState: 'initialized', employees: [...] }`。

**6. 阶段推进：selfcheck→onboarding 自动转移（i2-2 裁决 A'，2026-08-14）**：

- **推进点** = `init-selfcheck.ts` executeSelfcheck 完成路径（`updateSelfcheck` 之后、事件序最后）：`summary ∈ { pass, degraded }` 且当前 `chainState === 'selfcheck'` → `await deps.chain.transitionTo('onboarding', 'daemon')`。发布顺序 = selfcheck-finished（自检绿卡/红卡汇总）→ chain-changed（阶段切换）——入口先看自检结果再切选择界面。
- **blocked 不推进**：诊断卡保留，CEO 修复后重跑 selfcheck（端点幂等可重跑），pass/degraded 后推进。
- **幂等守卫**：链态已是 onboarding 时重跑自检 → `getState() === 'selfcheck'` 守卫跳过（无转移无事件；transitionTo 合法性校验天然拒绝自环）。
- **assemble 门禁维持字面**：`chainState === 'onboarding'` 否则 422 不变——不新增端点面（否决 begin 端点：违背零命令原则 + 多余指令面；否决 assemble 受理 selfcheck 态：选择界面呈现将先于链态推进，UI 与状态机真源错位，违反「chain-changed = 两入口渲染阶段切换的唯一依据」i1-1 §三）。
- **断点续跑**：daemon 重启 load 恢复 onboarding 态 → 入口直接渲染选择界面（自检结果经 phaseDetail.selfcheck 快照可回看，A3 支撑）。
