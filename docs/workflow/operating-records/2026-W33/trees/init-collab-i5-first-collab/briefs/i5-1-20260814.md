## 一、L1-L4 验收执行口径（判定矩阵 + 证据留档）

### 1.1 协议层判定矩阵（数据源 = confirm/check 响应 + 真源三件套）

| 层 | 判定数据源 | 判定标准 | 证据留档 |
| --- | --- | --- | --- |
| L1 注册同一性 | 本地 project-registry.json（activeProjectKey/repoUrl/worktrees[]）↔ bundle.project ↔ TriMC status.project ↔ check 响应 l1.items | 三面 project key + repoUrl + worktree 路径短指纹（SHA-256 前 8 位）完全匹配；任一不匹配 = ERROR（错误仓/错误分支） | check 响应 l1 + 注册点摘录 + bundle.project 摘录 + status.project 摘录 |

| L3 写读闭环 | status.applied.bundleId == 本地 bundle 文件 bundleId | 相等 = 正向链路实证（sync commit 即探针）；未 applied = 「未就绪」+ 重试（§6.8 前提） | bundle 文件 bundleId + status 响应 applied 段 |

### 1.2 呈现层验收（确认卡三态，两入口）

1. **三元素同显**：TriPilot 面板 + trilc chat 两入口各显示 repoUrl / project key / worktree 路径**短指纹**，与 check 响应 l1.items 一致。
2. **短指纹防截断**：路径呈现 = 8 位 SHA-256 指纹（computePathFingerprint），非全路径（§7.2）。
3. **HEAD 一致性徽标**：L2 结果渲染（绿一致 / 红差异）。
4. **红差异注入测试**：人为构造不一致（改注册点 worktree 路径）→ 红色差异提示列出（哪端/什么元素/期望值 vs 实际值）+ 诊断入口可达（重新登记 = I3 link 流程 / 重新同步 = sync/run）。
5. **未就绪态**：sync 未 applied 时确认卡「未就绪」+ 先同步提示（§6.8）。

### 1.3 迁移后 L2 收敛步骤（协同稳态证明，本拆解新增）

周日 23:00 迁移 commit 后 fleet HEAD 前移，本地未 pull 前 L2 三值不等——**这不是失败，是「迁移 commit 待回流」态**。首个协同工作验收含收敛链：

1. 迁移 commit 到裸仓（fleet push，job 内）→ fleet HEAD 前移（自动）；
2. 编排层本地 `git pull sg-server dev` → 本地 HEAD 前移 → W34 产物可见（**L4 核心判定**）；
3. **建议 re-sync**：sync/run 幂等重跑 → bundle.devHead 更新 + push → L2 三值重新收敛 + L3 applied 新 bundleId——§6.6「变更触发重新生成」语义内动作，证明三端在迁移后依然操作同一项目（协同稳态）。

### 2.2 三路径回退与恢复流程

| 路径 | 失败面 | 回退 | 恢复 |
