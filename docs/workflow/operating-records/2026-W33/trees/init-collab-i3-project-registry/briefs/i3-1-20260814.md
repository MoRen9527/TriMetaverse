## 一、project-registry.json 注册点（design-v2 §③ 落地，schema 先行冻结供 I4 并行）

**落点**：`%LOCALAPPDATA%\trilc\project-registry.json`（固定路径，不随 TRILC_DATA_DIR 覆盖——design-v2 §③；测试隔离场景读共享注册点为只读无害，写入仅 daemon 单主体）。**写契约**：原子写 tmp→rename + 校验读回；读取时惰性清理（existsSync + gitdir 双校验，§五）。

```json
{
  "schemaVersion": 1,
  "activeProjectKey": "trimetaverse",
  "projects": {
    "trimetaverse": {
      "repoUrl": "https://github.com/MoRen9527/TriMetaverse.git",
      "mainCheckoutPath": "D:/Code/ai/TriMetaverse",
      "hasNpmFileDeps": false,
      "defaultBranch": "dev",
      "worktrees": [
        { "path": "<abs>", "gitdir": "<abs>/.git/worktrees/<name>", "branch": "project/trimetaverse", "claimedAt": "<iso8601>" }
      ]
    }
  }
}
```

- **项目仓注册表**（design-v2 §⑥）与注册点合并为同一文件：`projects` 键即 project-key → { repoUrl, mainCheckoutPath, hasNpmFileDeps, defaultBranch, worktrees[] }。MVP 单项目 = daemon 内置预置表（TriMetaverse 单条目，含 repoUrl/hasNpmFileDeps/defaultBranch 常量）+ 注册表文件承载运行态（mainCheckoutPath/worktrees 为动态登记）；配置层 UI 与公司级默认清单（TriCompany 中央 registry 发布）不做——design-v2 §⑥ 预留结构不变。
- **activeProjectKey** 语义 = 焦点项目（design-v2 §2.7）：link/claim 成功即置 active（MVP 单项目无歧义）；多项目切换 UI 归后续树。
- **主键去重**：worktrees 以「绝对路径 + gitdir」为主键；同路径重复 add 拒绝（git 原生 + 注册点双重）；同项目多 worktree 允许（不同分支）。

## 二、link / claim 端点契约（design-v2 §五.1 第 3/4/5 步）

**1. POST `/internal/v1/projects/link`**（TriPilot/CLI 发指令，daemon 执行）

请求：`{ source: "local" | "github", localPath?: string, repoUrl?: string, targetPath?: string }`
响应：202 `{ runId }` + SSE 进度（§三事件族）；完成 200 `{ projectKey, worktreePath, branch }`；失败 4xx/5xx `{ error, classification }`。

**端点内原子序**（每步失败分类 + 回滚，§七.4）：

| 步 | 动作 | 失败分类 |
| --- | --- | --- |
| 1 检测 | `git rev-parse --is-inside-work-tree` + `.git` 文件/目录形态判别（目标路径若已存在） | 非 git / 非空非 git 目录 →「普通文件夹」分类 |
| 2 关联判定 | `git remote origin` URL ↔ 注册表 repoUrl 白名单比对（含 GitHub 源 URL 规范化：https/ssh 同仓等价，去尾 .git） | 未命中 → 拒绝自动流程 + 提示（防克隆非项目仓） |
| 3 门禁 | 注册表 hasNpmFileDeps 标记仓**拒绝自动 add** + 手动评估提示（INCIDENT-20260814-001 纪律） | 标记仓 → blocked（无自动路径） |
| 4a 认领 | 目标已是本仓 worktree（.git 文件 + gitdir 属主仓）→ 只登记（**绝不重复 add**） | gitdir 不属于项目仓 → 拒绝 |
| 4b 建立 | 本地源：`git -C <mainCheckoutPath> worktree add <targetPath> -b project/<key>`（落点校验：空目录或不存在、不落主 checkout 检出内、不与其他 worktree 重叠）；GitHub 源：白名单比对 → 克隆建立主 checkout（凭据 = 系统凭据管理器；clone 到用户路径）→ 登记 mainCheckoutPath → 转本地源链路 | 网络 / 凭据 / 仓库不存在 / 分支冲突 / 磁盘权限——分类提示 + 可改走另一源 |
| 5 登记+去重 | 注册点原子登记（主键去重）+ `git worktree list` 交叉验证 | 登记冲突 → 读回修复 |
| 6 链态更新 | init-chain `project-link` 阶段快照（status=linked, source, projectKey, worktreePath）+ `init:step-event` 发布 + **内存态热更新同一请求内完成**（无独立热更新端点） | 更新失败 → 注册点回滚（§七.4） |

**2. POST `/internal/v1/projects/claim`**：`{ path }` → 打开文件夹认领路径（§4a 同构 + 认领登记）→ 200 `{ projectKey, branch, claimed: true }`。

**分支规约**：常驻分支 `project/<key>`（不存在则 `-b` 从 sg-server/dev 最新 ff 起点创建；已存在则同 worktree 内 checkout 或新 feature 分支）；`feature/<key>-<slug>` 归 P4；project 分支禁止直接 commit（写权边界，P4 前靠提示）。

## 三、SSE 事件族新增（沿 init:* 惯例，daemon 单写方）

| 事件 | 载荷 | 语义 |
| --- | --- | --- |
| `init:project-link-started` | { runId, source, targetPath } | 链路开始（两入口转圈态） |
| `init:project-link-progress` | { runId, step: detect\|match\|gate\|claim\|clone\|worktree-add\|register\|chain-update, status, detail } | 逐步进度（向导 Step 4 创建反馈渲染源） |
| `init:project-link-finished` | { runId, projectKey, worktreePath, branch, chainState: "project-link", phaseDetail } | 完成帧（= chain/status 投影同帧） |

约束：事件流 = 状态文件/注册点同帧投影；project-link→sync 转移不发布（归 I4）。

## 四、向导接入与识别分流（design-v2 §2.4/2.5）

- **链态门**：link/claim 仅在 `chainState='project-link'` 时生效，其他态 409 `{ chainState }`（线性转移表约束）；onboarding→project-link 转移由 I2 装配端点在开张完成时触发（已实现链上动作，本树复验）。
- **识别分流**（打开文件夹判定，产品面 §2.5 呈现）：已是项目 worktree（.git 文件 + gitdir 命中）→ claim 认领 → LINKED-*；项目仓普通克隆（.git 目录 + remote 命中白名单）→ 「非受管」+ 升级引导（不自动升级不强制）；其他 git/非 git → 未关联轻提示。判定接口 = GET `/internal/v1/projects/inspect?path=` → `{ kind: "managed-worktree" | "project-clone" | "unlinked", projectKey?, branch?, worktree?: bool }`（两入口渲染共用）。
- **TriPilot 侧**：本树**零 TriPilot 仓改动**（workspaceRoot 现役字段够用）；渲染升级复用 I2 已建结构化流程面（init:step-event 通道），产品面 §2.5 六步呈现接口由 inspect + link/claim + 事件族承载。
- **trilc chat 侧**：`init-cli-flow.ts` 增量——project-link 文本流程（inspect 呈现 → 源选择问答 → POST link 收进度），零本地执行。

## 五、幽灵路径惰性清理（design-v2 §六）

- 注册点每次读取：worktrees[] 逐项 existsSync(path) + gitdir 可读校验，无效项惰性移除（登记移除，**不删磁盘 worktree**——物理资产保留，重新打开可重新认领，design-v2 §2.7）。
- `git worktree list` 交叉验证：注册点有而 git 无 → 登记移除；git 有而注册点无 → 不动作（未认领 worktree 属正常态）。
- `worktree remove --force` 全仓禁用（含测试 mock 断言）。

## 七、门禁口径（i3-3 小柯 / i3-4 小狄）

1. **零本地执行**：TriPilot 仓 diff 零行（本树）；新端点 localhost-only internal 面。
2. **git 单执行体**：全部 git 操作在 daemon 端点内，单身份（OBS-20260814-002 映射）；无 sudo、无多身份分支。
3. **junction 纪律**：hasNpmFileDeps 门禁拒绝自动 add；`worktree remove --force` 全仓（含测试）禁用。
4. **原子性 + 回滚**：add + 登记 + 链态更新同一请求完成；登记/链态失败 → worktree remove（非 --force）回滚 + 日志留痕；认领路径零磁盘写。
5. **链态纪律**：非 project-link 态 409；转移仅经 transitionTo 线性表（本树不转移出 project-link）。
6. **护栏零触碰**：init-state.ts / session-initializer.ts / init-chain.ts（除 project-link 阶段快照写入）diff 零行；如需加字段 CTO 单批审批。
7. **回归**：I1 SELFCHECK 五探测 + I2 assemble 全流程回归；r19 问周面冒烟仍 green；既有测试基线一致。
8. **测试隔离**：显式 TRILC_DATA_DIR（r19 教训）；注册点读共享文件只读无害断言。
