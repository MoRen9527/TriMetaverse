## 三、OBS 1-7 裁决（含根因实证）

### OBS-1（幂等重推活体不可达）——裁决：修复（返修包 R1）

**根因实证（本终审独立复核）**：contentHash = 五维语义哈希，含 `project.devHead`（sync-bundle.ts:295-303 / types.ts:296-301）。devHead 是**自引用事实**——每次成功 run 必 commit bundle 文件推进 HEAD，下一轮收集的 devHead 必变 → 内容 hash 必变 → 必换 bundleId。活体历史实证：bundle 76a905be（commit b8b57414）的 devHead = ad836bcb = **其自身 commit 的 parent**（git show b8b57414:docs/registry/init-sync/sync-config.json 实读）；fe1fae01 同构（devHead = 自身 parent a09ca76f）。单测 scripted git 固定 devHead 掩盖（init-sync.test.ts:394 rePushedOnly=true 用例）。i4-3 活体 4 次 run 均换新 bundleId（67ece555→8ace866f→07ee59b0→fe1fae01→76a905be）同源。
**影响**：① 重跑=纯重推语义失效（push 失败后重跑也换新 bundleId + 新 commit + fleet 重新 apply）；② 逐次重跑产生历史噪音 commit（OBS-5 同源）；③ 更严重推论 = OBS-6b（devHead 自推进使 L2 三值相等数学不可达）。
**裁决**：候选 c（接受现状）不成立——§一.4/§二.3「同内容不重新生成、重跑=纯重推」是门禁 5 契约语义，且 L2 连带自锁。候选 b（收集容差）产生每跑一 commit + 服务器 no-op 错位（同 bundleId 下 devHead 更新永不落地），否决。**采用候选 a：contentHash 两端同口径排除 project.devHead（R1）**——devHead 保留为 bundle 内诊断事实（生成时值），幂等判定语义 = 「五维真实内容变更才重新生成」；幂等路径跳过写文件（字节不变 → 无 commit → 纯重推）。

### OBS-2（push 失败后无 daemon 侧 pull 对齐路径）——裁决：登记后续树（P2），MVP 接受人工 pull

理由：§7.2 失败分类已把重试语义留给 sync/run 幂等重跑（OBS-1 修复后重跑 = 纯重推，正确性保持）；远端领先属活跃协作窗口的并行写协调问题，自动 pull 涉及合并策略与工作树脏态决策，不并入返修包（返修包聚焦确认正路径阻断）。后续树范围：push 拒绝分类（non-fast-forward 识别为 push-rejected-ahead）+ `git pull --ff-only` 自愈重试一次 + 失败分类呈现；OBS-4 的 fail-fast hardening 并入同树。即时注记：runbook/README 注明「push-failed 且远端领先 → 人工 pull --ff-only 对齐后重跑」。

### OBS-3（fleet TriCompany 属主残留）——裁决：环境修复项（立即执行，非代码改动）

机制面已按设计工作（employees 维 warning + 日志落地 ✓）。修复：`chown -R fleet:fleet` 复核 /srv/fleet/TriCompany 属主（含 packages/agent-core/src/loop.ts）→ cron API 触发 config-sync-apply 复跑 → 确认 employees 维 warning 收敛（fleet HEAD 追上 bundle sourceCommit）。执行方 = 编排层派 ops（小全/小柯均可）。

### OBS-4（手动 apply CLI 缺 TRIMC_CONFIG_DIR 落错目录）——裁决：runbook 注记（立即）+ fail-fast hardening 并入 OBS-2 后续树

### OBS-5（dev 历史噪音 + tags/dev 歧义）——裁决：登记不回改

历史冻结原则：i4-3 活体 3 个 bundle commits + 2 个 merge commits 留 dev 历史（不回改不 reset——多 agent 共享仓卫生）。OBS-1 修复后此噪音不再复发（幂等重跑不逐次 commit）。tags/dev 同名歧义：编排层已用显式 refspec 绕过（现状可用），登记 repo hygiene 后续项（tag 重命名或文档化）。

### OBS-6（Phase D 正路径双阻塞，阻塞级）——裁决：契约级修复（返修包 R2+R3）

**OBS-6a L1 worktreePath 空集误判**：compareL1Value `!!localStr &&`（init-confirm.ts:95）使三方 worktrees 均空集（指纹空串）判 error。语义修正：worktreePath 三方等值（含空集）→ ok（L1 职责 = 一致性判定，非完备性判定——注册完备性归 I3 门禁）；空集时确认卡给「worktree 清单为空」提示注记（非阻塞）；repoUrl/projectKey 维持非空 + 等值要求。
**OBS-6b L2 严格三值自锁**：i4-1 §六 L2 契约「本地 HEAD == bundle.devHead == fleetHead」**数学不可达**——bundle.devHead 是生成时值（必为其自身 commit 的 parent，§OBS-1 实证），fleetHead 是实时值（15min 持续 pull 前进）→ 严格相等自锁。i4-3 活体实测三值全异 + readyForConfirm=false + POST confirm 409（门禁路径正确）。**契约级修正（本裁决 CTO 单批）**：L2 改「同 dev 线（ff 收敛可达）」语义：
- l2.ok = bundleHead 为 localHead 的祖先或相等（git merge-base --is-ancestor，本地可判定）**且** fleetHead 与 localHead 等值或互为祖先（一方为另一方祖先 = 同线可 ff 收敛；均不可达 = 分叉 → red「勿确认」；fleetHead 本地不可解析 = 未拉取 → red + 「先 pull」诊断）。
- 降级（remote null）：l2.ok = bundleHead 为 localHead 的祖先或相等（废止原「local==bundle」双值比较——同源不可达）。
- ConfirmCheckL2 增 `bundleAncestor?: boolean`（additive，诊断呈现用）。
依据：design §7.2 L2 行括号原文「不等 = 落后/领先诊断（**ff 同步收敛**）」——同线判定正是 ff 收敛语义，比字节相等更贴设计本意，且消除「fleet 每 15min 前进 → 本地追不上」的竞态（一方为祖先即绿，落后仅提示不阻断）。
**连带修复**：L2 契约修正后 I6 验收口径「三元素一致 + 一次确认」在 OBS-6a+R2 落地后可达。
