## 一、bundle schema（生成端拒绝 api_key + 测试门禁）

**落点**：项目仓 `docs/registry/init-sync/sync-config.json`（写入对象 = 注册点 mainCheckoutPath 对应 checkout 的 dev 线工作树；MVP 单项目 TriMetaverse 双轨合一，多项目后公司维迁 TriCompany 仓按 §6.3 预留）。

**字段契约（两端独立实现同一契约，本 brief 冻结；共享包升级挂后续）**：

```json
{
  "schemaVersion": 1,
  "bundleId": "<uuid-v4>",
  "generatedAt": "<ISO-8601，单调：max(now, 现存bundle.generatedAt + 1ms)>",
  "generatedBy": "trilc-init-<version>@<host-hash-8>",
  "company": { "state": "initialized", "ceoName": "<str>", "onboardedAt": "<ISO>" },
  "model": {
    "defaultModel": "tmv-deepseek-v4-pro",
    "catalog": [{ "id": "tmv-deepseek-v4-pro", "provider": "deepseek", "capabilities": ["chat"] }],
    "providers": [{ "provider": "deepseek", "baseUrl": "http://127.0.0.1:3333/v1", "port": 3333 }]
  },
  "keys": {
    "providers": [
      { "provider": "deepseek", "ready": true, "fingerprint": "a1b2c3d4", "baseUrl": "..." },
      { "provider": "openai", "ready": false }
    ],
    "refreshIntervalS": 900,
    "fetchedAt": "<ISO>"
  },
  "employees": {
    "roster": [{ "roleId": "chief-technology-officer", "name": "小狄" }],
    "sourceCommit": "<TriCompany HEAD sha40>"
  },
  "project": {
    "projectKey": "trimetaverse",
    "repoUrl": "https://github.com/MoRen9527/TriMetaverse.git",
    "defaultBranch": "dev",
    "worktrees": [{ "path": "<abs>", "branch": "project/trimetaverse" }],
    "devHead": "<sha40>"
  }
}
```

**纪律（SEC-20260813-001，§6.7 裁决）**：

1. **生成端 schema 校验递归拒绝密钥材料字段**：任意深度出现字段名 `api_key` / `apiKey` / `secret` / `token` 且值为非空字符串 → 抛错拒绝生成。keys 维只允许 `provider/ready/fingerprint/baseUrl` 白名单字段（额外字段拒绝，防未来滑变）。
2. **fingerprint = SHA-256(api_key 材料).slice(0,8)**：在 daemon 内存内计算（key-cache S2 解密后），材料不落任何中间文件。
3. **测试门禁（i4-3 独立复测口径）**：① 构造含 `api_key: "sk-..."` 的载荷 → 校验必须抛错；② 真源五维生成后的序列化输出全文断言无 `sk-` 明文、无 `api_key` 字段名；③ commit 前 diff 扫描断言（pre-commit 检查步）；④ 服务器侧 apply 校验同规则双保险（防未来生成端被绕过）。
4. **幂等单调**：bundleId uuid 每次生成唯一；generatedAt 严格递增（见字段注）；同 bundleId 重复 apply = no-op；更旧 generatedAt = 忽略 + 日志；更旧但 contentHash 不同 = 告警日志不动作（时钟回拨/多机写，MVP 记日志，§6.5）。

## 二、TriLC 生成/commit/push 链（daemon 单执行体）

**新模块** `TriLC/src/company/init-sync.ts`（生成/收集/提交/推送）+ `TriLC/src/company/sync-bundle.ts`（纯 schema：校验/指纹/单调性，可单测）。

**端点 `POST /internal/v1/init/sync/run`**（internal 面同族，执行主体 = daemon，两入口只发指令）：

1. **链态门**：`chainState ∈ {project-link, sync}` 否则 409 `{ chainState }`；`project-link` 且 `phaseDetail['project-link'].status === 'linked'` → 先 `transitionTo('sync')` 再执行；`sync` 态 = 幂等重跑。防重入 409（单执行体互斥）。
2. **五维收集（单维失败降级，§2.7 三态可见）**：
   - company ← `{dataDir}/company/state.json`（失败 = 无公司态，属于硬错误 → 400 提示先开张）
   - model ← TriModel `/v1/models` + key-cache 响应面（网络不可达 → model 维 unavailable 降级）
   - keys ← key-cache 读（S2 解密 → 内存指纹 → 即刻丢弃材料）；条目缺失 → 该 provider `ready:false`（逐 provider 降级）
   - employees ← company/state.json roster + contract-resolver（roleId 校验）+ `git -C <TriCompany sourceRoot> rev-parse HEAD`（sourceCommit；读取失败 → 该维 unavailable 降级，§九 服务器侧校验兜底）
   - project ← project-registry.json（activeProjectKey 条目）+ `git -C <mainCheckoutPath> rev-parse HEAD`（devHead）
   - 维度收集结果逐维落 `init:sync-progress` 事件（未同步/同步中/已同步三态渲染源）；**单维失败不阻塞全链**，bundle 内该维段 `{ "status": "unavailable", "reason": "..." }`，其余维正常。
3. **生成 + 校验**：bundle 组装 → §一 schema 校验（拒绝密钥字段）→ 单调性（generatedAt 递增）→ 幂等判定：**本地文件已存在且内容 hash 未变 → 不重新生成、不换 bundleId**（重跑 = 纯重推）；源事实变更 → 新 bundleId 生成。
4. **写 + commit + push**（git 单执行体 + 固定身份 D2）：
   - 原子写 `{mainCheckoutPath}/docs/registry/init-sync/sync-config.json`（tmp→rename）
   - `git add docs/registry/init-sync/sync-config.json` + commit（`-c user.name="TriLC Init Sync" -c user.email="trilc@tri.company"`，**绝不使用环境 git 身份**）
   - `git push origin dev && git push sg-server dev`（双远端；任一失败 = 失败分类 + sync-pending 挂起，sync/run 可重跑；§7.2 网络不可达分类）
5. **成功路径**：`phaseDetail.sync.status='pushed'` + bundleId 快照回写 → `transitionTo('confirm')`（**D1**，依据 §6.8：未 applied 时协同确认卡呈「未就绪」——confirm 态可达未 applied 态，故转移门槛 = pushed；applied 由 confirm 阶段轮询收敛并回写 sync.status='applied'）→ `init:step-event { phase:'sync', step:'pushed' }` 发布。
6. **事件族**：`init:sync-started / init:sync-progress（逐维三态）/ init:sync-finished / init:sync-failed`——经既有 `/internal/v1/init/events` SSE 通道发布（I2 已建，零新通道）。

**辅助端点**：`GET /internal/v1/init/sync/status` → 200 `{ chainState, phaseDetail.sync, localBundleId, localBundleGeneratedAt, remote: { reachable, appliedBundleId, appliedGeneratedAt, fleetHead, dims } | null }`（remote = 拉取 TriMC status 端点，超时 3s + 失败降级为 null，§6.8 降级口径）。

**daemon 重启 re-sync 检查**（§6.6 尾部）：启动时若 `chainState ∈ {sync, confirm}` → 读本地 bundle 文件 + 调一次 sync/status（远程不可达静默）——本地文件存在且 status 已 applied 同 bundleId = no-op；无本地文件且链态=sync = 面板「待补」提示（正常断点态）。**不自动 push、不自动生成**（启动期零写面）。

**跳过语义注记**：SYNC 允许「稍后再说」（§2.2）= 用户离开流程，链态停留 sync/pending，面板常驻「待补」入口——**不设 skip 端点、不转移**（线性转移表禁止 confirm→sync 回退，重试 = sync/run 幂等重跑，无回退需求）。

## 六、L1-L4 协同确认卡（契约先行、实现后置，内序 = TriMC 侧先行）

**契约冻结（本 brief 先行，实现待 I3 收官——project-registry 落地后同批开跑；i4-2 内序按编排层：①③④⑤前半先行、确认卡后接）**：

**1. `GET /internal/v1/init/confirm/check`**（daemon 端点，按需计算，无后台常驻轮询）：
- **L1 注册同一性**：project-registry activeProjectKey/repoUrl/worktrees[] ↔ bundle.project ↔ TriMC status.project 三面比对；**路径用短指纹呈现**（SHA-256(worktreePath).slice(0,8)，§7.2 防截断）；不匹配 = ERROR（错误仓/错误分支）
- **L2 版本一致**：本地 dev HEAD（daemon 读 git）== bundle.project.devHead == status.fleetHead.commit；三值相等 PASS，不等 = 落后/领先诊断（ff 收敛提示）
- **L3 写读闭环**：status.applied.bundleId == 本地 bundle 文件 bundleId（sync commit 即探针，无需额外文件）；未 applied = 「未就绪」+ 重试提示（§6.8）
- **L4 反向闭环**：由首个协同工作承载（周平面平移，I5 树），check 端点返回 `l4: { status: "pending", note: "由首个协同工作承载" }`
- **降级口径**（§7.2.3）：TriMC HTTP 不可达 → L2 服务器侧事实退化（本地 push 成功 + 裸仓 reflog 人工口径），MVP 接受，响应 `remote: null` + `degraded: true`
- 响应：`{ chainState, l1: {ok, items[]}, l2: {ok, localHead, bundleHead, fleetHead}, l3: {ok, appliedBundleId, localBundleId}, l4: {...}, readyForConfirm: boolean }`（readyForConfirm = l1 && l2 && l3 全 ok）

**2. `POST /internal/v1/init/confirm`**：用户一次确认（两入口同载荷 `{ entry }`）→ 服务端重算 check → `readyForConfirm` 门禁（否则 409 附 check 结果）→ `phaseDetail.confirm.status='confirmed'` + l1/l2/l3 快照 → `transitionTo('ready')` → `init:step-event` 发布。**协同开启成功 = 三元素一致 + 一次确认**（§2.8 验收口径）。

**3. 确认卡渲染契约（两入口）**：三方同显三元素（repoUrl / project key / worktree 路径指纹）+ dev HEAD 一致性徽标（L2）；任一不一致 → 红色差异提示（哪端、什么元素、期望 vs 实际）+ 诊断入口（重新登记 = I3 link 流程 / 重新同步 = sync/run）；同步未达 → 「未就绪」+ 先同步提示。渲染实现后置，与 check/confirm 端点同批（Phase D）。
