## 二、链路进度状态文件 schema

**落点**：`{dataDir}/company/init-chain.json`（与公司 init-state 同落点同目录；公司态 state.json 与链路态文件分离独立持久，护栏）。

```json
{
  "schemaVersion": 1,
  "chainState": "uninitialized | selfcheck | onboarding | project-link | sync | confirm | ready",
  "phaseDetail": {
    "selfcheck": { "runId": null, "summary": "pass | degraded | blocked", "checks": [ { "id": "healthz", "status": "ok | fail | degraded | skipped", "detail": "", "hint": "" } ], "finishedAt": null, "retryCount": 0 },
    "onboarding": { "step": null, "ref": "company/state.json#progress" },
    "project-link": { "status": "pending | linking | linked | skipped", "source": null, "projectKey": null, "worktreePath": null },
    "sync": { "status": "pending | pushed | applied | failed", "bundleId": null },
    "confirm": { "status": "pending | confirmed", "l1": null, "l2": null, "l3": null },
    "ready": { "firstCollab": "pending | triggered | passed" }
  },
  "lastTransitionAt": null,
  "lastUpdatedAt": null,
  "eventSeq": 0,
  "sourceEntry": "tripilot | trilc-chat | daemon | null"
}
```

**规则**：
1. phaseDetail 各阶段为**显示快照 + 引用**，写真源归各域（公司域 = state.json progress、项目域 = project-registry.json、同步域 = bundle）——链路态不复制真源，只存指针与快照（公司态分离护栏的持久化形态）。
2. 持久化 = **真 tmp→rename 原子写**（写 tmp → rename 覆盖 → 校验读回），事件序号 eventSeq 单调递增；无任何 git 操作（REQ-019 隐患不复制）。
3. I1 只实现 UNINITIALIZED→SELFCHECK 的真实动作；其余五态转移函数 + 事件发布在 I1 实现（供后续树端点驱动），阶段真源逻辑归 I2-I5。
4. 断点续跑：daemon 启动 load → chainState 为 onboarding/project-link/sync/confirm 时按 phaseDetail 快照续跑（I1 只交付机制，续跑动作主体归后续树）；selfcheck 幂等可重跑。
5. 转移触发：SELFCHECK = 端点触发（§四）；后续阶段 = 后续树端点（I2 装配端点、I3 link 端点、I4 sync、I5 confirm）——I1 预留 `transitionTo(next, entry)` 内部函数 + 端点契约占位。

## 三、SSE 步骤事件类型（两入口投影真源）

沿用 publish({type}) 惯例，新增族（全部为 daemon 单写方发布）：

| 事件 | 载荷 | 语义 |
| --- | --- | --- |
| `init:chain-changed` | { chainState, from, to, eventSeq, sourceEntry } | 状态机转移（两入口渲染阶段切换的唯一依据） |
| `init:selfcheck-started` | { runId, checks: string[] } | 自检开始（诊断卡进入转圈态） |
| `init:selfcheck-progress` | { runId, checkId, status, detail } | 逐项检查结果（诊断卡逐行点亮） |
| `init:selfcheck-finished` | { runId, summary, report } | 自检完成（绿卡/红卡汇总；report = 第五探测含 r19 问周面缺陷行） |
| `init:step-event` | { phase, step, entry, payload } | 通用步骤事件（ONBOARDING 起供两入口渲染步骤流，I2 起消费） |

约束：事件流 = status 端点数据的投影（同一状态文件帧），两入口不各自维护流程状态；事件序号与状态文件 eventSeq 一致。

## 四、SELFCHECK 端点契约（I1 新增，localhost internal 面）

**1. GET `/internal/v1/init/chain/status`** → 200 { schemaVersion, chainState, phaseDetail, lastTransitionAt, eventSeq, sourceEntry }（两入口只读投影 + 诊断卡数据源）。

**2. POST `/internal/v1/init/selfcheck/run`** → 202 { runId }，检查过程经 `init:selfcheck-*` 事件流发布（复用既有 SSE publish 通道）；并发防重入：运行中再触发返回 409 { runId }。

**3. 检查面（四要素 + 第五探测）**：

| checkId | 探测 | 判定 | 失败分类 |
| --- | --- | --- | --- |
| healthz | GET 本机 /healthz（ok:true）+ heartbeat-runner 最近心跳时间戳（复用 trilc status 机制） | ok / fail | fail = blocked（daemon 面） |
| tripilot | 被动观察：近 N 分钟 /v1/tasks/stream 请求携带 context.workspaceRoot 的存活计数（daemon 内存态，随 status 上报）；主动面 = 第五探测 | ok / degraded | degraded = 提示「面板连通待交互确认」 |
| trimodel | GET http://127.0.0.1:3333/health（无鉴权可达性）+ key-cache 现状（fetchedAt/expiresAt/条目计数） | ok / degraded / fail | 网络不可达 = degraded 重试降级；401 认证失败 = blocked（§5.2 唯一阻塞类） |
| tristaciss | GET http://127.0.0.1:8008/v1/models（端口标准终案 8008） | ok / degraded / fail | fail = degraded（直连 fallback 过渡可用态，§5.1 现状） |
| plane-hint-probe（**第五探测**） | daemon 内部构造 TriPilot 形态会话：POST /v1/tasks/stream 带 workspaceRoot + systemPrompt 含 buildWeeklyPlaneHint 注入 → 校验事件流 task:queued→running→succeeded 无 task:failed | ok / fail | **fail = 诊断卡显式红行「问周面路径」+ 分类（模型链族/提示注入族/渲染族）——r19 前置缺陷不静默吞** |

summary 汇总规则：任一项 fail（blocked 级）→ blocked；仅 degraded 项 → degraded（降级继续，key 类不阻塞）；全 ok → pass。诊断卡逐行呈现 checkId/status/detail/hint，第五探测红行直接引用 §一 修复归属。
