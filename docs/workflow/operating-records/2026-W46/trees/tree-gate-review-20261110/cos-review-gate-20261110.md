## §一 · 适用域划界（本席方案主张一·候四席并陈）

- **纳入**：D-27 任务书拆树派工系**执行树**（`tree-op.json` 在树·值席拾取开工的树）——CEO 定谳「拆树派工只能 COS+COO 一起」的语境域。
- **不纳入**：非执行树（联审评审树/ patrol 记录树/tick 通报树/daily-progress 等记录面）——若全树纳入，patrol 将对自身记录树天天告警=噪音淹没；记录树有各自既有治理面（git 留痕+台账）。
- 判据一句话：「这棵树的开工会不会产生对外/对内执行动作？」会=纳入·否=记录树不纳入。

## §二 · CEO 定谳面转述（议题基座·如实入卷）

1. 拆树派工只能 COS+COO 一起进行；其他席位无权建树、无权开始执行树任务。
2. 每个任务树执行前必须检查 COS 授权（明确的授权字段与授权值，缺任一即不得执行）。
3. CEO 自评缺陷（如实）：CTO 本身是 agent·SendMessage 直发他席+工具调用执行任务，原则上无法拦截。

## §三 · 程序面设计（层面①）

### 3.1 授权文件形态：每执行树一枚 `tree-auth.json`

| 项 | 主张 |
|---|---|
| 形态 | 独立文件（不嵌入 tree-op.json）——机械可检（jq/grep 一发即中）+不改现有树结构向后兼容 |
| **签发笔分离（本方案核心）** | **授权必须由 COS 席位签发**（COS 会话写 tree-auth.json）·COO 拆树（写 tree-op.json）——**两支笔分离=互锁**；若授权随拆树顺手写=COO 自签 COS 授权·锁不住（自证循环缺陷） |
| 字段规格 | `{tree_id, authorized_by:"cos", authorization_ref:<台账笔锚或令文锚·禁空>, authorized_at:<date 现查原值>, scope:{seats[],windows[]可选}, expires_at:<可选·默认本周平面末>, status:"active"|"revoked"}` |
| 授权值检查（四断言） | ①文件存在 ②authorized_by=="cos" ③authorization_ref 非空且**可溯**（挂台账笔锚或令文锚——禁裸授权） ④status==active 且未过 expires_at——**任一不过=不得开工** |

### 3.2 执行侧读取检查点

- 值席开工第一动作=读 tree-auth.json 走四断言；不过→不开工+即报 BOD+COS 双面。
- FADE 树协议面：节点收口报告（§2.7）必含授权断言读数——无读数=收口不受理（机械面卡口）。
- COS 销账面：销账前验授权链——无授权树的活不销账（台账域卡口·三权保留内）。

### 3.3 拦截点选位（含现实评估）

- **最硬程序闸=会话内 PreToolUse hook**（D-47 闸先例同构）：值席会话对树目录的**首次写操作**前 hook 检查 tree-auth.json 四断言——机械可判（路径+文件+字段值）。hook 系 harness 层，bypassPermissions 绕的是权限提示非 hook——硬度高于 agent 自律。
- **绕过现实评估（如实）**：①agent 有写权限=可伪造 tree-auth.json 本身→缓解=authorization_ref 必须挂台账笔锚（台账=COS 域写时镜像+git 留痕——伪造授权需同步伪造台账笔+git commit·多面一致性攻击成本高·patrol git diff 可检出异常写入）——**提高伪造成本·不消除伪造可能**。②hook 只拦工具调用写面·SendMessage 直发「你去开工」的内容语义拦不了→**唯一真闸=收信席开工检查点自律+patrol 事后审计**。
- 定性：程序面做到「**违规必显性化**」（事后必可检出）而非「违规不可能」——硬隔离需进程/权限层重构（超本轮范围·候 CEO 另裁）。

## §四 · 值守工作流面（层面②）

- **零新增节律**（O3 教义）：现役 cos-patrol-timer 扩读数——扫当前周+上周 `trees/*/`：有 tree-op.json 而**无 tree-auth.json**的树=差集告警（新执行树未授权）；有 tree-auth.json 而 status!=active 或过期=告警。
- 工序：patrol 扫描→差集清单出卷（patrol-log.jsonl 留痕）→告警信 **BOD+COS 双面**→台账挂账候处。
- 双面互备：本机 patrol 扫本机树+sg m-duty-cos patrol 扫 sg 面树（同构·M-SG 外网派工通道同族）——两面 patrol 互为盲区兜底。
- patrol 自身停摆防护：patrol 产出 git 留痕+停摆=hub-silent-detect 现役读数族承接（patrol-log 无增量即告）。

## §三B · 候选 B·hook 层门禁设计（CEO 22:38 追令·四设计点逐项应答）

**技术底座采认**：PreToolUse 事件可拦 Bash/Write/Edit（permissionDecision allow/deny/ask）——D-47 落款闸即现役同构先例（本席会话在役实锚·机制可行性非纸面）。

1. **hook 读什么判定 COS 授权**：读目标路径所在树的 `tree-auth.json` 走 §3.1 四断言。**域判定先行**：路径含 `operating-records/<week>/trees/<tree>/` 且该树含 `tree-op.json`=执行树域→断言授权；非执行树域（记录树/评审树/台账镜像面）=直接放行（§一适用域划界的 hook 落地面）。
2. **拦哪些工具面（按树路径拦非全拦）**：Write/Edit 对执行树域内路径=Bash/PowerShell 命令文含执行树路径段（`git -C <树>`/cwd 切入/树内脚本调用）=拦+断言。docs/ 台账镜像等非域路径零触碰。
3. **误拦面与授权主体豁免（按域豁免·不按席豁免）**：BOD 值守落卷/tick 树/COS 台账镜像全在非执行树域=天然放行（无白名单成本）。COS 签授权=写 `tree-auth.json` 本身——**该文件名单文件白名单**（任何席可写·签发滥用面走事后审计：auth_ref 必须挂台账笔锚+git 留痕·patrol diff 验可溯性·乱签可追责）——授权主体过自己门=「文件级豁免+事后审计」形，不做席级豁免（席级豁免=COS 会话全域免检=自授权后门·不取）。
4. **settings 层级**：**每席独立 settings**（席位会话启动时指向各自 settings.json——项目级一刀切会拦 BOD/COS 记录面·用户级太宽）——工程落位（各席 settings 分流机制）候 CTO 域实勘细化。hook 配置面自解闸余隙如实注：agent 可改 settings 自我解闸（训练约束非技术闸）→缓解=settings 变更入 patrol git diff 监控读数+settings 只读化候宿主面另裁。

## §三A · 候选 A·C-level 执行工具写入权限收权评估（三形并陈）

| 收法 | 冲突面 | 可行性 |
|---|---|---|
| 全收（取消写入权限） | C-level 本职产出全要落盘（台账/卷面/毕报/设计单/分卷/值守通报落箱）——全收=每笔落盘走审批=值守面瘫痪·BOD 通报链/台账写时镜像/patrol log 全卡 | **不可行**（冲突面=全部日常工作产出） |
| 收执行留写入（收 Bash/执行类·留 Write/Edit 文档面） | C-level 仍需 Bash 做探活/读数/git log（值班通报/体检/台账现查全靠读类命令）——全收 Bash 同样瘫值守 | 需再细化为**命令族白名单**（读类 log/status/ls/GET 放行·写类 commit/push/POST 收权候批） |
| 白名单式（permissions allow/deny/ask 按席配） | 折中正形：文档写类放行+执行写类 ask（弹审批）+高危 deny——宿主侧现役支持（settings.json permissions 数组） | **可行·推荐形**（与候选 B 互补分层） |

**A/B 关系定性（本席卷面）**：A=权限层静态闸（席级·「这席能干什么」）·B=hook 动态闸（树级·「这次执行有没有 COS 授权」）——**双层并立非二选一**：A 管身份能力面·B 管授权检查面·合并=最硬可达形；纯 A 无 B=有权限但不知该不该干·纯 B 无 A=hook 可被绕时无兜底。候四席并陈 CEO 择配。

## §五 · 门禁面（层面③）

1. **纪律册条款**（候 CAO 铸条·与件三合并勘定防两张皮）：新增 D 系条「树执行授权门禁」三款——①拆树派工=COS+COO 双笔面（COO 拆树+COS 签授权·禁同席兼任）②开工前置=tree-auth.json 四断言任一不过禁开工 ③无授权树施工=违规·patrol 检出即告+事后审计追责面。
2. **考卷检查项**：FADE-001 考卷 verify 段扩 tree-auth 断言检查项（候 CTO 判据 owner——冻结考卷不动·新版走改版窗）。
3. **验收门**：节点收口报告必含授权断言读数；patrol 周报含授权差集读数（周清零=观察期通过判据之一）。
4. **观察期**（件四衔接）：重启后拟 **2 周**——判据=patrol 违规检出率 0+抽查树授权链全可溯（≥10 树抽样）——通过=门禁转常规；不通过=方案修版。

## §六 · 缺陷面如实评估（三层各余隙·不粉饰）

| 层 | 余隙（真实漏洞） | 缓解 | 诚实定性 |
|---|---|---|---|
| 程序面 | agent 可伪造授权文件；SendMessage 语义直发绕过 hook | auth_ref 挂台账锚多面一致性+收信席检查点自律 | 提高成本·不消除可能 |
| 工作流面 | patrol 本身也是 agent（停摆/被诱瞒报） | 双面互备+git 留痕+BOD 抽查读数 | 审计者亦可被审计·非绝对 |
| 门禁面 | 纪律对 agent=合同约束非运行时强制 | 观察期读数+人位（CEO/BOD）抽查 | 最终闸=人位·非代码 |

**总定性（本席卷面立场）**：本方案目标=「**违规必留痕·留痕必可检·检出必上报**」的显性化门禁——在 agent 直发原则上无法拦截的现实约束下，这是程序+工作流+门禁三层能到达的最优形；硬隔离（进程/权限层）如实标注为候 CEO 另裁的独立议题。
