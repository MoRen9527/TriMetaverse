## §一 · 需求本质与产品判读

**这不是技术问题为主，是治理产品问题**：把「谁可以开工」的授权规则从纪律册文字条款升级为机械可查的授权模型。缺陷本质=授权靠自觉（文字约束），而自觉在 agent 语境下不可依赖（机械优先原则④的逆命题实锤：没机械化的规则=靠自觉=会失效）。

**授权生命周期模型（产品化正形）**：授权不是静态字段是生命周期——申请（拆树需求）→签发（COS+COO 联署）→检查（执行侧三层）→过期/撤销（expiry+revoked）。**无时限授权=门禁形同虚设**（旧树过期授权放行新执行=僵尸授权·时效衰减原则同源）；**误拦=可用性反噬**（门禁误拦正常产出比无门禁更糟——会催生旁路文化）。

## §二 · 程序面（授权文件/检查点/拦截点+直发绕过现实评估）

**授权文件字段规格建议**（树目录 `tree-gate.json`·产品面建议 CTO 定稿）：
- `tree_id`（唯一标识）·`authorized_by`（**双签双字段**：cos+coo 各自席名+各自时点——单字段无法表达联署）·`issued_at`（签发时点）·`expiry`（**时限必填**·建议默认 72h——防僵尸授权）·`scope`（允许执行的席名清单+工具面清单）·`status`（active/revoked/expired·枚举）·`charter_ref`（任务书锚——授权可溯源到令源）。

**执行侧读取检查点**：执行 agent 开工第一动作=读树目录 gate 文件校验（status=active+expiry 未过+自身席名∈scope）→三条件任一不满足=停+上报 COS（不自行放行不自行改 gate 文件——gate 文件只有 COS+COO 可写=授权签发权与检查权分离）。

**拦截点选位**：三层——①hook 层（PreToolUse·候选 B·拦工具调用面）②值席 patrol 层（扫描树 gate 态·事后照亮）③销账对账层（对账时未授权树暴露=审计兜底）。

**agent 直发绕过的现实评估（CEO 自评缺陷·如实应对）**：hook 拦工具调用，**拦不住 SendMessage 语义层**（「你帮我建树」话语直发）——如实成立。产品面补位=**不追求 100% 机械拦截，采纵深防御+事后审计**：绕过 hook 的树会在 patrol 扫描与销账对账中曝光（未授权树=无 gate 文件或 gate 状态不合法→patrol 异常清单→追责+补授权或拆除）。**「拦不住就照亮」**——侦探控制补位预防控制，绕过无利可图（绕过的树活不过下一个 patrol 周期）威慑面即成立。

## §三 · 值守工作流面

值席 patrol 工序增授权态检查项：①扫当周树清单→逐树读 gate 文件→无 gate/过期/revoked/席名不在 scope=异常入清单→notify COS（urgent 形·信到人）②扫描频次建议=与盯守底座拍频对表（10min 轻拍量级·圆桌产出① watcher 归并——不另起平行件）③patrol 本身零处置权（只照亮不拆除·处置归 COS——零自动修复红线同源）。

## §四 · 门禁面

- 纪律册条款：D 系增「树执行授权门禁」条（gate 文件正形+三条件校验+三层拦截+豁免面清单）。
- 考卷检查项：FADE 考卷模板增「gate 校验执行」检查项——实例开工先过 gate=可评分行为。
- 验收门（本方案自身的验收）：**红蓝对抗实锚**——授权外席试建树→被 hook 拦记录；模拟直发绕过→patrol 曝光记录；COS/COO 正常落卷→零误拦记录。**不测绕过=没验收门禁**——三组实锚齐=方案验收 PASS。

## §五 · 两候选评估

**候选 A（C-level 执行工具写入权限收权）三形逐评**：
- **全收=反对**：C-level 正常产出面（台账/卷面/毕报/PRD——本席 PRD 真源即写入面）依赖写工具，全收=公司产出瘫痪，误伤远大于收益。
- **收执行留写入=可行但不单独够**：Bash 执行类收权+Write/Edit 保留——本质=把「归属路由阀门」（岗位件 0.5 条·写他人域产出物须路由审批）从纪律条款机械化为工具权限——方向正确，但拦不住「在自己域内执行未授权树操作」的变体（执行面白名单难穷尽）。
- **白名单式=渐进正形**：C-level Bash 按命令白名单收窄（git 读面/validator/ls 等安全族放行·建树/推送/删除类收权）——与跨平台整治同款渐进形（新增硬规则+存量顺手迁）。

**候选 B（hook 层门禁）四设计点应答**：
1. **hook 读什么判定**：树目录 gate 文件（§二字段规格）——注意 hook 判定必须含**会话身份输入**（当前席名/会话标识）否则豁免不可实现（机制事实归 CTO 勘：PreToolUse 事件能否取到会话身份=方案可行性前置断言）。
2. **拦哪些工具面**：Bash 按「树操作特征」拦（建树/删树/批量写 operating-records 命令模式）+Write/Edit **按树目录路径拦**（operating-records trees/ 下新建树目录=拦；卷面更新既有授权树内文件=凭 gate 放行）——**树执行面 fail-closed（拦错比漏拦好）·非树产出面 fail-open（误拦卷面=产出瘫痪）**——fail 方向分离是本方案最重要的设计原则。
3. **误拦豁免**：授权主体白名单（cos/coo 席名=签发者自免）+值守落卷面（BOD 值守直落主检出正形路径白名单）+非树路径全局放行（§2 fail 方向）。
4. **settings 层级**：项目级入仓（.claude/settings.json 版本化=全席一致可审计）+**hook 脚本内部按会话身份分支豁免**（不搞每席独立 settings——分叉=漂移温床·陈旧态教训同源）。

**组合结论：B 为主+A 收窄形并入，非二选一**——B（hook+gate 文件+纵深）=主干；A 白名单式（Bash 执行面收权）=B 的工具面补充；A 全收=否决。分层组合=纵深防御的一致形态。

## §六 · 纵深防御总形（三层·产品面总判）

| 层 | 机制 | 拦什么 | 漏什么 |
|---|---|---|---|
| L1 hook 预防 | PreToolUse 拦工具调用 | 绝大多数工具面建树/执行 | SendMessage 语义直发 |
| L2 patrol 侦探 | 值席扫 gate 态 | hook 漏网树（含直发建树） | patrol 周期内的窗口期 |
| L3 对账审计 | 销账对账暴露未授权树 | 一切存量违规 | 无（终态兜底） |

三层各漏各补——**CEO「原则上无法拦截」的正解不是放弃，是把「拦截」换成「纵深+照亮」**：绕过成本>合规成本（绕过的树活不过下一个 patrol 周期+对账必曝+追责留痕），威慑面成立即治理目标达成。

## §七 · 风险与前置断言

1. **前置断言（CTO 面·方案可行性门）**：PreToolUse hook 能否取到会话身份（席名）——取不到则豁免设计塌方，须先勘。
2. gate 文件被伪造/篡改=门禁被攻破——缓解：gate 只有 COS+COO 可写（git 层权限+commit 归属审计）+patrol 校验 gate 的 commit 归属（签发席 commit 才算数）。
3. 误拦投诉通道：被拦席对 gate 判定有异议→上报 COS 复核（不自行绕过——绕过即违例）——门禁配套申诉面，防旁路文化。
4. 时限 23:45 内出具=方案深度受时限约束——本卷为产品面框架+判据，字段规格终稿与 hook 实现细节归 CTO 面，候总卷合并。
