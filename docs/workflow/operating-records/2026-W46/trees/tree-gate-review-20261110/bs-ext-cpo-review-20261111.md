## 判定总形：不扩——但须两配套件随行（判据精确化+原则文一句话锚）

独立判与 CEO 倾向结论一致，**理由独立**：不是「编制外席不重要所以不写」，而是「机制已覆盖+点名=漂移温床」——扩圈需求本身不存在（无验证路径的场景不设条款）。

## §一 · 核心辨析：挂载闸是行为闸，不是身份闸

v2 框架的结构性优势在本议题下显影：**门禁查的是「执行行为有无授权件」，不是「执行者是谁」**——执行必经服务域挂载闸，任何席（编制内外）持合法授权件（COS+COO 双签+expiry 未过）即过闸，无授权件即被退回。

推论：bs role 持 All tools 的能力面**在挂载闸模型下天然已被覆盖**——它现在无树执行职责（行为不存在），未来若有执行需求→必经闸→按授权流程申请即可。**闸不因原则文不点名而失效**。

「写入原则文」的真问题因此不是机制覆盖（已覆盖），而是**文本要不要点名**——点名制 vs 规则制之争（§三）。

## §二 · D-78 界分判据自洽性检查：措辞须精确化（配套件 1）

D-78 现行判据「只读=不入闸域」对两席族的适用检查：

- **registries 族**：定位=非人格数据枢纽（facts/state/boundaries/indexes/memory only）·工具面 Read+Glob+**Edit**——Edit 面限自家 registry 收口写，无执行行为。按字面「只读」判据，registries 族**不完全命中**（它有 Edit）；按精神「无执行行为」判据则完全命中。**判据措辞与席位现实有缝隙**。
- **bs role**：All tools 面但域=战略裁决+模块边界，无树执行行为——「只读」判据同样字面不命中（它持写工具），精神命中。

**配套件 1（建议随原则文一并勘定）**：D-78 判据从「只读=不入闸域」精确化为「**无服务域执行行为=不入闸域**」——判据锚行为不锚工具面，两席族字面+精神双命中，自洽达成。锚行为还有一利：工具面是五件套可变项（改版即漂移），行为是治理定义项（稳定）——判据锚稳定项。

## §三 · 扩与不扩的产品判据（正面立论）

**不扩判据（四条）**：

1. **机制层已答**：挂载闸行为闸——执行必经=编制无关全覆盖（§一）；点名与否不改变闸的有效性。
2. **点名=漂移温床**：原则文写编制名单→roster/五件套每变一次原则文即陈旧（编制外席族本身随组织演化）——陈旧态呈报族教训的直接应用；**名单化反而造空档**（名单外未来新席=规则外？规则制天然全，名单制天然漏）。
3. **需求不存在**：编制外席无树执行职责=「编制外执行树」场景不存在——无验证路径的场景不设条款（MVP 纪律同源：为不存在场景立法=过度设计=「想复杂了」的另一种形态）。
4. **重复立法**：D-78 界分判据已入册=界分正身已存在——扩圈写入=同域二法（防两张皮·件 B CAO 归口同款考量）。

**扩判据检查（反面均不成立）**：

- 「防未来」：未来执行→必经闸→届时申请授权即可——闸不失效。
- 「完备性」：原则文管执行行为规则非执行者名单——规则（须授权）适用于一切执行行为。
- 「审计」：审计对象=授权件+行为（挂载闸日志+patrol 照亮），不按编制点名——不受名单影响。

**配套件 2（建议随原则文一并落）**：原则文加一句「**闸域判定=行为判据（有无服务域执行行为）·非编制判据（席位名单）**」——一句话把「为何未点名编制外席」写死在原则文内，防未来误读为遗漏、防有人以「原则文没写我」为由主张规则外。**写判据不写名单**=原则文该有的形态。

## §四 · 真空档如实注记（非本议题·候治理窗）

编制外席的**违规问责归属**是真空档：若 bs role/registries 族绕闸违规执行，追责对象与 scorable 归属未定义（编制内席有绩效体系挂靠·编制外席问责链未立）——但此空档**不是「扩圈写入」能解的**（问责面归 CHO/治理域另一线），混入本议题=议题越界。如实注记候治理窗单独立题。
