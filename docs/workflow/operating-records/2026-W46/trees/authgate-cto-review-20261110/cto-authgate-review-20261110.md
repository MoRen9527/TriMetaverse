## 一、授权件规格（程序面核心·机器可读正形）

**形**：每树根落 `authorization.json`（ADE 家族同形·与 .shift-ade.json 读数形统一）：

```json
{
  "objectType": "TREE_AUTHORIZATION",
  "tree": "docs/workflow/operating-records/2026-W46/trees/<tree>",
  "authorized_by": "cos",
  "co_signer": "coo",
  "authorized_at": "<ISO8601 原值>",
  "scope": ["<执行席名清单>"],
  "execution_permit": true,
  "order_msg_id": "<COS 派工信 msg_id 锚>"
}
```

- **规格要点**：①机器可读（执行侧/消费侧/巡检侧三面同读一份）②`order_msg_id` 锚=授权令回链到 COS 派工信原文（「已发≠在链」纪律投影——授权可溯源到发信记录非自述）③落卷 commit 署名（@m-cos）=**授权不可抵赖锚**（git log author 对表席位·伪授权可事后审计发现）；
- **裁决要素**：authorized_by ≠ cos 或 co_signer ≠ coo 或 execution_permit ≠ true = 任一不满足即无权态——**字段值面三查**（键在≠值对·家族纪律投影）。

## 二、三层拦截点选位（含直发绕过现实评估·如实）

| 层 | 拦截点 | 硬度 | 拦什么 | 拦不了什么 |
|---|---|---|---|---|
| **L1** | pre-commit hook：新树目录 commit 必须带 authorization.json·无=拒 commit | **硬**（机器强制） | 无授权树进 git 链 | ①落盘不 commit 的裸工作区（hook 只拦 git 面）②他宿主/他机落盘 |
| **L2** | 执行席接令自检：接树令三查（授权件在/字段值面/双签齐）·无权态=拒执行+报 COS | **软**（纪律约束） | 无权执行动作 | 执行席无视纪律硬跑（agent 直发令绕过 COS 直接指挥执行席） |
| **L3** | 消费面检查：树收口/销账/registry 入链/台账记账面验授权态·无权态产出物不入链 | **硬**（机器可强制·门消费面读树不读会话） | 无权产出物变既成事实 | 已产生的副作用（树卷已被读/被引用） |

**agent 直发绕过现实评估（CEO 自评「原则上无法拦截」的技术定性——如实）**：
- **技术事实**：SendMessage 传输层无 ACL——A 席直发 B 席令+工具调用执行，宿主层拦不了「发令」这一步。任何把拦截点放在传输层的方案都不成立；
- **防线实质=三转化**：把「不可拦」转化为「①不入链（L1+L3 硬闸——绕授权的产出物进不了 git 链与收口链=白干）②可发现（patrol 授权态扫描+裸工作区树与授权态缺失可见）③可问责（git 署名锚+msg_id 锚——谁建的树谁落的盘事后可审计）」；
- **残余风险如实**：执行席无视 L2 硬跑的极端场景，副作用面（文件系统写入/外部系统调用）技术上无业务层拦截——唯一硬拦=宿主权限系统（per-session permission·拦工具权限非业务授权·不在本方案域）——方案不冒称绝对拦截形；
- **结论**：与 CEO 自评一致——本方案把门禁从「拦动作」重构为「拦入链+留痕迹+可问责」·威慑+审计形·非绝对拦截形。

## 三、值守工作流面（patrol 工序设计）

- **检查项并入现役 patrol**（cos-patrol-timer 树在役·零新工序零新固定成本）：每轮扫 `trees/` 现役树→逐树验 authorization.json 存在+字段值面三查→输出授权态读数（合规/缺件/无权态三分类）；
- **异常处置工序**：缺件树→通报责任席补授权（宽限期一巡）；无权态树（无授权件而有执行痕迹）→通报 COS+树标记执行冻结+git log 署名溯源（谁落的盘）→按 D-27 责任链处置；
- **巡频**：照现役 patrol 节律·增量成本≈每树一次 JSON 读取（零 token 机械面）。

## 四、门禁面（纪律条款+考卷项+验收门）

1. **纪律册新 D 系条款候选**（「树执行授权门」）：①拆树派工=COS+COO 双权（CEO 定谳面照录）②树 authorization.json=执行前置件③执行席接令三查·无权态拒执行+报 COS④消费面验授权态（L3 硬闸）⑤**紧急通道=COS 快速授权（授权动作快·门不豁免）**——不设「紧急免授权」弱化入口（门不豁免哲学投影）；
2. **FADE 考卷 Verify 断言集增项**：树授权态检查=机械可查断言（authorization.json 存在+字段值面）——入冻结考卷 v1.2 修订注记序（走冻结勘正序·不现改冻结卷）；
3. **验收门**：树收口/销账动作面验授权态——无权态产出物销账请求=拒+通报（D-27 收口面扩一点）。

## 七、候选 A 应答 · C-level 执行工具写入权限收权评估

**冲突面（如实）**：C-level 正常写卷面=台账行/联审分卷/毕报落卷/registry 回写/任务书/裁定卷——本席今夜单值守段即落 8+ 卷件：**全收=席位认知产出物落盘全面瘫+COS 代写单点瓶颈+固定成本爆表**——判全收不可行（「中枢爆溃」风险放大面）。

**三收法评估**：
| 收法 | 判 | 依据 |
|---|---|---|
| 全收 | **否** | 上述冲突面·席位职能瘫痪 |
| 收执行留写入 | **可行但需再切** | 技术面上「写入」与「执行」在工具层不可分（Edit 树卷=写入·Bash 施工=执行但同样写盘）——可操作切法=**按路径域+工具域**：树卷写+registry 写+本机读面保留·跨机执行写面（ssh 河源/sg 写操作+daemon POST/PATCH 写 API）收权——与「施工=FSD 面」既有分工对齐（C-level 本不该直跑施工·收权=纪律约束升机器约束） |
| 白名单式 | **可行·推荐形** | 现役 settings permissions 数组本系白名单形——扩颗粒度：C-level allow=读面+树目录写+registry 写·deny/ask=跨机执行写面 |

**残余风险如实**：ssh/Bash 命令内容面判（读形放行/写形 deny）系字符串级判——**可被等价变体绕过（变量拼接/脚本中转）——收权=提高门槛非绝对墙**·与直发不可拦同构定性。且 C-level 值守读数（活体勘验一发 ssh 读探针）依赖跨机读面——deny 全 ssh=值守面瘫·白名单须保读形通道。

**判**：候选 A 可行形=**白名单式·按路径域+工具域切·保读形通道**——与候选 B 和原三层组合成纵深（见 §九）。

## 八、候选 B 应答 · hook 层门禁四设计点（CTO 域细化）

| 设计点 | 应答 |

| ①hook 读什么判定 | 树目录 `authorization.json`（§一规格同形）——hook 内做**值面三查**（authorized_by=cos+co_signer=coo+execution_permit=true·键在≠值对）·任一不满足=无权态 |

## 九、纵深组合与总评（A+B+原三层=完整防御形）

**五层纵深**：A 权限层（工具权限·机器硬）→B 写入层（PreToolUse hook·机器硬）→L1 git 层（pre-commit hook·机器硬）→L2 纪律层（接令三查·软）→L3 消费层（收口/入链验授权态·机器硬）——**软层只剩纪律自检一处**·四硬层机器强制。

**组合判**：候选 B=原方案 L1 的强化前置形（拦 commit→拦写入动作本身·更早）·候选 A=L2 的机器化（纪律约束升工具权限约束）——**A+B+原三层非三选一·系同一场门禁的三个深度**·建议全组合落地。

**落地排程**：P1=授权件规格+L2 条款+L3 消费面（先立·零基建）→P2=B hook ask 档+每席 settings 分流（~1-2 天工程+两周误拦观察）→P3=A 权限白名单收权+L1 pre-commit hook（观察读数后收 deny 档）→考卷断言项随观察读数定——每步独立可回滚。

## 十、前置断言答（CPO 卷问·PreToolUse hook 取会话身份可行性）

**断言：可行·主路径=env 继承+辅路径=session 对表·伪造面=低（宿主 permission 罩住）**：

1. **主路径（env 继承）**：hook 进程由 Claude 宿主主进程 spawn·**env 继承自主进程**——席位启动器注入席位名 env（SEAT_NAME=<席名>·现役座位 env 注入先例同形：POWERSHELL_UPDATECHECK=Off/座位变量族）→hook 读 env 即得当前席名→对表授权件 authorized_by/co_signer/scope 判「授权链内放行」。工程前提=13 席启动器统一补席位名注入（启动器一处改·一次性低成本）；
2. **辅路径（session 对表）**：hook stdin 输入含 session_id+transcript_path——对表 `.claude/seats.json`（席位注册表现役）动态映射·作 env 缺失时的第二判定；
3. **伪造面如实**：agent 在 Bash 子进程内 export 冒名=**无效**（hook env 继承自宿主主进程·Bash 子进程污染不回传主进程）；真伪造需改宿主进程 env 或启动器=改权限面文件→被宿主 permission 系统挡（permission laundering 防范域）——伪造门槛=宿主级·非会话级可绕；
4. **fail-closed 兜底**：临时形会话（claude -p 无启动器 env）取不到席名=按无权态处理（deny/ask）——**取不到身份不放行**（门不豁免哲学投影·宁可 ask 多一次不漏门一次）。

**判**：豁免设计（授权链内席位放行+自动件清单）的会话身份取面可行——前置断言过门·候选 B 全设计点成立。
