## §一 · 五要点必要性逐判（防过度设计第一道）

判据先立：**产品必要=把现有错误死法改对（死得早/死得响/死在正确阶段/死有名字/死好找）；工程自嗨=新增能力或新系统**。五要点逐过：

| 要点 | 判 | 产品理由 |
|---|---|---|
| ①铸 run id | **必要**（度量主键） | CPO-011 三读数（成功率/发现时延/修复时延）记录单元=run——无 run id 三读数无处挂靠，读数退化为周粒粗读。run id=度量的主键不是工程洁癖。形制候议形含周号+时刻=自解释好；**补一条建议：Z 后缀 UTC 明示**（跨机时区对表纪律——河源/sg 双机位无 Z=时点歧义源）；形制定死不再改名（命名稳定=机械扫描前提·DEM-007 同源） |
| ②preflight 上移 | **必要**（无过度设计嫌疑） | 「死得早死得响死在正确阶段」=产品可感知性本质改善：公司面从「迁移成功但迁错了」（静默数据事故）变「迁移没跑+告警」（可修复可归因）。四条断言是准入门槛不是新功能；8710 healthz 探针上移=F2 到岗窗产品面配套 |
| ③触发告警闸 job 级 | **必要·五要点中优先级最高** | CPO-011 基线实锚=发现时延 19.5h（CEO 亲令盯才发现）——告警闸直接把发现时延压到分钟级。job 级非 service 级=定位性（degraded service 级 max over jobs 抹掉「哪个 job 在败」·周任务专属告警现架构不存在=BOD 研究 §二判读，本要点补的就是这个产品缺口） |

## §二 · 三问②边界：归本阶段 vs 留后段（防过度设计第二道）

**边界总判据（产品面提出）**：第一阶段改造**不改迁移本体行为**——preflight 四条是准入检查（不过=不跑零副作用），bash 交棒后流水线接的是既有 L6-L7 本体。验收面=「触发阶段行为变化零外溢」：改造后迁移成功的产出物（W 目录结构/carry-over 语义/commit 形）与改造前 byte 级同形——任何外溢=越界改了本体，打回。

**归本阶段**：五要点全部成立（每条都在「改对错误死法」域内，无一条新增能力）。

**留后段（显式清单·防范围蠕变）**：
1. qualify agent 到岗断言（阶段 2）——本阶段 preflight 只做机械探针（8710 healthz），agent 到岗窗不塞本阶段。
2. plan skill（阶段 3·纯业务面）——本阶段不实现；产品语义锚提前定（§五）防后段语义漂移。
3. DCE 段重构+统一自愈标准（阶段 4）——「同一根链管子一半有自愈一半没有」（BOD 研究 §二）是真问题，但解法=设计标准一次性定清，属 DCE 段改造窗，不塞触发段。
4. **ζ 疑点（成功面无闸·notify 失败=成功不可达）**——真缺口但归阶段 5/10（verify cli/结论与动作段·映射表 §二第 10 格 F 系销项位）。第一阶段不塞。

**两处防过度设计显式提醒**：
1. **告警闸不要做成告警系统**——「N 分钟无成功日志+job 级」两条判据够；不做告警分级/路由/聚合（那是盯守底座的事·圆桌产出①归并口径）。BOD 研究 §六 Q3「告警器住在哪」产品面回答：**告警器住在盯守底座 watcher 面，FADE-001 只提供「无成功日志」信号源**——告警器归属不落 FADE-001（防 FADE-001 自带一套平行告警=四套平行建反例）。
2. **run id 不要做成 run 管理系统**——铸 id+全链挂靠即可；不做 run 状态机/run 查询界面/run 历史库（映射表 §二第 9 格「run id 终态落卷」够了·FADE-012 适配语义后续段的事）。

## §四 · 验收锚可复算性设计（照 LG-096 五条先例·CPO-011 收册形）

第一阶段验收锚建议（五条·全可机械复算）：

1. **run id 全链挂靠**：改造后首轮 run 的 log 目录名/聚合文件名/close 记录三处=同一 run id 字符串（grep 对表）。
2. **preflight 拦截实锚（注入式）**：临时注入一条必败断言→bash 不执行迁移+告警发出（告警达 COS 记录）——DEM-009 同款注入式判法。
3. **告警时效实测**：模拟败跑→通知 COS 时延 ≤ N 分钟（N=告警判据值，CTO 定稿；**口径对表 CPO-011 发现时延≤2h——同值同源不两套**）。
4. **零外溢断言**：改造后首轮成功 run 的产出物形态与改造前对表（W 目录结构/carry-over 语义/commit 消息形三处=同形）。
5. **F5 修复旁证**：store 路径唯一真值面（一处配置改两处生效，或两路径显式分开记录可查）。

与 CPO-011 关系注：CPO-011=度量口径（读什么）；本五条=改造验收（改对没有）——共用「发现时延」口径同值同源。

## §五 · plan skill 产品语义锚（CEO 23:06 定调纯业务面·提前定锚防后段漂移）

- **迁移范围业务判据（草案·候定谳）**：迁=周平面产出物（trees/周记/daily-progress/OP/unresolved——「上周活动记录」语义）；不迁=机械噪声件（tick-log/patrol 轮转等既有规则已处理的）；carry_over=在办树/未决项（「活动未完成·随周带走」语义）。判据本质一句话：**「这是一周的记录，还是这一周的活」——记录随周封存，活随人带走**。
- **plan skill 产出验收标准（可复算）**：①迁移清单枚举完唯一（清单外新文件=漏·清单内不存在=幽灵，双向断言）；②不迁清单每行带判据注明（为什么不迁·一句）；③carry_over 预审每项带状态与去向（滞留旧周=死信风险标注）。
- **产品定位一句话**：plan skill 是「迁移的预审清单」不是「自动决策器」——产出候审清单，qualify/DCE 才动。第一阶段不实现，本节=语义提前定锚。

## §六 · 三问③风险：11-15 时钟的产品面决策建议

F4 时钟真实（研究 §四：若 sg-bare/dev 再 diverging 且拆分未落地，F4 原样再炸——唯一有时钟的现役风险）。产品面决策建议：**优先告警闸先行，而非赶工全量改造**：

1. **赶工改造=为时钟压力压测试门**——省测试=造新雷（构建绿≠运行时通教训同族），不接受。
2. **告警闸可独立先行**：要点③判据=「读现有 per-run log 判无成功日志」——不依赖 bash 改形，不动触发器本体，**可在 11-15 前单独上线**=「临时缓解」的产品面正形：不改结构先装烟雾报警器。11-15 若再炸，发现时延从 19.5h 压到分钟级=爆炸代价大幅降级（11-08 轮实证：修复成本小时级、发现成本 19.5h——装上报警器后「再炸一次」的净代价≈一次小时级修复）。
3. **五要点 11-15 前优先级序（若全量赶不上）**：③告警闸先行 ＞ ②preflight ＞ ④bash 改形（与①run id 同卷，id 依赖改形后的触发器）＞ ⑤F5（顺手不赶工）。
4. 「接受再炸一次知情」若发生=按既有序号走（应急链 D-27 直派先例在·修复有谱），事后 run id 锚三读数基线第二拍。
