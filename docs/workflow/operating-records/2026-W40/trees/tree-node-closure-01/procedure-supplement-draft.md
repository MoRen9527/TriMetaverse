## 三、状态账载体与记录形态

- **载体荐=`trees/<treeId>/node-status.jsonl`**（append-only，一行一记录，COS 落笔；巡检器可机器读）。轻量候补=树目录状态行（任务书 §一.1 原文形态）；jsonl 与状态行不排斥——jsonl 为机器面，md 状态行为人读面可由巡检器/工具派生，候定稿裁。
- **记录字段（一行 JSON）**：

```json
{"ts":"2026-09-28T00:00:42+08:00","tree_id":"plane-shift-local-align-01","node":"execution-report","actor":"SDE","state":"done","receipt_id":"86a17e99","content_ref":"align-rehearsal-and-form-study.md","recorded_by":"cos"}
```

- `state` 枚举复用协议节点状态族：`done / missing（缺卡标记，代记/催办用） / escalated`；
- `recorded_by`：`cos` 或 `deputy:<身份>`（代记时必填，见 §五）；
- 六行即全链审计链，任一时刻读账可知全链进度（任务书 §一.4）。

## 四、5 分钟超时规则（含细化勘定，候定稿裁）

- **计时起点**＝前节点完成证据落账（收口件 ts）；
- **超时判定**＝后继节点 5 分钟内无**接管证据**→催后继责任席；
- **细化勘定（草稿补充口径，源自任务书 §四「不含承接席作业时长」，候定稿裁）**：
  - 流转型节点（流转/拆派/汇录/验收销账）：收口件本身即接管证据，5 分钟内须现；
  - 执行型节点（执行·回报）：**作业时长不计入**——5 分钟只卡「认领」（接令回执 id 到 COS），收口件随作业毕落账。若按字面「后继收口件未现即超时」套执行节点，长作业必假阳性——此为字面口径与 §四排除项的张力点，**显式提请定稿裁决**；
- **催办动作**：notify 后继责任席（LG-036 通道＋/或 SendMessage），催办事件本身留痕入状态账（`state:"missing"` 记录）；
- 5 分钟为试点初值，试点单后可调。

## 六、恢复读树续办步（SOP 增补原文草稿）

> 席位会话重启／断线后，接手者（复活体或代接席）按以下顺序续办：

1. 定位在途 `treeId`（挂账台账树指针／最近拆派消息），打开该树目录；
2. 读 `node-status.jsonl`：哪些节点 `done`（含回执 id）、哪些节点欠卡——**全链进度自知，不靠记忆靠树**；
3. 从**最后收口节点**之后续办（最后 done 节点的 `content_ref` 即工作上下文入口，routedInput 语义同源）；
4. 续办毕照常随消息交回执 id，状态账照常推进；
5. 若中断点在执行节点内部（非流转链断），转协议 §7.1 崩溃恢复流程（checkpoint 幂等续跑）。
