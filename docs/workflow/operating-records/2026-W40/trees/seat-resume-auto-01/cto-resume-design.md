## §一 问 1：零交互拉起 CLI 正解——**`--resume <session-id>` 精确形态，侧车供 id**

三形态勘验裁：

| 形态 | 交互性 | 判定 |
|---|---|---|
| `claude --resume <session-id>` | 零交互，精确 | **主形态**——看门狗持席 session-id 直拉 |
| `claude --continue` | 零交互，「最近」 | **多席面禁用**——13 席同 project 目录（D--Code-ai-TriMetaverse），「最近」=可能拿错席的会话；仅单席专用机可作降级 |
| 裸 `--resume` | 交互列表 | **自动化禁用**（本次事故根因形态） |

- **session-id 供源=席位侧车文件**：`.fade/seats/<seat>.session`（pidfile 同族纪律：按席分文件、启动器写、看门狗巡检刷新）。写时机①席位启动器启动成功后落盘；②看门狗健康巡检时从名址系统（13/13 注册面）对表刷新——断线瞬间侧车 id 必为最近有效会话。
- **侧车失效时的最新会话判据**：`~/.claude/projects/<proj>/` transcript jsonl 按 mtime 排序取最新+**名址指纹过滤**（转录头部席位身份标识核验）——防跨席拿错；无指纹可验的转录不自动采用。

## §二 问 2：拉起链环境纪律——**resume=新进程，env 三件套重刷（BOD 代起教训直引）**

- **resume 拉起前 env 强制集**（缺一不可，缺=不存转录不注册名址）：
  1. `CLAUDE_CODE_CHILD_SESSION` **必清**（环境遗传坑根因，03:29 实证）；
  2. `FORCE_SESSION_PERSISTENCE=1` **必设**；
  3. 其余 launcher env 照 D-03 快照纪律全量重刷（token/模型/通知通道面）。
- **拉起动作纪律**（保活链五条对齐）：权威启动器路径拉起；断线检测后旧进程已亡无需杀（半死残留清理走既有 pid 验对纪律，**禁裸杀**）；拉起后 healthz 类留痕（此处=侧车回读+转录 mtime 快照留痕）。
- **dry-run 位**：拉起命令组装后先打印全串（env 清单+resume 命令+目标 id）不执行，一轮验证格式——先导实弹前置步。

## §三 问 3：断点接续验证——**两级判据（L1 存活自动断言 + L2 任务接续留痕）**

| 级 | 判据 | 形态 |
|---|---|---|
| L1 存活 | resume 后 **T+120s 内原 transcript jsonl 字节增长**（阈值 ≥1KB，可调）——转录续写=会话真接上 | 看门狗内建自动断言，失败触发降级序 |
| L2 任务接续 | resume 后看门狗投递**断点续办消息**（treeId+节点指针，LG-057 §六读树续办步格式：「读 node-status.jsonl 从最后 done 节点续办」）→席位接令回执=任务级接续证据，回执入状态账 | 自动投递+回执留痕，值班席可读 |
| 响应性核验 | capture-pane 增量**只认 thinking/对话流增量，禁认 ❯ 行文本**（暗示提示幽灵线坑直引） | L1 的防误判子句 |

- **取舍声明**：L1=降级触发器（机器可判无人值守）；L2=接续质量证据（比「验证接上了」更进一步——直接续办而非仅验证）。两级皆自动，不自欺不靠人盯。

## §四 问 4：失败形态——**四级降级序+卡死检测+熔断**

1. `--resume <侧车id>` 失败（无转录/损坏/秒退）→ ②侧车从名址系统强刷重试一次；
2. 仍败 → ③项目目录 mtime 最新+指纹过滤候选 id 重拉；
3. 仍败 → ④**裸交互列表形态+TRIMC_NOTIFY toast 值班席**（LG-036 通道现成）——人工兜底但留痕提醒，非静默卡死；
4. **交互卡死检测**：resume 后 T+90s 无转录增长且 capture-pane 命中会话选择列表特征 → 判卡死并入④；
5. **熔断**：连续 ≥3 轮失败 → 停自动重试+升级 toast（防循环拉起风暴）。
