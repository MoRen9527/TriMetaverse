## 一、设计对象与总原则

秘书处制度（`TriCompany/docs/workflow/cyber-company-secretariat.md`）增「值守班次」节，与语义级静默探测（CEO 否 mtime+2h 原案后新案）对接成一体方案。总原则：

1. **排班解决「谁在值」，探测解决「断了知不知道」**——两案一体设计，班次节定义告警接收方与响应义务，探测机制定义触发面；
2. **不另起炉灶**：值席位复用现役 m-duty-cos 正名与实践形态（夜航01/sg 值席批次先例），告警通道复用 LG-036，探测挂 Seat-Watchdog 同窗；
3. **值≠在办**：值席是响应义务不是任务在办——候令待命静默属正常态，探测判据必须区分两者（语义级方案的「有在办单」前置即此义）。

## 二、谁在值（值守角色定义）

1. **值席位**：常设行政班次岗位，由 COS 面承担（通信正名 m-duty-cos，现役实践正名；单席值，不设多席同值）；
2. **兜席位**：值席缺位或无响应时的升级承接=BOD（董事会直连会话，全天在位性由宿主面保证）；
3. **值席三责**：
   - **告警响应**：承接静默探测告警（语义级链路终端），按 §四 响应动作处置；
   - **催办断面**：值守窗内对在办单超时限（D-34/D-27 档）的在途任务主动催办——12:08 型「催办单点依赖随 COS 会话挂起双失效」（CHO 卷 ca6fc723 缺口二）的制度补位；
   - **应急通道**：停工不停应急先例（09-25）的常态化——值席是应急令的第一承接面。
4. **值席三不**（职责边界）：不替代 owner 办活（只催办不代工）；不裁内容面（技术/产品判断归 owner 席）；不动正身（制度与真源改动走批程不走值席通道）。

## 三、班次怎么排（排班规则）

**时间底座**：班次密度跟随排程哲学（对接件款一）——黄金期（18:00-次日 14:00）任务最密，值守必须全覆盖；14:00-18:00 双高峰禁窗活动最稀，值守可减配不空窗。

| 班段（北京） | 密度 | 值守配置 |
|---|---|---|
| 18:00-24:00（最优批量窗） | 高 | 值席全责段（告警响应+催办巡检） |
| 0:00-9:00（夜间最优窗） | 高 | 值席全责段；夜航形态（sg 侧）照现役值席批次惯例 |
| 9:00-12:00（平价窗） | 中 | 值席常规段 |
| 12:00-14:00 | 中 | 值席常规段 |
| 14:00-18:00（双高峰禁窗） | 低 | 值席减配段（只保留告警响应，催办巡检免） |

**排班载体**：值班表按周排，COS 汇总写入 operating-records 周索引件（周平面随迁，零新系统）；值席变更=台账状态字段更新，不另立排班工具。

**与 7×24 的关系**：服务域（sg daemon 面）本就 7×24 自动运转，值守针对的是**半自动本地域 13 席会话面**——排班哲学「全自动排服务域、半自动排本地域」在值守面的投影：本地域会话静默才需要人值，daemon 死活归 watchdog/TriMLC-Watchdog 机器面。

## 四、与语义级探测的对接面（接口契约）

CEO 新探测链路（BOD 转述）：**看门定时检查 → 有在办单 → COS 查最优先任务树 → 节点 idle → SendMessage 直达**。

| 接口字段 | 供方 | 本卷侧定义 |
|---|---|---|
