## ②部署形态与用户价值

- **单租户改值起步，不为多租户预付架构税**：值文件天然每实例一份（values-<tenant>.json），多租户只是值文件管理问题非模板问题——P3 之前不做租户面，一套模板+N 份值即多租户全貌。
- **两维度定制深度差异**：公司维度（TriCompany）改**身份与组织语境**——浅层高频（公司名/员工名/行业语），价值=「这套 AI 班子拿去就是我自己的团队」的部署就绪感；项目维度（TriMetaverse）改**技术与结构语境**——深层低频（模块名/仓路径/命令族/端口），价值=方法论与纪律原样迁移到新项目。**产品建议：公司维度先做**（改值收益立现、槽位集中、用户操作成本分钟级）；项目维度槽位散布工程文档面，P2 跟进。
- **用户改值操作成本预期**：JSON 平铺键值改一处即改——单值分钟级；真实成本在**值不齐风险**（正名改了别名漏改）——成本控制不在文档而在工具：渲染管线**残留扫描**（成品零 `{{ }}` 命中=完整性门，STE 禁词扫描器同款机制复用）+**槽全覆盖断言**（模板槽位与值文件键集 diff 报缺）。
- **一句话价值锚**：定制不是「能改名字」的功能，是「部署给谁就长成谁的样子，但规矩一模一样」——面子（呈现层槽）+里子（契约面白名单）缺一不可。

## ③与既有治理链的产品化口径

现役链：源侧真源（source-agents/ 模板+槽位）→ 渲染管线（填槽+断言，--host 参数扩 --tenant/--values 参数，正交不耦合）→ 发布拷贝（已填槽成品，禁人工编辑不变）。

- **填槽时点=渲染时，非发布后**——源侧真源保持 {{槽位}} 形态（模板真源），值文件=部署实例资产（新资产类型，类比 binding profile 位阶），发布拷贝照旧只读。**治理链零改动，只增一个输入。**
- **值文件变更流程**：部署实例的配置变更（与 binding profile 同族位阶）——不走源侧五件套合同（那是模板变更），轻流程（实例 owner 改值+重渲+断言门）。
- **防漂移双断言**：模板加新槽而旧值文件缺键→槽全覆盖断言报缺（渲染失败出声，CTO 三钉同哲学）；值文件多键无主→告警不阻塞（前瞻兼容）。

## 五要素收束

1. **可行性**: 高——管线模板机制/binding profile 值分离模式/正文孤立项样态三处地基已验证，泛化非新建。
2. **工作量级**: 小-中——三件套：槽位标注（源侧五件套逐件改造，逐件渐进）+值文件 schema（键空间设计，建议 co./proj. 前缀空间防两维度冲突）+渲染断言（全覆盖+残留扫描）。契约白名单硬编码随断言一并落。
3. **风险清单**: ①契约稀释（防线=白名单硬编码，非文档约定）②值不齐（防线=残留扫描门）③模板-值版本漂移（防线=全覆盖断言）④两维度键冲突（防线=前缀空间）⑤host×tenant 参数组合（防线=正交化，host=渲染目标/tenant=值来源互不感知）。
4. **分阶段建议**: **P1 试点**=3-5 个高频槽（公司名/正名/别名/阶段语境）单件先行验链路 → **P2 扩面**=岗位描述协作名单+项目维度槽 → **P3 多租户值管理**=真有第二部署用户时再启（不预付）。每阶段验收锚=残留扫描零命中+契约面零改动可证。
5. **不槽化边界**: 纪律条款/决策权柄/层契约/方法论语义/义务面职责五类白名单，管线硬编码强制；白名单增删走治理流程（非用户值文件可达）。
