## 二、评估维度分工

### CPO（产品面）
1. 用户可定制能力的**产品边界**：哪些值适合槽化（正名/别名/人格称呼/岗位描述/协作名单…），哪些不适合（纪律条款/决策权柄/护栏语义——槽化是否稀释契约刚性）。
2. 部署形态与用户价值：单租户改值 vs 多租户模板；两维度（公司级 TriCompany/项目级 TriMetaverse）定制深度差异；用户改值的操作成本预期。
3. 定制能力与既有治理链（源侧真源→渲染→发布拷贝）的产品化口径。

### CTO（技术面）
1. 槽机制设计代价：`{{slot}}` 语法+值文件 schema（含中文多值/嵌套引用/缺省回退）；与**现役渲染管线**（源侧→--host 渲染→双宿主位发布拷贝）的整合点——是管线加值注入层，还是源侧模板化，改造代价各多少。
2. 存量改造面：13 席×8 件套+registry 型 agent+BOD/Board 面的槽化覆盖范围与工作量级（席·窗）。
3. 风险清单：值文件缺失/槽名漂移/渲染失败 fail 方式（fail-closed vs 原样透出）；校验面（槽名与值键对表）；git 面影响（值文件与模板分离后的 diff 可读性）。
4. 分阶段建议：单席试点（COS 起步）vs 全套一步到位；回滚锚。
