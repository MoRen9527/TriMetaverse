## 条款 1·LG-041③ restore 工具族与 A2/A3 调用关系

## 条款 2·LG-056 对齐 job 与阶梯触发面交叉

**裁态: 采纳（阶梯优先+迁移链即停）+三条交叉细则（合流 v1.1 建议 §七）**

- **总则采纳**：迁移窗内故障，恢复阶梯优先、迁移链即停——法理=迁移非应急（对齐 SOP 既有「冲突即停」条款的同语义延伸到服务故障面）；LG-056 A1 判据「fetch+merge 不推」天然低危（只读+本地 merge，自身不构成阶梯触发源）。
- **细则 1（触发面限定）**：交叉面仅限「迁移动作所依赖的服务」——通知链（QQ SMTP/notify）、daemon restart、8712 面服务；此三者故障入阶梯。迁移 git 面自身故障（冲突/拒推）走对齐 SOP，**不走阶梯**（防阶梯吞并一切错误的框架泛化）。
- **细则 2（处置权）**：阶梯触发后按 §二/§三 原生走（A1 通报 P1/A2 值席判 P2/A3 BOD 裁 P3），迁移链无处置权只冻结留痕；恢复毕 P4 双签后，原迁移窗错过即**顺延次窗/人工窗补跑**，不挤占恢复后窗口（防「恢复完立刻补跑迁移」二次事故窗）。
- **细则 3（防环）**：对齐 job 与 watchdog 面解耦声明——watchdog（≤5min 复活）先于人工阶梯动作，迁移窗内 watchdog 复活成功则迁移链可在其 P1 通报后自评估续跑（探活双面制 T-健康确认为准），不必等到人工阶梯；细则 1 三服务之外的静默故障不入环。
