## 〇、总纲一句话

配置页的信息架构从「一张混杂卡」纠偏为「**角色清晰、机位明确、卡如其名**」的四域面卡体系：每张卡回答三个问题——**这个域面控制器从哪拉配置、现在用的什么、健不健康**；页面分层是总览层（现在什么状态）→操作层（四卡各管各域）→参照层（策略卡只读+CLI 对照），不再混层。「要做产品不做玩具」在本件落为三条硬标准：卡名与数据真身一致（名实相符）、降级态如实显示不造假（诚实三态）、页面能做的心智 CLI 也能做（能力对齐）。

## 一、四域面角色矩阵（要素①）

## 二、TriMMC 卡纠偏语义＋河源侧配置入口归卡（要素②；v3 重定）

### 2.1 现役错误的三层解剖（CEO 纠偏令的产品面展开）

1. **名实不符（根因）**：现役 `TriModel/trimmc-card.json` 域锚=`TABLET-0BGCRCP5`（本机）、connection=「本机」——**它从来不是 sg TriMMC 的卡**，是 TriModel 服务端本机实例的策略卡（LG-035 卡 v4 本体：模型集/规则/策略/活动策略）。UI 却标着「TriMMC 信息」——卡名借了控制器名，数据真身是另一台机器另一个域的东西。
2. **混层**：该 section 同时承载策略面（LG-035：模型集/规则/策略）＋机器信息＋曾被挂入的连接配置——策略卡、控制器卡、连接配置三种心智挤在一个区块。
3. **错挂**：河源侧 TriRMC 域面配置因「页面只有一个卡编辑面」被挂进此卡——面错（M≠R，两者同属服务域故域不显错，更具迷惑性）＋机位错（sg≠河源）双重错位。

### 2.2 纠偏三裁定

1. **「TriMMC 信息」更名归位**：该 section 更名**「TriModel 策略卡（本机过渡位实例）」**，IA 中归参照层、常态只读＋状态显示，标注 LG-035 边界（编辑只对 CEO 测试窗开放；pending 卡等策略状态在此如实显示）。**更名属 UI 文案层不触数据/逻辑**，但该面系走查走界面——更名候 CEO 走查窗顺带批或双件合审确认，不擅动（依赖标注，见 §七.1）。
2. **TriMMC 卡回归本职**：新建「TriMMC·sg」卡=sg 机位 M 服务域控制器的配置拉取面板，数据真身=TriModel 服务端 face 账（M2 修复后经 API 读）；**sg 三断链候修期间卡显示诚实降级态**（「候修中·M2 候修⑤在册」＋指向，禁显示假数据）——设计要求非阻塞项。
3. **河源侧配置入口=TriRMC·河源 卡本身（v3 重定，撤销 v2「TriRLC 域面拉取卡·河源实例」）**：河源机上的域面控制器=**TriRMC**（周迁移 cron 现役在河源即其证）——河源侧配置的卡就是四卡之一的 **TriRMC·河源**，不存在也不需要第五张实例卡（v1 虚构「本地卡」、v2 虚构「TriRLC 河源实例」同根因：把「TriRLC=R 面本地域角色」误推为「TriRLC 部署在 R 面机器上」；TriRLC 实际一直在本机 8711）。R-HY 旧 trimmc-card.json 错装配置经迁移线归 **rmc 卡**（与 §六 CTO 迁移线对表）。卡拉取语义与其他三卡完全同构：**从 TriModel 服务端远程拉取配置**；现役服务端与河源 TriRMC 同机部署（R-HY 3333）系过渡形态，迁独立服务器后该卡只换拉取端点，卡语义零变化。**跨机 UI 不假装能编辑他机消费域的卡**（域锚四元组跨机互解不开=任务书 §五第一约束的产品面表达：配置写入动作必须发生在数据真身域内——此为物理约束，与「本地/远程」概念无关）。

### 2.3 卡实例化规则（防复发，产品铁律）

新卡入页走「**角色·机位**」实例化规则，不新发明卡型。规则用法两步（v3 按二次纠偏补正）：**第一步看机位上现役的域面控制器是谁**（河源机=TriRMC），**第二步按其角色归卡**——而非按「角色的面归属」猜测部署位（**角色归属面≠部署位**：TriRLC 属 R 面但部署在本机 dev 机）。同角色新机位=同角色卡下新实例（如未来 TriRLC 分部署到独立本地 PC 后，原 dev 机寄居实例随迁，卡名换机位后缀、角色不变）。**寄居过渡注记**：TriMLC（8713）与 TriRLC（8711）现同寄居 dev 机系条件所限的过渡形态，未来两者分开部署到不同的本地 PC——卡的「角色·机位」结构天然支持此迁移（机位后缀随部署位更新，卡语义零变化）。**卡特有项禁跨卡复制**——「TriMMC 卡管河源」这类错误的制度性防线就是：卡的一切区块必须能通过矩阵三问溯源到同一（角色，机位）。

## 四、配置页 IA 方案（要素④）

### 4.1 目标形态：左侧选项卡菜单＋右侧单页配置

**左菜单（导航层）**，自上而下：
1. 「当前生效」总览（默认选中——四域面一行一卡的健康摘要，答「现在系统在用什么配置」）
2. 四角色卡：TriMLC·本机／TriRLC·本机／TriMMC·sg／TriRMC·河源
3. TriModel 策略卡（标注「LG-035 面·常态只读」）
4. 连接配置（fb-zone，过渡期保留；本机栏并入 TriMLC 卡后此入口收敛为 sg 栏+帮助，终态随 M2 消化）

**右单页（操作层）**：选中卡的单页配置，区块顺序=一致面八项序，特有项追加其后——右侧永远是「一卡一页看全」，不嵌套二级页。

**参照层**：策略卡页＋各卡 CLI 对照行——页面与命令族互为映照，学一套用两处。

### 4.2 单卡形态论证（charter 要求：含不改的论证）

菜单解决的是「卡多了找不到」；**卡≤3 个有实数据时菜单收益小于成本**，三情形保留现单页滚动形态：
1. **单卡实数据期**（现役：仅本机两卡+策略卡有真数据）：菜单自动折叠为顶部细条（不占宽），页面仍单页滚动——菜单是渐进增强非前置条件，随卡实例化自动展开。
2. **CEO 走查窗冻结期**：LG-035 走查面（策略卡编辑流）页内布局零改动，菜单仅外层挂锚点零位移——防走查基线漂移（UI spec 必附实现态走查教训同源）。
3. **窄屏极简态**：菜单收为顶部横滑 chip 条，右单页纵向堆叠不变——右侧单页是主体承诺，双栏是宽屏增强。

### 4.3 分层原则（混层根因的制度化防线）

**每层一个心智**：总览层答状态、操作层管变更、参照层供对照。任何新功能入页先问进哪层——答不出=设计没完成（矩阵三问的 IA 面）。现役「TriMMC 信息」混杂三心智=混层根因，本方案即解。

## 六、白皮书对表记录（义务项）

1. **TriModel 定位**：组件层 Provider/Model 配置、服务域 L0 基础设施（模型路由与 token 中转）（§3.3 词条 L1324／§3.3.1 L312/L1191）——本件四卡=该配置中枢向两面两域四个消费角色发放配置的产品面，定位一致无冲突。

3. **M/R 语义矩阵**（LG-031 定谳，L191）：四格=远端 M（TriMMC 治理决策面）／远端 R（TriRMC 执行自治+周迁移）／本地 R（TriRLC）／本地 M（TriMLC）——四角色卡的特有项设计直接承接各格语义（TriMMC 卡治理关联行、TriRMC 卡周迁移关联行即出于此）。
4. **读法约定**（L1323）：TriModel（组件层）≠TriMLC（系统层）——本件卡名用控制器正名，策略卡用 TriModel 正名，名实相符原则与白皮书词条约定同构。
