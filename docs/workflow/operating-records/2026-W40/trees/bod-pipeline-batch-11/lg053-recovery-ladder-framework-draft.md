## 一、故障分级（探活三态）

| 态 | 判据（探针） | 例证（本域实证） |
|----|------------|----------------|
| T-健康 | 探活端点响应+功能探针通过 | 8712 healthz ok+cron jobs 响应 |
| T-1 服务暂不可用 | 进程在/端口听但功能面拒（503 族）——重试可愈 | recovery-ladder 偏-2：503=重试态 |
| T-2 写面未启用 | 服务在但开关/通道未启（401 配置族/端口迁移族）——重试不可愈，须开开关/走命令通道 | 偏-2 写面子型；0930 8710→8712 迁移窗 |
| T-3 进程/端口亡（含混合态） | 无监听+进程亡；**混合态单列候裁**=进程活端口死 | E-0011：8710 失听（进程活端口死实证） |

探活双面制：healthz（进程面）+功能探针（业务面）两探皆判，防「进程活功能死」假健康（E-0011 实证形态）。

## 二、自愈动作阶梯（重启→重装→回退）

- A1 重启：T-3/T-1 首选——systemctl restart（root 通道）或应用层 token 门 shutdown（watchdog 形）；时限=重启后 5min 探活回归
- A2 重装/重建：重启×2 无效→配置重建/版本重部署（dist 重建/卡重建，照 STE slug 先例与 LG-041 ③ restore 工具族）
- A3 回退：A2 无效→回退锚（配置 bak 链+git revert 点+**端口/宿主拓扑回退维度**——8710 退役案教训）
- 阶梯纪律：逐级触发留痕（读数+耗时+结果入 execution log）；A2/A3 前置=回滚锚 declared（双方先行，照 M2 链纪律）
