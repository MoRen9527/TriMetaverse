## 一、方案总图（一体两翼）

**探测翼（机器面）管「断了知不知道」，班次翼（制度面）管「谁接告警、谁响应、谁兜底」**——单翼不成网：无探测则静默不可见（今日 10 小时盲区实证），无班次则告警无主（催办单点依赖随 COS 会话挂起双失效实证，CHO 卷 ca6fc723）。

```
[定时 900s] → [在办账查在办单] → [COO 排序列取最优先树] → [三源 idle 判定+waiting 语义检查]
     → [15min 提醒级入账 / 30min idle 升级] → [notify 信箱面] → [值班 COS 消费转发 pipe 直达] → [离值二跳兜底 BOD]
     └──────────────── 探测翼（CTO 架构+CPO 语义）────────────────┘   └────── 班次翼（本卷 §四）──────┘
```

## 二、探测翼成文（CTO 架构 × CPO 语义，零分歧折算）

1. **架构**：共享基建层+独立 job（CTO §三）——底座=8713 cron spawn 容器现役形态；共享件=发信函数库（notify 信箱面统一出口）/树账读取库（node-status.jsonl+在办账解析，覆盖三源读取零新增件）/allowlist 统一管理；job 分层=tree-node-patrol 60s（现役）/watchlist 300s/静默探测 **900s 级新 job**（语义级不需高频）；
2. **idle 判据=三源 OR 豁免**（CPO §7.1 采认 CTO 组合信号+扩一源）：树账两源（node-status 尾行时戳+树 git log 尾 commit）+承办席会话 transcript mtime 一面（防「席在干活未落盘」误报）；**任一源活动即 active，三源齐静默才进 waiting 语义检查**；evidence 件 mtime 归树账族辅助源；
3. **阈值定值对**（CPO §7.4 联审定值）：检查节奏=活动窗口=**900s（15min）合一**；**1 轮齐静默（15min）=提醒级**自动轻触入账（fade-008 实锚）；**2 轮齐静默且无 waiting 理由（30min）=idle 升级**→COS 语义确认→三选一催办；
4. **通道=案 a**（CTO §三.5 建议+CPO §7.3 认）：判定在 daemon、发信走 notify 信箱面+值守 COS 消费转发 pipe（单点换手，零新增通道形态）；**pipe 桥（daemon 直写会话 uds）未验证，候真验证另案，本方案不作可用假定**；留痕双点=信箱入站即入 `nudge` 事件+值守转发达成补 status（单点换手不丢审计）；冷却期=每节点每 idle 轮（观察窗 2 检查轮）一封，900s 下最快 30min 一封；
5. **误报分界**（CPO §7.3 确认）：CTO 三钉（锚核查失败出声/发信失败不置已通知/解析失败不崩）=器自身可靠性；语义豁免面=waiting 挂账/长思考并入三源/深夜候晨 waiting 吸收/冷却期——零重叠；
6. **前置改造（候 COS 评估排窗，CTO §五建议尽早）**：在办账结构化入仓——**②③共享同一前置**（一个改造服务守望 sg 版+静默探测两能力）；载体倾向**独立在办账文件**（CTO v2.1：候办 watchlist 语义=候销账项、在办账语义=执行中，两状态机生命周期不同别混一文件；CPO 语义同向认），最终落点归 COO/CTO 商定；排序权威锁死=**COO 最新排序裁＞时间序最老＞缺序升级 COS 补序**（CPO §7.2）；
7. **与 fade-008 超时催办器关系**：一套两级同账异阈值（CPO §五），不另起炉灶。

## 四、班次翼成文（CAO 班次节卷折算+告警消费衔接·本席成卷域）

1. **值守角色**：值席位=COS 面常设班次（通信正名 m-duty-cos，单席值）；兜席位=BOD（值席缺位/无响应升级承接）；值席三责=告警响应/催办断面/应急通道，三不=不代工/不裁内容面/不动正身；
2. **班段（滚动循环两段制，CEO 23:24 口径）**：黄金段 18:00→次日 14:00 共 20h=值席全责段（告警响应+催办巡检；sg 侧 0:00-9:00 子段夜航形态照现役值席批次惯例）；禁窗段 14:00-18:00 共 4h=减配**不空窗**（只保留告警响应，催办巡检免——探测 900s job 照跑不随班段停）；
3. **告警消费衔接（CPO 留白归本席，即班次翼对接探测翼的合同面）**：
   - **消费时窗**：idle 升级告警 7×24 进值席位信箱（nudge 事件）——两段都消费，禁窗段消费动作=只转发不停；值班表按周入 operating-records 周索引件（零新工具）；
   - **值席响应动作链**：收 idle 升级告警→①核对该席在办单（在办账读）→②语义确认（有无 waiting 理由：waiting 挂账/深夜候晨/冷却期内=吸收入账不催）→③无豁免理由即转发催办信直达承办席 pipe（三选一动作要求照 CPO 判据③）→④承办席无复超 D-34/D-27 时限档→升级 BOD；
   - **离值兜底（二跳）**：值席位自身静默（值班 COS 无响应）=探测第二跳对象直告 BOD——值守断链的最后一网；
   - **留痕闭环**：信箱入站 nudge+转发达成 status 双点（CPO §7.3），值席处置摘要随周索引留痕。
4. **排班载体与试运行**：值班表=COS 汇总周排（周索引件）；首周=试排观察期，班段密度参数候两周读数校准。
