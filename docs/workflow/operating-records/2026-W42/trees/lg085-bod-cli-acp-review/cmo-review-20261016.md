## 〇·总判断先行

**定性纠轴**：此移动端是**单用户（CEO/BOD）内部管控台，不是消费产品**——评估轴=入口可达性×迭代速度×合规链×安全绑定强度×告警推送可靠性五轴；市场容量、分发增长、商店曝光等消费产品轴全部不适用。以此轴看四形态：

1. **「直上小程序主攻」产品面成立，但附三前提**：①企业主体（营业执照）在位；②境内中转节点+备案域名（解 CLI 部署 M-SG 与小程序备案门的结构冲突）；③接受每版平台审核的迭代摩擦。三前提的本质：**小程序把「境内合规链」设为平台门**——这不是缺点而是平台属性，选它=隐含承诺走完这条链。
2. **PWA 保留面=建议保留**（本席对「候评估面意见」的直接回答）：角色=过渡先行形+小程序受阻兜底形双角色；与 CLI 聚合视图同源（web 面），**增量开发成本≈零**；iOS 16.4+ 主屏推送已实锚，推送短板不再是一票否决。
3. **TG=备援/工程验证形**：产品面硬伤单一但致命——大陆直连不可达，代理通道成为 BOD 可用性单点；通道稳定则它是最快上线形（零审核零认证）。
4. **自研 APP=建议「不启动·远期重评」**：单用户内部台场景下双端开发+商店/签名+软著+备案链的成本收益比四形态最差；远期若 BOD CLI 面产品化对外，那是新的产品决策（归 CPO 面 PRD，不在本卷）。
5. **补位候选（CTO 轻形清单原有，本席建议保留在桌）**：企业微信自建应用——备案门槛与小程序同级（且主体校验更严）但**省每版审核**，且企微应用消息是微信生态内最可靠的告警推送面（§一⑤）——与小程序组合成「企微管告警+小程序管操作」是本席建议的目标形态。

## 三·合规+认证成本面（候 CFO 裁②并入）

**主体决策树（首要分叉）**：
- 有营业执照（企业主体）→ 小程序企业认证 300 元/年，类目全开，web-view 可用——**主攻路径畅通**；企微自建应用亦可开（可信域名主体一致校验可满足）。
- 无营业执照（个人主体）→ 小程序可个人注册（工具类目够用），但无 web-view、无认证、类目少；**企微自建应用主体校验难过**——主攻路径降级为「可用但受限」，告警旁挂面改走 PWA Web Push。
- **本司主体在位状态本席不掌握→待 CFO/公司面确认（本卷头号待验证项）**。

**现金成本表（估算口径，量级供裁非报价）**：

| 项 | 小程序路径 | TG 路径 | PWA 路径 | 自研 APP 路径 |
|---|---|---|---|---|
| 平台认证 | 300 元/年（企业） | 0 | 0 | Apple 99 USD/年+Android 软著数百-千元级 |
| 域名+备案 | 域名约 60 元/年+备案免费 | 不需（沿用 M-SG） | 不需（沿用 M-SG） | 若境内分发/服务则备案链同小程序 |
| 境内中转节点 | **需**——境内轻量 VPS 约 600-3600 元/年 | 不需 | 不需（境外直连） | 同小程序（若境内） |
| 开发工时 | 中（独立 UI 重写） | 低（web 复用） | **最低（CLI 视图同源）** | 高（双端） |
| 一次性时间成本 | 备案链 1-4 周（可与开发并行） | ≈0 | ≈0 | 软著/签名/审核数周 |

**结构性结论**：选小程序主攻的**真实成本大头不是钱（千元级/年），是「境内中转节点」这一新增架构件+备案链流程时间**——中转节点本身是新增安全暴露面（CTO 安全五条的适用对象从 CLI 扩到中转层），建议 CFO 裁②将「中转 VPS+域名+认证」三项合并估价，CTO 面同步把中转层纳入安全底线适用域。

## 四·安全面意见（对照 CTO 五条+市场侧增补）

1. **五条全形态适用**（只读先行/白名单动作/token 门/审计/速率告警——CTO 卷 §二③原文）：客户端形态改变的是**绑定强度与平台门**，不改变 CLI HTTPS 暴露面本质；小程序路径下安全底线适用域**扩至境内中转层**（中转只做反代不改包，日志入审计面）。
2. 小程序安全加分项=**平台级身份绑定**：openid↔CEO 一对一（CTO 五条第②条）在小程序形态下由 code2session 服务端换号承载，无自建账密面，比 PWA/TG 的纯 token 绑定强一档。
3. **市场侧增补两条**：
   - **告警通道分离原则**：操作面（小程序）与告警面分离——告警走「企微应用消息+PWA Web Push」双通道互备（小程序原生订阅消息工具类目不可靠，§一④），告警通道不承载写操作。
   - **开发态纪律**：小程序「不校验合法域名」仅限开发/体验版调试——正式版强制白名单是平台附加检查面（弱加分，非安全依赖，不得作为安全设计输入）。

## 五·信号→假设→验证建议（P2 前置验证清单）

- **信号**：CEO 主攻小程序（微信生态触达最强）+CTO 轻形先行建议（迭代最快）——两倾向各有依据，张力点=合规链。
- **假设**：H1 主体在位则小程序三前提一周内可全部落实；H2 CLI web 视图改造成 PWA 后可覆盖「手机随时看」90% 诉求（CTO 卷风险 6 同口径）；H3 企微应用消息+PWA 双通道告警可靠性与延时满足 BOD 24h 在线体验。
- **验证建议（低成本先行，全部不阻塞 P0/P1）**：
  1. 主体确认（CFO/公司面，一天级）——决策树根节点；
  2. PWA 零成本试：CLI P0 聚合视图出来后直接 Safari 添加主屏，CEO 48h 真实使用取可用性读数（零开发增量）；
  3. TG 可达性实测：CEO 设备一周体验记录通道稳定率（TG 候选的去留判据）；
  4. 备案链并行启动窗口：若裁③维持小程序主攻，备案（小程序+域名）即时启动——它是全链最长纯等待件，**可与 P0/P1 并行不占关键路径**；
  5. 小程序原型延后至 P2 窗（一至两周级），UI 独立开发的工时实测取数供 CFO 复核。

## 风险与升级

1. 主体不在位（无营业执照）→ 小程序主攻降级受限形 → 升级 CFO/CEO（主体补办 vs 改道 PWA 先行的决策）。
2. 备案链卡时（通管局超期/驳回）→ P2 小程序窗顺延 → 兜底=PWA 过渡形顶上（本卷建议其保留的核心理由）。
3. 个人 30 元认证档、7 天存储豁免细节两处中置信 → 以官方开通页/WebKit 原文复核为准，不作为决策依赖。

## 大白话摘要（呈 BOD/CEO 面）

我们比较了手机上用四种方式操作公司控制台：微信小程序、Telegram、自己做个 App、网页快捷方式（PWA）。结论：**小程序当主力可以干**，但要先办三件事——公司营业执照能用来认证、在国内加一台中转服务器并完成域名备案、接受微信每次更新都要审核。**网页快捷方式建议保留**，因为它几乎零成本、能立刻用，小程序卡住时顶上。Telegram 当备份（国内要翻墙，不稳）。**自己开发 App 不建议启动**——就给董事长一个人用，花双倍工时不值。另建议：审批提醒的推送别依赖小程序自带通知（它对工具类小程序限制大），用企业微信消息+网页推送双保险。要花的钱不多（一年千元级），主要成本是备案等 1-4 周的中转服务器流程，可以和开发并行不耽误工期。
