## 结论（先行·四句）

1. **定位：内部底座（now）→产品内嵌内核件（中期·随本地域安装体分发），不做独立对外 SKU**——无信号支持独立件。
2. **位次：不插当前主线**——dsh 基线读数在前（对比参照系），TriModel 前置已满足，DEM-006 是 agent-core 评估的供料件；迁移评估=P3（与 CTO 双案 A 对齐）候实测读数。
3. **MVP：首版=非人格常驻管理面**（催办/巡检/节拍 job 常驻化——DEM-006 即首个实锚），人格类不切首版。
4. **范式：不打乱**——「运营件归消费侧自持」不仅未被迁移威胁，反升格为**准入判据**（≥2 面消费才进包）。

## ① 产品面定位（内部底座 or 对外件）

**判：内部底座，中期演进为产品内嵌内核件，不做独立对外产品。** 溯源：白皮书 L121 已将 agent-core 写入元现实层叙事（「共用自研内核 agent-core：会话、调度、权限、cron、进程监督与审计由自研代码掌控」）——但叙事位是**内核件**非独立产品件。对外独立件四判据逐一不满足：无独立交付形态（四面 `file:` 同源依赖·随 daemon 发行版走·背景卷 9.5）、无外部需求信号、无版本化发布面（改包四面立受·9.5）、维护承诺未单列。**中期位**：白皮书本地域安装体（Win/macOS/iPhone/Android 多端·L108）终局需要终端 AI Worker 运行时内核——agent-core（会话/调度/权限/监督）正是安装体内核候选，演进路径=file: 依赖→版本化发布→随安装体分发。**一句话：它是 TriMetaverse 产品架构的承重件，不是货架上的单独 SKU。**

## ③ MVP 划线（若推进）

**首版最小面=非人格常驻管理面：催办/巡检/节拍类 job 的常驻化**——这条线已在发生（BOD 转报链/催办定时器=bod-tick 系·工单命题 2「已发生」自认），DEM-006 落地即首个制度化实锚。**人格类不切首版**：人格承载=五件套/soul/colleagues/social 四层+宿主 binding，迁移=人格承载形态变更，工具链缺口大（agent-core tools 118 行 vs claude code 全家桶·背景卷 §三）而人格类施工力需求高；且 RMC soul-loader 已预留人格装载位（背景卷 9.1 彩蛋注）——终局位有预留，读数未到不预启用。**「人格类偏运营者」（COS/COO 例行巡检面）首版只迁其机械面（job 触发层·scheduler 擅长短任务触发——背景卷 §六接法注），语义裁量留席面**——与 DEM-006「COS 只当大脑」同构。

**验收判据三条（机器可判）**：a) 常驻管理任务闭环率≥现役 harness 形（同任务对照）；b) token 成本读数优（idle 零 API+短任务免唤醒形态·背景卷 §二异①）；c) 零新增治理面（信箱/审计留痕/挂账台账形态不变——治理面变更须另批）。

## ④ 范式张力判（工单命题 5）

**不打乱，反而升格。** 背景卷 9.5 定谳：CEO 提议形态=现状已如此（共有功能→agent-core 包统一维护/特有功能→各 daemon 自持）；reaper 与启动补跑=「消费侧自持补回」的既有实例（§8.1 表）。产品面建议：把这条惯例**升格为准入判据**——「≥2 面消费才够格进 agent-core 包，单域特有运营件留消费侧自持」（9.5 候补治理条款采认）——分层范式从事实描述变为迁移闸门，评估工单命题 1 的「边界划哪」随之有机械答案。
