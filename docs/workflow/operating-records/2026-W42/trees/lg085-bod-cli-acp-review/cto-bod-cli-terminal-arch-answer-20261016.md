## 〇·一句话答案

**不需要两者齐备——消息发送终态=纯 daemon 面即可全通（零会话依赖）；BOD claude code 会话只服务判断力环节（审阅/裁决/拟稿），触发式存在，不是消息通路的必要件。**

## 一·双路现役事实（答非推演·现役通路实证）

本地域 agent 与跨域 daemon 的消息通路现役各两条：

| 通路 | 依赖 | 实证 |
| --- | --- | --- |
| **daemon 信箱**（TriMLC 8713 notify mailbox·POST API） | **只需 daemon 活** | 席位不活消息照存（复活补读·D-52）；hub-watch 告警=纯脚本→8712→outbox→8713 全程零会话参与（LG-082 现役） |
| 会话直发（uds pipe·SendMessage 形） | **两端会话都活** | 本席跨席消息现役即此形——低时延但活体约束 |

跨域 daemon 消息：CLI→本域 daemon（8713）→outbox 三态→跨域转发→目标域 daemon（8712/8710）——**纯 daemon 链，BOD 会话零参与**（现役 outbox 实证）。

## 二·逐问作答

**(a) 对所有本地域 agent 的消息发送**：CLI→8713 信箱 API 投递→目标席信箱→活体即收/不活复活补读——**只需 daemon，无需 BOD 会话**。会话直发（uds）可作 CLI 聚合视图的低时延增强（可选旁路），非主干依赖。

**(b) 对其他三域 daemon 的消息发送**：CLI→8713→outbox→跨域转发——**纯 daemon 链，BOD 会话完全不需要**。

**裁剪空间**：
- **纯 daemon 面（最小可达形态）**：CLI 作 daemon fat client（HTTP+token 门）——(a)+(b) 全通，BOD claude code 会话依赖=**0**。此即评审卷 P0/P1 形态（已批）。
- **纯会话面**：本地 agent 直发可行（uds）但跨域 daemon 消息不通（仍要借 daemon HTTP 面）+会话不活即全断（无异步存续）——**形态残缺，不作选项**。
- **终态推荐形（已批分层的自然延伸）**：CLI=双面聚合——daemon 面为消息主干（7×24 异步可靠）+ACP 会话面为判断力增强（触发式）。

## 三·两组件各自承载（与已批 ACP 分层对表）

| 组件 | 承载面 | 在消息发送中的角色 |
| --- | --- | --- |
| 本地域 daemon（TriMLC 8713） | **状态与消息面**（信箱/outbox/快照/审批队列+①层规则判） | **消息发送的唯一必要件**——存续+路由+异步 |
| BOD claude code 会话（经 ACP 由 CLI 驱动） | **会话控制面**（判断力·③层语义：审阅/裁决/拟稿） | 非必要件——「要发什么、发得对不对」的判断环节触发式参与 |

已批分层原话对表：ACP 管「BOD 判断力怎么被驱动」，HTTP 面管「状态在哪读、动作往哪写」——**消息发送属后者，纯 daemon 达成；BOD 会话=判断力插件，不是通路件**。

## 四·架构结论（P0 不受影响·终态更简）

CEO 疑问指向的「双件齐备」形态不存在——终态比直觉更简：**CLI+daemon 两件即可完成全部消息发送**；第三件（BOD 会话）只在 BOD 本人要用判断力时被 CLI 经 ACP 触发（审批/裁决/拟稿——LG-085 P1/P3 面）。P0（只读镜像）维持搁置候本答卷，裁后即可排（形态零变更）。
