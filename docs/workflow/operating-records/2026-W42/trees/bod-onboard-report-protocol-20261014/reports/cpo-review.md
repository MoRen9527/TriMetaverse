## 摘要（大白话）

总判：**报到制方向对，方案可立**——它把「上线恢复」从隐含状态补偿升级为显式事件注册，与 10-10 联审第五面「事件触发为主+机械兜底」的融合裁同构，是同一家产品哲学。四条主要意见：①链路五步顺、零多余环节，但须补「报到回执」与「重复报到幂等」两个闭环件；②泛化适用判定建议写成一条判据式（有无五件套生命周期承载），13 员工席不入报到制，名单边界由此自然导出；③与原三案关系=部分保留（报到制为主正身、daemon 机械兜底降级候补——两案覆盖区互补不重叠）；④正身落点=两者并职责分面（行为正身在 source-agents 合同面、纪律条款在 D 册）+清单正本文档化（防「报到制自身也重启即失」的自我指涉漏洞）。

## 一、席侧审点①：流程合理性（上线→报到→领单→自检→恢复）

**判：链路成立，五步无多余环节，但有两个闭环缺口须补。**

- **为什么报到制是对的（产品机理）**：原三案解决「cron 失了怎么补」——状态补偿；报到制解决「上线这个事件必须显式注册」——事件驱动。事件驱动优于状态补偿：不需要猜测「什么状态算丢了」，agent 自己知道「我刚复活」。这与本席现役先例完全同构——10-10 联审第五面：CEO §六事件触发四步为主形+晨间盘点兜底=融合裁。报到制（事件为主）+机械兜底（状态探测候补）=同一融合裁在 agent 生命周期域的复用。
- **报到与领单两步不可合并（回应「有无多余环节」）**：报到=「我在」信号，领单=「我该做什么」。解耦的收益=清单可独立演进（清单增删改不改动报到协议本身）——合并看似省一步，实则把清单版本焊死进报到协议，演进成本更高。此环节不多余。
- **闭环缺口一·报到回执**：链路第五步「恢复」之前应有「已领」确认——agent 领单后回执「已领+已验」，无回执=报到未完成。「已发≠在链」教训同族（硬门签认必落卷直达：会话中继=暗签）：报到消息发了不等于闭环，须有回执判据。建议：报到完成判据=CAO 应答+agent 回执双签，缺一即视为未完成（未完成≠未上线，见缺口二的幂等规则）。
- **闭环缺口二·重复报到幂等**：agent 重启复活后再次报到（非首次上线），CAO 需区分「新上线 vs 恢复态再报到」——否则清单重发、cron 重挂可能重复。建议清单内置幂等规则：同 agent 短窗重复报到→按恢复路径处理（只重发/核对差异，不从头建）。这是本会话现役实况的直接映射：BOD 四时点 cron 随会话重启反复「复活」，每次复活都走新上线路径=清单管理面会被噪声淹没。

## 二、席侧审点②：泛化产品面影响（13 员工常驻席 vs 非人格机构席区分）

**判：区分可以做到清晰，但泛化正身必须写显式适用判定条款，不能靠名单枚举。**

- **两类 agent 的本质差异（产品面判据）**：13 员工常驻席=有人格（soul 覆盖+五件套+宿主 binding profile），上线恢复由宿主拉起与 CHO 生命周期承载；非人格机构席（BOD/registry 型）=无人格，BOD 定位条款（2026-09-21 定谳）明文「非人格组织机构不具员工能力」——生命周期**无五件套承载**，这正是报到制要补的空档。
- **适用判定条款（本卷主建议）**：泛化正身落一条判据式——**「该 agent 的上线/恢复是否有既有机制承载：有五件套生命周期承载者不入报到制；无承载者入报到制」**。好处：a) 13 席天然出列（不重复登记，报到无意义——他们有宿主 binding 与 CHO 流程）；b) 新 agent 入列判定机械化（不用逐案问「算不算非人格」，问「有没有承载」即可）；c) 与 CHO 审点的「名单边界归属认定」互补：CHO+CTO 两席会签定类、判据式做推导依据，名单=推导结果而非人工维护表。
- **反例风险（为什么不能靠枚举）**：枚举名单会随 agent 增长漂移（registry 型 spawn 出新件、机构席扩编），漏更名单=报到制静默失效——与要治的「重启即失」同病。判据式自含，无此病。

## 三、共同审点 a：与原三案关系——建议部分保留

**裁法建议：报到制=主正身；daemon 机械兜底降级候补条保留；原三案其余两案（纪律条/载体行）被吸收退役。**

- **保留兜底的硬理由（覆盖区互补，非冗余）**：报到制依赖 agent 复活后**能主动行动**；若 agent 连「能行动」都未达成（spawn 风暴、宿主未拉起、进程崩溃在拉起前），报到根本不会发生——此静默死场景只有外部机械探测（8713 tick 陈旧催办）能覆盖。两案覆盖区：报到制管「复活但忘了重挂」，兜底管「根本没复活」，交集为零、并集=全谱。
- **投资姿态（降级非对等）**：兜底=候补可选非强制施工，不与报到制同批投资；候报到制实跑一段后按「静默死实际发生率」裁去留（发生率≈0 则退役，同 DEM-003「不投资过度」口径）。与 10-10 第五面裁法一致：8713 预派 job=短中期过渡形，终态零人工——机械兜底同理是保险不是常态链路。

## 四、共同审点 b：泛化正身落点——建议两者并、职责分面

**裁法建议：行为正身落 source-agents 合同面；纪律条款落 D 册；先立后破适用。**

- **分面理由**：报到行为是 agent 启动行为的一部分——离正身最近的落点=agent 自身合同件。board 侧建议落 **agent-body**（行为规范属行为面；contract=通信身份面，frontmatter=元数据——报到不是二者语义）。泛化版同理：通用件落 TriCompany 侧 source-agents 公共合同件。
- **D 册放什么**：不是重复行为描述，放**纪律定性**——「应报到未报到=运行纪律缺陷」的违认定性与追溯面，D-47（信面落款机械合同在席位侧、纪律在册面）同族分工：合同管怎么做，纪律管不做会怎样，双向引用不混写。
- **先立后破适用性**：适用。报到制是对「上线即默认恢复」隐含假设的显式化，不破坏任何现行 D 系条款；原三案存档保留（spec 件不删）即先立后破形态照旧。
- **清单权威位附议（涉 CAO 审点，本席产品面补一句）**：CEO 口谕③清单放 CAO 记忆+置前置核查提示——照做，但建议**正本文档化一份**（治理文档或 operating-records 面留正本，记忆只放指针+必做提示）。理由：CAO 记忆=运行腿（机器写入、复活时初始化）——若清单唯一正本在记忆里，清单自身也成为「重启即失」的受害者，报到制出现自我指涉漏洞（负责补挂的清单自己会被挂丢）。

## 五、共同审点 c：CAO 不可用兜底——建议三态降级链

**裁法建议：报到留痕不阻塞 + 超时升级 + 回退承接人，三态。**

1. **报到=异步留痕**：agent 发出报到消息即完成己方义务，不阻塞上线——CAO 恢复后补发工作清单。理由：若「CAO 必须应答才算上线」=把 CAO 变成全体非人格 agent 的上线单点闸，单点故障面反而大于原问题。
2. **无应答超时升级**：报到后无 CAO 应答超容差窗（建议 30-60min 级，具体值联审定）→自动升级 BOD。与 10-10 第五面「窗偏超容忍度自动升级链」同构（触发 owner→COO→BOD）。
3. **CAO 持续不可用**：承接人回退 COS（路由中枢既有定位）——COS 凭清单正本文档（见 §四权威位附议）临时派工，CAO 复位后交还。正本文档化是此态成立的前提，再次互证 §四附议。

## 六、结论

**方案可立（APPROVE 方向），建议 CEO 终审稿吸收四条**：

| # | 意见 | 建议裁法 |
| --- | --- | --- |
| 1 | 报到闭环补两件 | 回执双签判据（CAO 应答+agent 回执）+重复报到幂等规则（恢复路径不重建） |
| 2 | 泛化适用判定条款 | 判据式=有无五件套生命周期承载（有承载不入、无承载入）；名单=推导结果非维护表 |
| 3 | 与原三案关系 | 部分保留：报到制主正身+daemon 兜底降级候补（静默死发生率实证后裁去留）+纪律条/载体行被吸收退役 |
| 4 | 正身落点+清单权威位 | 两者并（行为正身=agent-body 系合同件、纪律定性=D 册、先立后破适用）+清单正本文档化（记忆只放指针+必做提示） |
| 5 | CAO 不可用兜底 | 三态降级链：异步留痕不阻塞→超时升级 BOD→回退 COS 承接 |
