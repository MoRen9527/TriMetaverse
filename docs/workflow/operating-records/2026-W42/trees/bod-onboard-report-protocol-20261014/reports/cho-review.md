## 一、侧重①：与岗位启用/五件套增量更新/handoff 流程的衔接

**总判：报到制不并入员工生命周期节点——并列两条线，一处指针互认，一处命名钉死。**

1. **不并入的理由（隔离面）**：员工生命周期（入职/试岗/转正/退役/五件套增量/roster 变更）管**人格席身份**；报到制管**非人格实例运行**（上线时配置自恢复）。LG-075 N2 刚把 `family: Registry` 钉为隔离技术承载、body 条 8 刚落「board 无记忆层·连续性载体=树卷与 transcript」显式句——报到制若并入生命周期节点，等于给非人格 agent 变相配「入职」，**直接冲撞刚立的隔离面**。两者是同构不同域：入职 checklist（员工域）↔上线工作清单（registry 域）结构可互鉴，正身必须分立。
2. **非人格 agent 无 handoff 概念**：handoff=任职连续性移交（有人格前提）；非人格 agent 的连续性=配置面（cron job 定义）+树卷，重启后报到本质是**配置自恢复触发器**，不是身份事件。CHO 域 handoff checklist/completion tracking 不覆盖此物。
3. **衔接点一（CHO 侧指针）**：员工域真源（chief-human-resources-officer-handoff-governance.md）建议留一行指针：「非人格 agent 上线报到制见纪律册 D-XX（CAO 域）·不入员工生命周期」——防未来人事面误收。
4. **衔接点二（命名钉死）**：正身用词建议钉死「**上线报到**」词族，**禁用「入职/到岗/上岗」词族**——后三者是员工生命周期事件词，误用会触发 roster/五件套面联动误读（本席域实测教训：词族混用=边界混淆温床，同「席间分派 vs 席位分配」案）。
5. **衔接点三（泛化边界）**：13 员工常驻席**不入**报到制范围——人格席复活走各自 knowledge workspace/compass 复活面（如本席 boot 注入自恢复），已有各岗位 session-body 承载。报到制范围限非人格类，泛化时 CPO 审点「区分是否清晰」的答案=家族线（family: Registry vs 人格席 roster）即边界线，清晰无需新机制。

## 二、侧重②：「非人格类 agent」名单边界的归属认定

**总判：类定义推导制，不设逐个认定权——归属权问题消解为「类定义会签一次+清单运行维护」。**

1. **类定义已有权威面，无需新设认定机构**：非人格=无五件套家族（`family: Registry`）——这是五件套体系既有判定（13 席 roster=人格席全集，board+BusinessStrategy+CompanyGovernanceRegistry+各 registry agent=非人格集），LG-075 v4.0 合同 family 行就是技术承载。**类定义句建议两会签**：CHO 域定家族/隔离面（谁无五件套）、CTO 域定运行时面（谁有常驻会话实例+cron/daemon 依赖）——两会签一句定标准，此后不再逐个裁。
2. **类定义句正形建议**：「凡 `family: Registry`（无五件套）且有常驻会话运行时实例的 agent 属非人格类，纳入上线报到制；名单由 CAO 按此标准推导维护」——**清单=推导结果非认定结果**，CAO 作为报到制 owner 只做登记维护，新增 agent 上线按标准自动入范围。
3. **个案争议路由**：类标准判不了的边界个案（如未来半人格新形态、registry 家族新增成员存疑）→按归一裁决分级走：不涉岗位边界=BOD 裁；涉 roster/五件套结构=岗位边界变更，走 CHO 前置审核门（v4.0 precheck_gate 承接）呈 CEO 批。
4. **归属权落点汇总**：类定义=CHO+CTO 会签（一次）/名单维护=CAO（运行面）/个案争议=BOD 或经前置门 CEO 批（治理面）——三权分立零新增机构。

## 三、共同审点

**a. 与原三案关系：部分保留——报到制主道，案1 降级为备援条款，案2 被吸收，案3 保留候补。**

- **案2（前置核查载体行）被 CEO 方案第 3 条吸收**（「置于前置核查/项目路由位置提示必做」）——不再单独立案；
- **案3（8713 daemon tick 陈旧探测）保留候补**：覆盖「agent 连报到动作都无法执行」的静默死（复活失败/复活后首行动作前死）——报到制原理上覆盖不了此场景，机械兜底是唯一网底；可缓批（先跑报到制，静默死实际复发再激活）。

**b. 泛化正身落点：两者并——纪律册 D 系为规则正身+board 前置核查节一行指针；先立后破适用。**

- **报到制规范正身=纪律册新 D 条**（CAO 入册·唯一入册通道）——D-48 三分法判据：报到制是操作行为规范非权柄流程骨架，归纪律册不归合同；
- **board 侧落点（CEO 方案第 2 条「写进合适文件」）：建议 `agent-body.agent.md` 固定前置核查节一行**，**不进 contract**——理由：①报到约定是操作细则（D-48 三分法不进合同面）②board contract v4.0 昨日刚修订收敛（6e754f7），非骨架性新增不宜再动合同（防合同面膨胀回潮）③frontmatter 系场景描述面更不载操作。指针行正形：「上线报到：新会话上线先向 CAO 报到领上线工作（D-XX）」；
- **泛化到其他非人格 agent：同形指针化，逐个改合同**——各 registry agent 合同面不动，靠 CAO 报到清单+各前置核查指针覆盖（同 #7 面域清单降级的维护成本逻辑：通则+清单外置）；
- **先立后破适用**：原三案中现役条文（若案2 载体行已落前置核查节）迁出与 D 条入册同批，CAO 主笔双向一行指针。

**c. CAO 不可用兜底：三层递降——重试→自挂→机械催。**

1. **重试**：报到无应答 15min 窗重试一次（网络/忙态类瞬态）；
2. **自挂 fallback（案1 备援激活）**：仍无应答→照原规格存档自检自补（cron 缺即照规格表补挂）+报备一行——**报备对象建议 COS**（合账域·CAO 缺席时代收台账留痕），COS 亦不可用→BOD（催办中枢）；
3. **机械催（案3）**：连自挂都未发生（静默死）→8713 daemon 陈旧探测信箱落 letter——机械层网底，不依赖任何会话活性。
- 三层与 a 点「部分保留」自洽：主道（报到）+备援（自挂）+网底（机械催）——每层失效都有下接，无单点。
