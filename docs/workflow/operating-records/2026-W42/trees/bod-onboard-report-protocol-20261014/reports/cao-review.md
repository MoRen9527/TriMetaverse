# 非人格类 agent 上线报到制·CAO 联审意见（方案主责席）

## 一、总评与方案定性

**方向 CAO 赞成，无保留意见**。报到制优于原三案的核因=把恢复触发权从「复活体自觉」移到「生命周期起点」：原三案依赖复活体读正身提示后自觉自检自补（上下文污染时此环节最脆弱），报到制改为**义务外置+承接人核录**——复活体只需做一件最小事（发一行报到消息），挂什么、怎么挂由 CAO 清单承载，双保险结构。且天然泛化：任何非人格 agent 同律，无需逐席另立机制。

一个方案审关键判定：报到制的可靠性前提=「复活体知道该报到」必须落在**复活体必读面**——即正身文件（agent-body）经渲染发布的宿主位。复活体 boot 注入正身=知晓报到义务，链条闭合。此前提同时框定审点 b 的落件选择（见 §三 b）。

## 二、我席审点逐条意见

### ① 报到承接机制三落点——「清单=记忆，必做=前置核查，路由=session-body」三层分工

- **CAO 记忆（数据层）**：上线工作清单**本体**放 CAO memory 主题文件（建议名 `onboard-work-registry.md`），一行一 agent 型/席位。放记忆因=随角色扩展高频更新，记忆是活数据层；CEO 口谕「放入 CAO 的记忆」精确对应此层。
- **agent-body 固定前置核查节（动作层）**：加必做检查项「非人格 agent 报到队列检查」——我会话开场扫待承接报到，未承接即办。此层放**动作提示不放清单**。
- **session-body 中央收口路由节（方向层）**：加路由行「非人格 agent 上线报到→CAO 承接」——防其他席/agent 不知去处。此层放**方向指针不放清单**。
- **防双写**：三层不重复载同一内容——记忆载清单全文，前置核查与路由只放一行指针（指清单文件），与 D-48 一物一册一 owner 同构。

### ② 上线工作清单内容与维护责任

- **权威位**：清单文件本体=CAO memory（上）；清单的**执行内容真源**分层——如 board 四时点 cron 的重挂规格表（cron-rehook-spec 存档 §重挂规格）建议随纪律册新条作**附录表**升正身，清单行只持指针。防「清单说挂 cron 但 job 内容无从查」的悬空引用。
- **维护责任**：CAO 唯一写入面；CHO 岗位启用面联动——岗位启用登记时 CHO 标注「是否非人格型」，非人格型即触发 CAO 扩清单行；新增 agent 型时 CAO 会同该 agent 主责席扩行。
- **首批清单（现势三行）**：①board——挂四时点 cron 2 job（节拍转报 9,39＋信箱巡检 11,41，规格见存档表）+领单后自检在挂；②registry 型非常驻 spawn 类（CGR/BSR/TCR/TPR 等）——报到即录名址（D-13 对表 ListAgents）+五件套渲染发布态确认，**无 cron 需求**；③其余非人格席位现无——随启用扩行。

### ③ 报到消息格式与 CAO 回执形态

- **报到消息（agent→CAO）最小三要素**：正名（D-13 名址表内正名）＋上线形态（首启/常驻复活/临时 spawn）＋一句「请发上线工作清单」。一行消息，不设仪式。
- **CAO 回执三件**：①上线工作清单（具体动作+权威指针）②报到入账留痕——建议 operating records 当周树 `reports/onboard-log.md` 一行一条（时点/正名/形态/清单发放/领单确认），轻量不设独立台账 ③闭环三问随回执落实：谁 owner（该 agent）、记在哪（onboard-log 行）、何时回填（领单后自检结果一行）。
- **闭环四步**：报到→CAO 回执清单→agent 领单执行→自检回报一行。每步一行消息，无会议（禁形式主义：不为报到设会，不入秘书处会议机制）。
- **副产品联动**：报到时 CAO 顺手做名址核录（ListAgents 对表）——名址在册=报到自然产出，不另立流程。

### ④ 与现行机制域衔接

- **会议制度**：不涉（见上——消息面非会议面）。
- **治理文档归属/入册链**：制度条款正身=纪律册 D 系新条，CAO 主笔唯一通道（D-48 纯度三问过：报到义务+承接链+兜底=权柄流程骨架入册；清单明细=操作数据留 memory 不入册；案例归记忆）。
- **D-13 名址**：报到以正名为锚（上）。
- **D-48 先立后破**：原三案存档废止与新条入册同批（见 §三 a）。

## 三、四席共同审点

### a. 与原三案关系——**吸收式取代，非全废**

- 案 1（纪律条自检自补）＋案 2（载体行）：本质是「自检」环节，**被报到制吸收**——报到制闭环第五步「领单后自检在挂」即其变形；且 session-only cron 若会话未重启但 cron 失效，自检是唯一探测面，**建议保留自检句随报到制条款一并入册**（board 前置核查节载体位照旧）。
- 案 3（8713 daemon tick 陈旧探测催办）：**候补保留、不激活、不入正身**——报到制下「活着但不报到」已是最小概率场景（义务入正身+承接人核录双保险），机械兜底的真实增量覆盖面趋零；候实际发生一例再评估激活（YAGNI）。
- cron-rehook-spec 存档全文：历史冻结归档不动；其 §重挂规格表升纪律册条目附录（内容平移非新写）。

### b. 泛化正身落点——**两者并·先立后破适用**

- **纪律册 D 系新条**=通用行为规范正身（报到义务/承接链/兜底/清单指针/自检句），CAO 主笔；与原三案存档废止同批（先立后破）。
- **source-agents/board/ 落件建议=agent-body.agent.md**：报到是行为义务非权柄——不落 contract（decision_rights/forbidden 是权柄面，D-48 纯度不合）；frontmatter 只载触发场景，报到非触发场景。落点=agent-body「流转与记录规则」节（10-13 版已有 D-01 辨析+D-51 指针的指针结构现成）加一行报到义务句+纪律册条指针（D-16 指针两要素：目标面正名+真源路径）。
- **泛化节奏**：本批只立通用条款＋board 首例落实；其余非人格正身随各自修订窗逐件落——不在本联审批扩全司施工批。

### c. CAO 缺席兜底——**清单与承接人分离，无需新增机制**

- 原则：清单权威位=CAO memory **文件面**（非 CAO 会话内存），承接人缺席不阻塞清单获取。
- 兜底链三行：①报到无应答→agent 会话窗内间隔重发一次；②仍无应答→转 COS（管理层路由中枢既有正形），COS 读清单文件代发+台账留痕候 CAO 归位补回执；③双缺→候席位复活链（既有爆溃恢复 SOP 面），报到消息落收件箱持久候承接席恢复即达。
- 结论：**现有路由+消息机制全覆盖，兜底只须把这三行写进条款**，零新增机制建设。
