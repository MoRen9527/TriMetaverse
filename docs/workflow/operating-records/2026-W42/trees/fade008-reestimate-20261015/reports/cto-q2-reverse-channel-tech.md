## 〇·技术总判

**一期=拉模式（出向队列制）·零新隧道**——四类推场景全部经「服务域出向队列+本地 cron 拉取器」实现，端到端时效 5min 拉节律下≤10min 达 CPO 锚 1；急件抢占一期走现役人链不机械化。反向隧道（sg 直推本机）一期不做：本机无公网入站、反向隧道常驻+断线重连+入站暴露面三重成本，换来的只是急件时效——而急件一期人链够用。**「消息推材料拉」在传输层落地为「队列推节律拉」——语义是推（服务域出向队列=服务域单方写），机制是拉（本地按节律取），这正是无入站拓扑下推语义的标准实现形。**

## 一·拓扑定形（四通道落位）

| 通道 | 传输形 | 现役基座 | 一期动作 |
| --- | --- | --- | --- |
| M-local→M-service | 拉（现役） | 供料树+值席拾取（§八定形） | **零改** |
| M-service→M-local | **队列推+节律拉**（新增·主战场） | sg TriMMC notify outbox/mailbox/ledger 三件现役+本机 ssh 通道 | ①outbox 增「待取队列」语义 ②本机 TriMLC 拉取器 cron ③白名单补席 |
| R-local↔R-service | 同构复制 | TriRLC NOTIFY 出向（今晨启用·活体先例）+TriRMC 同族面 | 候 R 面流水线落位后对称复制（二期首项） |
| M↔R 跨面 | 不做直投 | — | 维持经 BOD 各 COS 流转（CPO 红线+现役纪律一致·零分歧） |

**M-service→M-local 数据流**：毕报/异常/回执产生→TriMMC 写入出向队列（含证据三元组）→本机 TriMLC 拉取器（cron 每 5min·ssh BatchMode+X-Internal-Token 鉴权·现役通道族）→GET 未取队列→写 TriMLC 信箱（advisory 标）→m-cos 消费→拉取确认（队列消账·防重复取）。

**失败形态**：拉取失败=下节律重试（幂等·队列消账确认制）——**零倒补零代登记**（§六锁定同构）；连续 N 节律失败→TriMLC 侧告警（notifyFailures 同族现役机制）。

## 二·白名单机制定形（红线②技术形）

1. **服务域出向端点白名单**：TriMMC 出向队列写入时校验目标端点∈配置白名单（env 结构化：`TRIMC_ECHO_TARGETS` 候名·一期单值=M-local 信箱端点）——白名单外写入=入队即拒+ledger 留痕。
2. **拉取方鉴权**：X-Internal-Token 现役机制复用（零新凭据·顺手轮换窗已候排）+拉取器身份登记（source_seat=`mc-echo-pull` 候名入 TriMLC 收箱白名单——SOURCE_SEAT_WHITELIST 同族·**P0-1 教训随行：改白名单须断言「改的目录=现役运行位」**）。
3. **拒收+审计留痕（验收锚 2 判法）**：白名单外/鉴权败=403+ledger reject 事件（现役 outbox-ledger.jsonl 扩事件型·零新机制）——负向探针案机器可判。
4. **白名单最小集验收锚**（CPO 红线②）：一期出向白名单=1 端点、收箱白名单增=1 席——两数值写死验收卷。

## 三·安全定形（红线①③④技术形）

- **红线①只推消息不推文件**：载荷 schema 硬约束——消息体≤8KB+字段白名单（三元组+text+指针字段·**无 file/binary 传输字段**）——schema 校验在服务域入队侧+本地落箱侧双层执行；文件一律共享位路径指针（「指针是字符串不是文件」）。
- **红线③收推≠执行**：TriMLC 落箱信带 `advisory: true` 字段；结构性保证=信箱写入 API 与 cron/job 调度 API **零共享面**（现役 notify-inject 与 addJob 本就分离·登记为设计注记非新工程）——信箱条目对本地域纯待阅数据，无任何可触发执行的路由面。
- **红线④证据三元组**：`{source_id, ts_machine, ref}` 必填——缺元组入队即拒（服务域侧）+落箱侧二次校验标疑（防服务域 schema 演化破约）——**验收锚 3 判法=双闸负向探针**。
- **时戳纪律**：ts_machine=服务域机写（UTC Z·D-47 同源）；本地落箱补第二时戳（拉取时刻）——双时戳支撑锚 1 时效判定。

## 四·两处技术裁决点（候 CPO 会签·涉场景时效语义）

1. **毕报时效锚达成形**：锚 1「≤X 分钟（建议 10min）」——拉节律 5min 下端到端≤10min 技术上稳定成立（拉取<1min+落箱即时）；**若 CPO 场景面要求 <1min 级时效（回执双签场景 3 挂实时性）则拉模式不达**——回执场景一期建议降级为「回执随下节律达（≤10min·双签闭环延迟可预期化）」，<1min 实时回执=反向隧道候二期。**候裁：回执类 10min 级可接受否。**
2. **急件抢占一期形态**：推场景 4（急查/紧急回滚协调）一期**走现役人链**（BOD/COS 直连）不机械化——急的定义=等不起 5min 节律，一期为其建通道=反向隧道全成本；急件频次低+人链现役可用。**候裁：急件一期人链可接受否。**两裁均直接影响一期范围，会签后合一卷。
