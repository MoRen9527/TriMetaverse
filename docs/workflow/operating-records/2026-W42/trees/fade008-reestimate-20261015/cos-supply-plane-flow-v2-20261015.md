## 三、v2 备料面流程四段（COS 主负责）

### 段一·谁备料：本地域全体员工半自动+COS 主负责

- 备料=本地域全体员工半自动——各席各员工出料（缺陷/需求/改进想法/董事会令落域件·带初稿要素）；**COS 主负责人**=汇总→筛→铸→登记全链收口（料源三路沿 v1：本域台账+周平面未决项/董事会令/跨域流转来料）。
- 筛选判据沿现制三条（边界明/验收锚齐/无需 CEO 逐步拍板）+D-39 纯净性（候裁件不入任务书·留候裁面）。

### 段二·任务书怎么铸怎么登记：一等实体·周平面登记面

- **铸**：照 M2 任务书模板正形六段（TriCompany/docs/workflow/task-charter-template.md·今日换代承入 A1 正形）——树锚款按 v2 重解：任务书**不带树锚**（树=执行域拆树产物·Q2）·带**执行域栏**（M1 制度保留·TriMMC/TriRMC/本地域四枚举）。
- **登记**：周平面**任务书登记面**（任务书原始态集中登记·来源标注：董事会令/需求大表/其他）——人机共读格式（机器可拾取：执行域栏/门禁毕锚/时限结构化字段；人可读：目标/范围/护栏正文）。
- **台账挂行照旧**：一任务一状态条（M-001 五字段）——台账管账·登记面管书·执行域树管活。
- **三锚齐=备料毕（v2 重定义）**：任务书入登记面+台账挂行+（跨域件）供料单出。

### 段三·执行域拾取与拆树：一对多·n 树

- 执行域=两条流水线（M面TriMMC/R面TriRMC·值席全员·无 CEO 交互）——拾取任务书→**按任务书拆 n 个树**（一对多：一件任务书可拆多树·每树一文件夹·树协议七步链照 FADE-008 §3/§4+D-27 现行）。
- 树三属性（Q2 定调）：有序执行（节点序）/故障恢复（checkpoint·resumePoint）/可审计（brief+artifactCommit git SHA）——树全量落执行域周平面 trees/。
- 本地域短任务（§五 ≤30min 分流）不走流水线：本地域（TriMLC/TriRLC）域内直拾任务书·拆树照现行（本地域执行时树属性同样成立——树=执行域属性·本地域执行也立树）。

### 段四·回声与销账：任务书锚+树束指针

- 节点收口照 FADE 协议 §2.7 落**执行域树**（brief+checkpoint+artifactCommit git SHA+resumePoint）。
- 回声链：执行域毕报→对域 COS→跨面流转→**备料面 COS**（回址照供料单）。
- **销账合同（v2）**：备料面 COS 销台账必附**任务书锚+树束指针**（一件任务书对应 n 树·销账时逐树指针或树束索引）+执行域毕报锚——禁裸销（销账唯 COS·权界沿 ⑦ 改排）。
- 催办/督办：E1 制度（今晨会签生效）沿接——8713 cron 触发+文件面+M-004 双通道·job 只产催办读数不握权；双层双向催办沿 §8.10/D-27 v4。

## 四、跨域流转缝（保留·按一等实体重接）

- **供料单=任务书跨域流转的信封**（CEO 点名好设计·保留）——五素重接：①任务书指针（周平面登记面锚·**不复制正文**——正文一处登记·多域引用）②目标执行域标注（M面TriMMC/R面TriRMC·照 M2 执行域栏）③门禁/毕锚④止损/回滚锚⑤毕报链回址=备料面 COS 名址。
- 流转链不变（制度正形）：备料域 COS→BOD↔对域 COS→执行域流水线值席（BOD 待裁全域授权·不经 CEO·D-39）；daemon-to-daemon 直连候二期。
- 执行域收料正形：对域 COS 收供料单→任务书入执行域拾取队列（登记面同步或对域 COS 落执行域登记面）→值席拾取→拆 n 树→执行。

## 五、Q8 ≤30min 分流基线·备料面评估（CEO 建议基线·本席评估）

- **判定位（备料端 COS 铸任务书时一次判）**——判据三看：
  1. **预估工期**：>30min？——核心分流线；
  2. **交互需求**：要人确认/要 CEO/要本地环境（IDE/本机 daemon）=本地性权重高；
  3. **流水线适配**：纯施工（代码/部署/批处理·可异步可重试）=服务域性权重高。
- **转域时点**：**登记时一次判**（任务书执行域栏照 M2 制度落域·不走执行中二次转域）；误判回流=执行域毕报带回「本地交互缺口」锚→备料面 COS 改判重挂（重挂=登记面改执行域栏+台账注·原树由执行域收尾）。
- **30min 边界实操形态**：≤30min 短任务本地做（交互快回·免跨域流转开销）——执行域栏标本地域·TriMLC/TriRLC 域内直拾；>30min 转服务域=供料单随任务书流转（供料单成为**转域凭证**）。**估不准件默认转服务域**（流水线吞吐大·本地只留交互型短件——防本地积压）。
- **供料单怎么接**：≤30min 件不出供料单（域内直拾）；>30min 件必出——供料单数量=跨域件全量·可统计（周度供料读数：跨域件数/回流改判数·候 E1 督办读数单扩一项）。
