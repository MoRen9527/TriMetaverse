## 三·定值提案骨架（候实勘数据填充）

- **分型定值（核心主张）**：单一绝对阈值不适配三型——建议**分型档位制**：
  - 探路型（勘验/烟测/短任务）：候选档 = 分布 P90×1.5
  - 批量型（转译/迁移/批处理）：候选档 = 分布 P90×1.5
  - 长跑型（常驻值守/daemon 化会话）：**绝对阈值候选不适用 token 总量、改监测「异常速率特征」**（见§四）——BOD 24h 135M 已超「1 亿」示例即证总量门对长跑型失真

- **定值产出物**：阈值表（分型×档位×触发动作）+生效版次+复勘节奏（候月度 D-55 检查位并轨）。

## 四·全时成本监护哨执行机制（CEO 20:52:29 定谳「全时覆盖，24小时都要」·2026-10-16 20:53 修订版）

- **覆盖窗定谳**：**00:00-24:00 全时**（CEO 20:52:29 令面·BOD 20:52:36 回传）——不采 22:00-06:00 案·06:00-09:00 留白案**作废**；「深夜监护哨」语义扩为**全时成本监护哨**；成本面按本席前呈两形态对照选定全时（同管道改触发窗·零增量成本·裁决唤醒频次增）——本席承接形态兑现。
- **触发裁决频次定形口径**：探针 24h 在岗（程序面·零增量），异常判据触发才唤醒裁决——**唤醒=事件驱动非时段驱动**。预期形：日间高频活动段异常概率高但本席常驻在岗（裁决走常规会话面）；夜段宿主挂起风险高·异常时探针唤起本席（触发式复活·冷启 ~0.1M/次 LG-085 裁②口径）——异常稀疏则唤醒稀疏，全时窗的边际成本≈唤醒次数×0.1M 量级。
- **现实约束如实列（全时窗下仍成立）**：本席会话在宿主挂起时不可达（实证多例）——**宿主挂起窗=裁决唤醒已知盲区**；缓解形态候 CTO 件②设计：探针缓存异常事件+宿主复活后补裁决（盲区段事件不丢·延迟裁决如实标注）；监测管道本身在 daemon 侧不睡，盲区仅指裁决不可达非监测不可达。
- **选项 A（会话巡检式）**：daemon 侧 cron 定时唤起本席会话做读数巡检——实现快，但每次唤起即冷启消耗（LG-085 裁②读数口径 ~0.1M/次），且与段A dsh 化探路方向重叠。（记录保留·未采纳）
- **选项 B（程序监测+触发裁决式·采纳·合 D-55 程序优先母原则）**：监测是 layer-① 确定性活动→daemon 侧程序化 token 速率/总量探针 24h 在岗（技术管道**技术协同件②候 CTO**：transcript usage 增量探针+速率判据·触发窗=全时）；仅当探针触发异常判据（超阈值/速率无收敛/死循环特征）才唤起本席做**终止裁决**（制止权=语义判断 layer-③ 归 agent）——token 成本近零、误伤率低、与 dsh 化形态同轨。
- **制止权边界（本席面预案）**：终止动作的执行接口（kill 哪个进程/哪个任务节点）**技术协同件③候 CTO**（daemon/任务编排层 kill 面·白名单对象域禁泛化 kill 权·审计留痕按呈报五要素可回查粒度——CTO 认领回对表已定）；本席只持触发判据认定与终止决策权。
- **呈报**：任何制止动作（含探针空值日报）**次日首锚呈报 CEO 知情**——报面五要素=时段/触发判据/终止对象/避免损失估算（token 计）/误伤评估；全时窗下呈报节奏改为**日报制**（原「次日呈报」夜间单场景扩为全时每日首锚一并报）。
