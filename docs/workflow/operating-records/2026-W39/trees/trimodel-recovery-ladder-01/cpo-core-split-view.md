## 总判

**案裁建议：C（极小纪律内核包 frozen＋四物理域包），并全量吸收 B 案的契约测试对冲。**

先立一个概念分界，它决定三案怎么比：**「命令包」和「代码库」不是同一层**。CEO 令要的「物理上是四个单独命令包」是产品面事实——用户敲的命令、装的包、所在仓四份各自独立；「代码共用」是依赖件事实——四个命令包底下共同引用一个纪律库。两者不矛盾：**四物理包＋一个共享内核依赖=C 案**，恰好同时兑现 CEO 的降耦合直觉与既批方案的「一份纪律防四漂移」。B 案把两者混为一谈（连纪律库也复制四份），复制了全场最不该复制的面（论证见问②）。

第二个实勘事实改写问题性质：**拆分线已经埋在现役 core 里**。波③落的 core 六层中 L-C 本来就是 CoreIO 注入边界，头注明写「core 零仓感知：一切仓特有项经 CoreIO 由 bin 侧给」——也就是说，域特有面与纪律面的架构分离在波③已经做完了，三案之争不是「要不要分离」，是「分离后纪律半边共享几份」。这让 C 案迁移从「重拆架构」降格为「按既有层边界划包」，是搬家不是重写。

## 问① 真实共用面量化（产品面拆分线＋实勘数据）

**判定问句（本席立，逐层过筛）**：「这一层下次变的时候，是四面一起变（纪律升级/契约演进），还是只有这一面变（域演化）？」四面一起变=内核；只一面变=域包；靠注入解耦=边界。

实勘（TriCode `src/trimodel-cli/`，0.2.0-wave3，2026-09-26 本席亲勘）：

| 层 | 文件/行数 | 判类 | 判据 |
| --- | --- | --- | --- |
| L-A 纯函数层 | pure.ts / 104 | **纪律·内核** | 零 IO 零 env；凭据健康门三态全拒/triplet 校验/diff/掩码——五防线的纯函数半边 |
| L-B IO 内核层 | io-kernel.ts / 342 | **纪律·内核** | 五门全集（幂等短路/备份轮换+哨兵豁免/键名锁+写后断言自动回滚/掩码审计）——五防线的执行半边，头注自证「逐行等价不删不减」 |
| L-C 环境解析+注入边界 | env.ts / 146 | **边界** | CoreIO 注入接口=内核导出面（frozen 候选）；env 缺省解析器随内核走、可覆写 |

**已现/可预见分化面**（域侧清单）：探活对象与端口（本机 3333 vs R-HY 远程 vs sg/河源各域端点）、钥文件路径与 per-provider 命名、目标 settings 路径（Win/Linux 平台差异）、L3 通知形态（Win toast vs Linux 侧形态候定）、各域未来专属命令（trirmc 周平面职责、trimmc 席位面操作等「2面2域各有不同」本体）——这些现役已全部关在 CoreIO/回调后面，物理四包后归各域包自由生长，零内核改动。

## 问② 三案对比（耦合度/演化自由/四漂移风险/维护成本）

| 维度 | A 维持共享 | B 物理四包·纪律内嵌 | C 极小内核 frozen＋四域包 |
| --- | --- | --- | --- |
| 耦合度 | 四族发版被 core 版本串成一条线 | 四族完全解耦 | 域包完全解耦；内核单向低频 |
| 演化自由 | 域需求塞 core=倾倒场，最慢域绑架全体 | 各域自由 | 各域自由；内核禁域逻辑（结构规则堵死倾倒场） |
| 四漂移风险 | 低（一份实现物理上无漂移） | **高，且随时间单调增长**（见下） | 最低（内核一份实现；壳面漂移由契约测试钉） |
| 维护成本 | 防线升级改一处✓，但每域变更拖着全族回归 | 防线升级改四处×4 基线×4 复验 | 防线升级改一处；域变更各域自决 |

**对 B 案的产品面异议（核心论点）**：B 的防漂移对冲=「共享契约测试套件钉住五防线语义」——本席认为这个对冲**不完备**，因为契约测试钉得住可枚举面（语法/ResultLine schema/退出码/成功路径读数），钉不住五防线的主体——**负面语义**：占位符未替换拒写、空钥三态全拒、写后断言失败自动回滚、钥不生于活体。负面语义契约化的代价=每族每防线专测（4×25 起步，每加一条防线×4），而「没测到的负面缝隙」随四份独立演化静默扩大——暴露时点=下一次事故时，这是最贵的暴露时点。09-25 事故的教训恰是：护栏的弱点在没人盯着的那条缝。**一份 frozen 实现是物理上消灭漂移，比测试对冲强一档**；防线升级（如备份轮换 5→7 份）时「改一处还是改四处」是本判据的一句话验收。

**对 A 案的保留**：现役六层+注入边界已经把共用面压到纪律半边，A 的短期形态其实不差——A 的病不在现在，在「两面两域各有不同」启动之后：各域专属需求没有合法落点，只会往 core 里塞，四族发版节律被最慢域绑架、跨仓版本协调成本随分化线性涨。CEO 耦合担忧的机制化表述就是这个倾倒场效应，C 案用「域逻辑禁入内核」的结构规则+物理包边界把它堵死。

**C 案 frozen 门槛的产品含义**：内核变更低频但不是不变——防线升级、schema 演进必须有合法通道，否则 frozen 变官僚门槛。通道=「CPO+CTO 双签＋STE 全族基线复验（25/25 脚本侧对照+276 测套）＋CORE_VERSION bump＋四仓同步重装读数」——这套机制波③已现成（CORE_VERSION 版本锁定纪律+验收门③正名对照表），C 案只是把它升格为内核变更的唯一合法门。

## 问③ 演化半径（「两面两域各有不同」的长期代价）

- **A**：演化半径=四族全族。任何一域的变化经 core 传导全族回归；半径随域分化只增不减。
- **B**：演化半径=单族（自由度满分），但**纪律漂移的暴露半径=事故**——四份纪律各自演化后，某族的安全侧默认/五门顺序/RESULT 语义悄悄变化，隐性分歧无同步机制发现，到暴露时已是用户侧事故。
- **C**：半径分层——域变化半径=单域包（与 B 同等的演化自由，这是对 CEO 令的正面兑现）；纪律变化半径=全族但走双签门+全族基线复验（变化故意变慢变重，因为纪律变化本该慎重）。**长期两面两域分化越深，C 相对 A 的优势越大、相对 B 的优势也越大**：分化深=域包各自长的东西多（B 的自由价值兑现），而纪律半边永远只有一份（B 的漂移风险不发生）。

产品验收问句（合成稿建议纳入）：「四族里任何一族要做一件只属于自己域的事，要动几个包？」——C 答一个（域包自决），A 答可能四个，B 答一个但纪律半边无人看守。

## 问④ 迁移路径（若裁 C；候批新增波次，不并吞波④）

**总性质：结构重组非逻辑重写**——波③已把层边界切好（L-C 注入边界在位），276 测套+f887b27 STE 25/25 双基线在位=搬家后回归对照现成。**现在拆是成本最低时点：越晚拆，域逻辑往 core 里长一分，拆线越糊一分。**

1. **内核划包**：L-A+L-B+schema+L-D 装载纪律半+L-C 接口面 → `trimodel-kernel`（TriCode 内 frozen 子包），版本 1.0.0 锁；frozen 门槛=双签+全族基线复验+版本 bump（前节通道）。
2. **域包落位**：L-E+L-F 壳层+CoreIO 绑定+探活回调落各仓 bin（TriModel 现壳同构改造）；四 bin 物理四包即此成。
3. **契约测试套件**（B 对冲吸收，无论裁哪案都建议有）：三统一契约面（语法/ResultLine schema/退出码/未知旗标拒收）挂内核仓一份，四族 CI 各跑——壳面漂移的钉子。
4. **STE 复验门**：25/25 脚本侧对照+276 测套全绿，防线语义零变化（本评估边界：只验结构搬家，不重开语义）。
5. **时序与并波**：波④演练主线在现役 A 形态上照跑全程零阻塞（边界条款）；迁移波候批后独立排窗一次搬家；R-HY M1 部署不受影响（部署消费的是 bin 契约面，包结构对部署面透明）。工作量产品面估：小波次（包边界声明+四仓依赖切换+测试重挂），非大波次。

**波③资产保值声明**（回应「刚落地就翻案」的直觉）：波③的真产出=纪律实现从 ps1 逐行翻译成 TS+276 测钉住+五门逐行等价验讫——这资产在 A/B/C 三案下全额保值，C 案迁移是给已验资产划包界，不是推翻重做。CEO 令「暂时代码共用是可行」的共用价值窗口=纪律翻译窗口，该窗口的价值已经兑现完毕。

## 风险与升级

1. **frozen 门槛官僚化风险**：门槛若重到没人敢走，防线升级会被拖延在内核外——合成稿须写明变更通道就是双签+基线复验本身，低频≠冻结死。
2. **五版本面一致性**：四域包+内核=5 个版本面，CORE_VERSION 同步读数须进正名对照表常设项（波③验收门③机制沿用扩展）。
3. **契约测试覆盖率边界**：契约套件钉壳面不钉内核负面语义（内核靠单一实现+frozen 门保真）——合成稿须写清这条分工，防「有契约测试就敢复制纪律」的误读回潮 B 案。
4. **本意见为候定**：案裁呈 CEO 批，评估期与批前不动现役 core；裁 B 亦同走迁移候批波次。
