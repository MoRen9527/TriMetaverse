- **P0 ④行必改**：「看现状」改指真 status 形态。trimlc status 已 F5 实弹全绿（`OK [OK]` 人话三段），候选正形；若用户 shell PATH 未验绿过渡期，宁删④行不可留假「查看」。
- **P1 fail-closed 分文案（CTO 裁量问，裁=分）**：verdict=unhealthy 与 DEPLOY_KEY_MISSING 两态用户补救动作不同——前者「手动恢复一次」成立，后者跑恢复只会再 fail-closed（F4 实弹 11 连自证），正确动作=供钥/完成部署步骤。本弹恰是 fail-closed 态弹的「手动恢复一次」——误导被实弹命中，非假想。分法：toast 触发时读 L2STUB 失败 reason（flag/log 可得）驱文案变体；key-missing 变体=「恢复所需部署钥未就位，请完成供钥步骤；您的 AI 服务不受影响」。判据同源=偏-2 503 定义案「两态补救动作不同，共话术=误导」。
- **P2 命令通道切正门**：joint-plan 问3 已裁「人对人的正门口只有一个=trimlc 命令族，两门=两事故面」+退役条款「过渡期以新族为准」。toast 现指 ps1=人肉入口在旧门。切换前置=trimlc 用户交互 shell PATH 可用性验绿（发现-A 已证 daemon spawn env PATH 缺 node，用户 shell 侧候勘）；验绿前维持 ps1 形态（可用性优先于正名——不能让用户拿到跑不通的命令）。验绿后 toast/警示句/页面引导三处同批切，禁三处两态。
