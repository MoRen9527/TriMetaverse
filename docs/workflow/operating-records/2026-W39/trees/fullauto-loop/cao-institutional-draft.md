## 二、状态机制度骨架（供 FADE-008 §8 的 CAO 制度面贡献）

### 2.1 态集（canonical 七态，与既有台账/信箱态映射）

`在办 → 候审 → 候批 → 已批 → 在执行 → 收口`（+终态 `closed`/`escalated`）。
映射纪律：**台账=状态真源**（single source of state），信箱=通知/视图面（投影非真源）——防双真源（信箱态漂移以台账为准追平，D-16 精神同构）。

### 2.2 转移触发（自动化边界内）

| 转移 | 触发 | 自动/人工 |
| --- | --- | --- |
| 在办→候审 | 执行席产出落盘（D-01 先写后报） | 自动（写信箱 target=bod+coo） |
| 候审→候批 | 审核席签认 | 自动 |
| 候批→已批 | CEO/BOD 批 | **人工**（BOD human in session；敏感面永不自动化） |
| 已批→在执行 | 回流开工（信箱状态机流转） | 自动 |
| 在执行→收口 | 树收口报告+台账销账锚（D-27 v2） | 自动+销账人工（COS 销账权） |

### 2.3 三层催办制度定位（与 D-27 v3 的关系）

- 催执行席=**周期催办**（v3 时机层 2：硬阈值/常规 24h 软阈值——自动催办的实现恰是 v3 的机制化）；
- 催审批链（BOD/CEO）=**即时催办**（v3 时机层 1：候批态素材齐备即写信箱，小时内——**禁预约隔夜**，LG-037 教训直接适用：候 CEO 批的事项 BOD 挂起即沉=隔夜催的审批链变体，本命题根治对象）；
- 催督办面（COO）=台账层双层催（COS 任务书层+台账层，v2 催办全覆盖+时效锚）。

### 2.4 边界条款（宪章 §六 制度化）

1. **敏感面永不自动化**：CEO 终裁/SEC 面/不可逆操作保留人工——自动化止于「推到面前」，不代做决定；
2. **BOD human in session=设计非缺陷**：本地域人工保留点清单由 BOD 段主笔，制度面确认其不可自动化属性；
3. **现役机制复用**：notify 通道/信箱/台账/Sync-Alert 已就位，本命题=编排层整合，禁新建平行基础设施（基建复用纪律）。
