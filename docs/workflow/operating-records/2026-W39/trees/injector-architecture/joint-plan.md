## 一、命题 B：形态裁=**案二共用模块单提，落 TriCode 包**

**B 必答（零漂移复制体为何不可持续，四条）**：漂移进行时实证（app.ts 5+5 先例）／每次演进双倍成本／归属模糊无权威位（diff=0 无法判原件）／审计聚合伏笔（两表漂移后失真）。

**三案并评**：
- 案一 各 daemon 内嵌（现状）——单一真源✗双维护✗ → 否；
- **案二 共用模块单提，落 TriCode 包**——单一真源✓/**面隔离=运行时概念非代码仓概念**（包同源/实例分跑/DB 分库，M/R 并行无退役不破）/维护单份/审计同构天然对称 → **采纳**；
- 案三 中心注入服务——跨面依赖+单点+会话初始化性能税，伤面隔离 → 否。

**渐进路径**：四件提 TriCode 包→TriMLC/TriRLC 改包引用→**行为零变化验证**（同输入同输出+consumption 表结构不变）→复制体退役（独立 commit 可回滚）。**喂食关系跟随被服务面（CPO 判据#1）在包架构下自动成立**：TriMLC 引包喂 M 面/TriRLC 引包喂 R 面——责任随消费者走且代码单源。

**sg 服务域红利**：TriMMC 未来需注入面（触发条件首例时）=引同一包加端，零新代码体系。

## 二、命题 C：决策权=混合制三权分置（CPO 核心交付，全采）

- **餐单规则→治理与策展**：保底正餐=三层分发核心层+岗位标准+stable 页——**技术硬保证：餐单=配置数据非代码**（injector 永不硬编码餐单，「照单执行机构」的代码面保证）；
- **执行→daemon**：现役三消费方调用点自动（会话初始化必注+心跳按需）=保底正餐通道，现状已在跑；
- **加餐→席位自请**：走**检索面**按需拉取（不计注入预算，按用付费；自请行为入审计）——增量补加面（CPO 修正版：自动半边已在跑，演进=增量）；
- **反馈闭环（CPO 最有价值条）**：自请主题→promotion 候选链路可查——加餐高频主题=策展升格信号（与认知资产审计信封 promotion 动词咬合）。
