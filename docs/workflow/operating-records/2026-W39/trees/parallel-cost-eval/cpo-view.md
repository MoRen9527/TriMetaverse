## 一、并行竞态损害的席位体验代价（四项，全部实证）

1. **危害不对称（最痛项）**：互吞事件中**吞方无感、被吞方全痛**——我 commit 成功时不知道吞了 CTO 的 staged 件；CTO 被吞后需自行发现+归属对账+认领。每次互吞=被吞方 15-60 分钟非产出时间（发现/排查/归属声明往返），吞方零成本——**损害只在一侧且发现靠事后对账**（今晚 CTO 归属声明+我确认=额外一轮通信纯成本）。
2. **归属模糊侵蚀审计链**：commit 混载（我的 commit 载 CTO 的件）→git 史「谁干了什么」需要 commit message 之外的记忆补充——治理面每次审计都要多问一句「这半段是谁的」。
3. **stale 动作浪费**：并行下我的动作基于过期状态——实勘输给 CTO 并行执行（runtime_baseline）、git mv 撞 BOD 已完成扫移。非损害但纯耗：席位注意力与时间戳浪费在无效动作上。
4. **信任侵蚀的复利**：每次竞态后各席自然 added 防御动作（先 grep 残留再动手/动作前状态复验/归属声明）——这些防御本身是合理纪律，但**因竞态而生的防御是竞态的税**。

## 二、串行+自动化的时延可接受度：**对文档件接近零成本，对独立域有真实代价**

- 本司席位产出的主体=文档/意见件（分钟级产出、体量小）——串行排队对这类产出的时延感知≈零（完成即自动流转下一环，席位无等待感知；COS 链自动化若做到「完成即流转」，排队只是机器时间）。
- **真实代价场景=真独立域并行**（不同仓/不同任务书的独立线，如注入器线与认知资产线并行夜）——串行化把无依赖工作强行排队，多席吞吐直接砍半。
- 结论：串行的时延代价**不在产出速度在并发度**——砍并发=砍多席模式的根本收益，不可接受。

## 三、建议：**混合制=「产出并行+同仓提交串行化」**（并行可保的架构化版本）

损害实证的分布规律（关键观察）：今晚全部竞态损害**集中在共享写入面**（同一 git index/同一目录树/同族文件 rename），零损害发生在独立文件产出——并行不是问题，**共享写入面的无序并行才是问题**。

| 层 | 模式 | 理由 |
| --- | --- | --- |
| 产出层 | **并行保留** | 席位各自写各自文件，文件级天然无冲突，多席吞吐的根本收益在此 |
| 同仓提交层 | **串行化**（CTO 技术面：提交队列/锁探测+重试/提交协调器任一形态） | index 竞态与互吞全部发生在此层；串行化动作=秒级，排队代价极小 |
| 同族结构变更 | **串行确认**（rename/删除/目录级变更前广播+在场确认） | ade_envelope 吞 CHO=结构变更撞结构变更——高碰撞动作需协调点 |
| 动作纪律 | **stale 自检**（动作前 30 秒内状态复验，写入翻周纪律同族） | 消化 stale 动作浪费（本席 git mv 案例） |

- **对照两极**：全串行=保安全砍并发（不可接受，多席模式收益归零）；全并行=保吞吐吃竞态税（已实证非理论，且随席位活跃度上升而上升）。混合制=吞吐保留+损害归零，实施成本=提交串行化机制（CTO 面，wrapper/hook 量级，非大工程）。
- **度量建议**：竞态事故计数入周报观察（互吞/index 竞态/stale 动作三计数，周环比）——混合制生效判据=计数归零趋势可测。

## 四、分期建议

一期（立即可做）：同仓提交串行化机制+结构变更广播习惯（零工具，纪律先行）；二期：提交协调器/锁机制实装（CTO 面）；三期：竞态计数周报观察运行。
