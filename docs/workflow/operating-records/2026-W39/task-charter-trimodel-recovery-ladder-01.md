## 一、背景与目标（CEO 架构定调要义）

1. **问题自勘（CEO）**：TriModel UI 加「直接编辑 settings.json」页面，页面跑在 3333 服务上——3333 挂则页面同样不可用；cc-switch 式本地配置不依赖端口、直接编辑 settings.json，故**兜底能力必须建在 3333 之外**。
2. **现役资产**：本机无 cc-switch 类软件，但有 TriMLC daemon（M 面本地域 daemon，8713，TriMLC-Watchdog 保活）——兜底执行者现成。
3. **分层恢复结构（CEO 定调，地基）**：
   - **L1 自动重启**：本地直连切 TriModel 后出故障 → watchdog 重启 TriModel；
   - **L2 自动降级**：重启仍无法恢复 → TriMLC daemon 自动调 trimlc 命令恢复本地直连配置可用参数；
   - **L3 人工提醒**：仍不可用 → PowerShell 定期弹窗（toast）提醒用户手动 trimlc 配置；
   - **L4 人工兜底**：用户手动命令配置 settings.json——命令参考/扩展 restore-claude-config.ps1，**未来跨平台多模型可配置**。
4. **执行顺序（CEO 明令，地基论）**：①TriModel 页面直连配置功能 →②分层恢复结构 →③trimlc 命令 →④全链故障分层恢复跑通 →⑤回头测删除策略（D1）。**「地基先打好，不然上面建什么都会塌。」**
