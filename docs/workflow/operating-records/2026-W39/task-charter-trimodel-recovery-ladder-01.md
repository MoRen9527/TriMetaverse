## 一、背景与目标（CEO 架构定调要义）

1. **问题自勘（CEO）**：TriModel UI 加「直接编辑 settings.json」页面，页面跑在 3333 服务上——3333 挂则页面同样不可用；cc-switch 式本地配置不依赖端口、直接编辑 settings.json，故**兜底能力必须建在 3333 之外**。
2. **现役资产**：本机无 cc-switch 类软件，但有 TriMLC daemon（M 面本地域 daemon，8713，TriMLC-Watchdog 保活）——兜底执行者现成。
3. **分层恢复结构（CEO 定调，地基）**：
   - **L1 自动重启**：本地直连切 TriModel 后出故障 → watchdog 重启 TriModel；
   - **L2 自动降级**：重启仍无法恢复 → TriMLC daemon 自动调 trimlc 命令恢复本地直连配置可用参数；
   - **L3 人工提醒**：仍不可用 → PowerShell 定期弹窗（toast）提醒用户手动 trimlc 配置；
   - **L4 人工兜底**：用户手动命令配置 settings.json——命令参考/扩展 restore-claude-config.ps1，**未来跨平台多模型可配置**。
4. **执行顺序（CEO 明令，地基论）**：①TriModel 页面直连配置功能 →②分层恢复结构 →③trimlc 命令 →④全链故障分层恢复跑通 →⑤回头测删除策略（D1）。**「地基先打好，不然上面建什么都会塌。」**

## 二、联审设计四问（方案必答）

1. **UI 直连配置页**：功能边界与安全护栏——活体 settings.json 编辑必须吸收 09-25 事故教训（备份先行/JSON 校验/凭据掩码显示/写入前验证）；页面定位=**日常便利层**（3333 在线时用），不承担故障兜底职责；与 LG-035 policy/card 冻结面的分界。
2. **分层监督链拓扑**：L1→L2 判定标准（「重启无效」=探针定义/重试窗/超时阈）；TriMLC daemon 探活 3333 的机制与触发条件；L2 自动降级的钥源（独立钥文件 `.deploy-key` 机制现成衔接，禁从活体死循环取钥——事故教训②）；L3 弹窗实现（Windows toast 形态＋定期节律＋D-29 无窗纪律：禁闪 conhost 黑窗）。
3. **trimlc 命令族**：命令面设计（恢复直连/配置参数/状态查询至少三件）；与 restore-claude-config.ps1 的关系（吸收/扩展/取代裁决）；多平台多模型扩展接口预留（bigmodel 直连为第一实现，deepseek 等后续模板可插拔——模板三件套：地址/模型名/钥占位符）。
4. **全链演练验收**：故障注入→L1→L2→L3→L4 逐层验证方案与「跑通」判据（每层触发条件实测＋恢复后状态断言＋各层间降级衔接实测）；演练用沙箱形态，禁真伤活体（事故教训③）。
