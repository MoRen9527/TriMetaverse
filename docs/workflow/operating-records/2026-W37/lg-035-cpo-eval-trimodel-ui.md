## 产品判断

CEO 方向成立且是正确产品化方向：**单入口管理多机，后端分发对用户透明**。SSH 隧道被否的本质是「运维通道词汇泄漏到产品面」——用户被迫知道机器拓扑才能配置模型。本评估把产品语义定住，技术缺口（UI 直推分发链）留给 CTO 方案，不阻塞 MVP。

三条产品原则（全案锚点）：
1. **通道词汇不上产品面**——界面出现 SSH/隧道/终端字样即产品化失败。
2. **保存与应用分离**——填错不误推；远端误推影响 sg 在跑的 13 席，成本不对称。
3. **「凭什么配」不进用户面**——用户填「配什么」（provider/key），不填「凭什么配」（ADMIN_TOKEN）。

## MVP 定义

- **范围**：本机 3333/ui 新增「TriMMC」栏（信息项见①）+ 三态状态徽标（未配置/待应用/已应用，失败红态）+ COS 代理应用（现有 ADMIN_TOKEN + secure 写面热生效，零重启）。
- **不含**：UI 直推分发链（P2 候 CTO 方案）、多机卡片列表（现役仅 sg 一台）、独立策略编辑器。
- **验证指标**：⑤ 验收口径六判据，CEO 亲手走查 + COS 应用读数双侧印证。

## ② 单入口信息架构（用户心智裁决）

心智定为**「我在管这台机器的模型」**（单机配置中心），不是「我在管多机」：远端 TriMMC 是「同一份配置的另一处应用目标」，不是独立机器对象。依据：CEO 原文「分出一栏配置 TriMMC」=栏语义；现役实际仅 sg 一台目标机，不引入机群管理心智负担。

- 本机 3333/ui 主视图不动；新增「TriMMC」侧栏/分区，栏内 MVP 为**单目标机卡片**（P2 多机时演化卡片列表，架构预留不实现）。
- 本机配置区与 TriMMC 栏并列、语义标注清晰：本机=本机生效；TriMMC 栏=远端应用。
- 栏内零 SSH/隧道/终端词汇（原则 1 的验收面）。

## ③ 跨机分发产品语义

**MVP：保存不即推，代理应用。** 「保存」只写本机配置存储并置「待应用」；应用动作由 COS 代理执行（读待应用→ADMIN_TOKEN+secure 写面热生效→回写「已应用」+时间戳）。三态：未配置→待应用→已应用（+失败红态）。

- 拒绝「填完即推送」为 MVP 行为：填错即误推远端，违反原则 2；保存/应用分离给一次反悔窗。
- 状态可见性：栏内徽标+最近应用时间+失败原因**类别**一行（不弹窗轰炸）。
- **P2（候 CTO 分发链方案）**：「保存并推送」按钮直推+即时结果反馈+失败重试按钮；推送鉴权模型随 CTO 方案定。若 CTO 判定跨机暴露写面端口安全不可接受，**回退终态=MVP 形态（COS 代理应用），UI 只做配置存储+状态**——不损 CEO 单入口体验，此为天然回退位。

## ④ 权限与安全边界（产品面）

- sg 侧凭据（ADMIN_TOKEN）不出产品面：COS 运维资产在档，UI 不填不看（见①）。
- Provider key：复用 P2 密文写面；分发日志/状态回写不回显明文。
- 分发执行权：MVP 执行者=COS 代理，UI 不开放无鉴权直推；P2 直推的鉴权模型在 CTO 方案内定稿。
- 失败提示信息边界：报「失败+原因类别」，不泄漏 token/内网拓扑。
- **定性红线**：本栏属内部运营工具面，不得被引用为对外产品能力或写进对外产品叙事（本席行为护栏：不把内部工具写成产品表面）。

## ⑤ 验收口径（CEO 侧体验判据，六条可测）

1. **全程无 SSH**：本机浏览器 127.0.0.1:3333/ui 完成一次 sg 模型配置变更，全程零终端——判据=操作录屏/步骤清单无终端出现。
2. **单入口**：唯一「TriMMC」栏，必填项 ≤4（预置端点时 ≤3）。
3. **生效可证**：应用后 sg 3334 代理面调用成功（COS 出热生效读数，零重启）。
4. **状态可读**：三态徽标+最近应用时间可见。
5. **密文合规**：key 写入后不回显明文（眼睛除外），与 P2 行为一致。
6. **失败不静默**：模拟错端点一次，出现失败态+原因类别。
验收方式：CEO 亲手走查 + COS 全量应用读数，双侧印证。
