## §2 页面信息架构 v3（一 URL 三区）

```
127.0.0.1:3333/ui
├─ 页头：TriModel 模型配置 ｜ 连接设置[ API令牌 · 管理令牌 ]（折叠，记忆本机）
├─ 状态条「当前生效」：当前模型 ｜ 来源 ｜ 一致性 ✓/✗ ｜ [刷新]   ← 零输入控件
├─ 【TriMMC 信息】主卡（页面主角，首位，卡片式实线边框）
│   ├─ 栏头：机器名 ｜ 状态徽标（待应用/已生效/失败）｜ 最近应用时间
│   ├─ 机器信息：机器名称（必填）；连接档案（预置只读，折叠）
│   ├─ 模型信息：条目列表（名称|厂商|模型|密钥|启用|操作）＋ [添加模型条目]
│   └─ 模型切换策略：当前使用 [下拉·仅已启用条目]（＋「按时段/额度自动切换将于后续版本提供」）
└─ 【本机策略面】折叠区（P1 原 策略列表/密钥状态，标题改「本机策略（高级）」，原样收敛）
```

裁决理由：CEO 七条中 ②⑤⑥ 的混乱共同根因=TriMMC 卡（配置意图，save→pending→COS 应用）与 P1 策略面（本机直调直生效）两种语义焊在一页无边界。v3 把两种语义**分区隔离**：主卡=CEO 单入口（远端配置意图）；本机面=高级折叠（本机运维）。令牌=页面授权件，独立成连接设置，不再栖身任何内容区。

## §3 TriMMC 信息卡详细 spec

### §3.1 状态徽标文案映射（禁英文枚举直出）
现状 :343 `badge.textContent = state` 直接显示 pending/applied/failed。v3：pending→**待应用**（橙）｜applied→**已生效**（绿）｜failed→**失败**（红，附原因一行）。

### §3.2 模型信息（条目交互唯一模式）
- 列表列：条目名｜厂商｜模型｜密钥（尾 4 位）｜启用（行内开关）｜操作（编辑/删除）
- **添加模型条目**按钮 → 卡片表单（非弹性行）：标签在上一列对齐，字段=条目名（必填）/厂商（下拉）/模型（下拉，§3.4）/API Key（必填，密文，眼睛）/base_url（高级折叠，选填）
- 编辑=行内按钮预填同一表单；**无覆盖**：同条目名保存=更新该条目（表单标题「编辑条目 X」明示）
- 删除：被切换策略引用时阻止，文案=「该条目正被切换策略使用，请先改选其他模型」（替代现 ：364/:77 的「悬挂引用/400 拒绝」黑话）

### §3.3 模型切换策略
- 「当前使用」下拉=**仅已启用条目**（修 ：375-383 无过滤）；选项文案=条目名（模型名）
- 空态文案：「暂无可用条目，请先在模型信息中添加并启用」
- 停用当前使用条目→自动回落默认+黄色提示「已回落：条目 X 已停用」（逻辑补全）
- 时段/额度：显示占位说明文案（同现状 :90，保留）

### §3.4 数据绑定规则（给 FSD 的硬规则）
1. 模型下拉数据源=GET /v1/models（与策略区同源，:309-322 复用），渲染失败=错误空态+重试钮
2. 一切选择器选项派生自实际数据，禁出现无数据源空下拉（⑤ 根因规则化）
3. 空态必有引导文案；加载失败必有错误态+重试

### §3.5 密钥单一路径（⑦ 裁决）
用户面唯一密钥录入点=模型信息条目内 Key 字段；独立密钥管理区删除。底层 keys.enc 与卡片 entry 密文的存储归并方案（provider 级 key 与条目级 key 的关系）归 CTO 方案，产品语义只有一条：**一个条目一把 key，在条目里填**。

## §4 保存与生效语义统一（架构级裁决，七条外追加发现）

实勘：条目「保存卡片」→pending 候 COS（:418-433），但「选为固定使用」按钮**直写本机 policy 即时生效**（:437-454，成功文案「3334 下一请求即生效」）——同一张卡两种生效路径并存，违反 v1 原则②（保存/应用分离）。
**v3 统一语义**：TriMMC 卡内一切写动作（条目增删改+当前使用）只写卡片，保存→**待应用**→COS 应用→已生效；卡内不出现任何即时生效按钮与「即生效」文案。本机策略面（折叠区）保留本机直写直生效语义，与卡无关。cos 巡检节律不变。

## §5 全局视觉准则（① 裁决）

- 区块=卡片式：`border:1px solid`（浅色 #d4d4d8 / 深色 #3f3f46，token 化交 CTO 定稿）+ 微差背景（浅 #fafafa / 深 #18181b）+ 8px 圆角；区块间距 16px
- 卡内分区（机器信息/模型信息/模型切换策略）各带小节标题+细分隔线（同 token，不再用 20% 透明度）
- 判据（走查项）：普通办公室亮度下分区界限清晰可辨；深浅两主题各验一遍

## §6 四族问题全扫结论

- **族 1 术语自造**：当前生效值对读→当前生效｜候选池→（删，改「模型条目」）｜固定规则→当前使用｜悬挂引用/400 拒绝→人话（§3.2）｜回显污染防护→删｜「masked 展示值不是真实密钥」→「检测到占位符，请输入真实密钥」
- **族 2 命名偷懒**：子栏N（§1③）｜TriMMC 机器栏→TriMMC 信息｜enabled→启用｜id→条目名｜priority→优先级｜badge 英文枚举（§3.1）
- **族 3 布局错位**：row-form 弹性错位（§1④）→标签在上网格对齐；kv 200px 网格保留
- **族 4 逻辑混杂**：添加/覆盖双义（§3.2）｜双密钥路径（§3.5）｜双生效路径（§4）｜启用过滤缺失（§3.3）
- **追加（七条外）**：错误文案直接暴露 HTTP 码与环境变量名（:167 「503 disabled（服务端未配置 TRIMODEL_ADMIN_TOKEN）」→「管理写面未启用：请先在服务端配置管理令牌」；:171 401→「管理令牌不正确，请检查」）；中英混杂标签（族 2）。
