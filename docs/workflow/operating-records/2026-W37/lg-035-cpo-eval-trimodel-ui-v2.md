## 产品判断（本轮）

CEO 三问一议整体是**向下加深度而非改方向**：单入口方向不变，三子栏把「连机器—配模型—定切换」三层关注点切干净，采纳。修订核心工作量在**与既有 P1 策略引擎合流，零双轨**——子栏二/三不得长出第二套模型选择逻辑。

## ① 裁决：名字 vs IP

**定谳：名字=主标识；IP/端点=连接档案属性，藏高级项、COS 预置、只读可见。** COS 初步理解成立，本席正式采纳同向。

理由四条：
1. **语义分层**：栏回答「我在配哪台机器」——用户心智里机器按角色标识（sg 机器），IP 是「怎么到达」的管道属性，不是「它是谁」。CEO 原文「单入口+分发透明」的产品语义本身就把拓扑推到后台。
2. **波动性解耦**：IP 会变（迁移、重托管），名字不变。以 IP 为标识，每次网络变动都打断用户识别与配置引用；名字天然抗物理变动。
3. **多机终态唯一通路**：CEO 直觉正确——未来 TriMMC 面多台服务器挂一个名字（同名多实例组），名字命名空间可 1→1 起步、1→N 演化；IP 天然 1:1，走不到组语义。以名为标识是唯一不用日后做数据迁移的选法。
4. **诚实注记**：现役仅 sg 一台，名字 vs IP 今日无实际差异——本裁决买的是不画角：成本为零，避免日后迁移。

展示面：状态徽标读「sg-01 已应用 20:15」（人读），IP 仅在子栏一高级区只读露出（调试用）。

## ② 三子栏结构 spec（修订版）

栏结构：**栏头 + 三子栏**。栏头=目标机名+三态徽标+最近应用时间（状态可见性载体，从 v1 子栏 C 上移）。

### 子栏一：服务器信息
| 信息项 | 必填 | 说明 |
| --- | --- | --- |
| 机器名称 | ✓ | 主标识（①裁决） |
| IP/端点（连接档案） | 预置 | COS 预置+ADMIN_TOKEN 管道同存储；高级折叠**只读**露出；新目标机时转可编辑 |
| 环境标签 | P2 | prod/test/灰度，本版不做 |

### 子栏二：模型信息（提供商条目列表）
每条目=厂商 + 模型名 + API Key + 可用开关。可增删多条（**多提供商录入本版即支持**，理由见③）。
- Key 密文写面+眼睛复用 P2 控件。
- 「当前使用」=**只读展示策略引擎当前裁决结果**，不设手填字段（合流关键，见下）。

**合流设计（零双轨）**：模型选择的唯一裁决者=既有 P1 策略引擎。子栏二=策略引擎的**候选池数据**（条目列表）；子栏三=策略引擎的**选择规则 UI**。CEO ②①「可指定具体用哪个模型」不是平行机制，而是规则表中一条最高优先级的「固定使用 X」规则——与时段规则同表不同类型。UI 呈现见子栏三。

### 子栏三：切换条件（策略引擎产品化 UI）
- **MVP 形态**：「当前使用」单选器（从子栏二已启用条目中选一）+说明文案「按时段/额度自动切换将于后续版本提供」。数据面按**优先级规则表**存储（固定规则=一行），UI 与数据解耦，P2 换规则表 UI 零迁移。
- **P2**：规则表 UI——时段规则（先上）、额度用尽自动切换（CEO 原文自标「未来」，且额度数据管道是新依赖、涉 CTO 计量面，非 UI 问题）。

## ③ MVP 边界重划（划线清单）

**进 MVP**：
- 子栏一全量（名称必填 1 件，连接预置只读）
- 子栏二：多提供商条目**录入**全量支持（数据形态一步成型避免 P2 迁移——此为 CTO 评估点），规则层仅「固定使用」
- 子栏三：「当前使用」单选器（=固定规则 UI），规则表存储形态
- 三态徽标+代理应用（v1 机制不变：COS 代理、保存不即推、热生效零重启）

**留 P2**：时段切换规则 UI｜额度用尽自动切换（含计量管道）｜多机卡片列表｜同名多实例组（数据模型预留不实现）｜环境标签。

**验收判据更新**：
- 原「必填≤4」→ 子栏一必填仅名称 1 件；新增提供商条目必填=厂商+模型+Key 三件。
- 新增：7. ≥2 提供商条目录入成功且密文合规；8. 「当前使用」切换后 sg 3334 代理面实际调用到目标模型（读数印证）；9. **零双轨验证**：策略引擎真源唯一，UI 改动未产生第二套选择逻辑（CTO 评估出证）。
- v1 判据 1-6（无 SSH/单入口/生效/状态/密文/失败不静默）全部保留。
