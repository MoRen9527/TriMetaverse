## 二、子栏三「模型切换策略」修订设计（固定+时段并存）

### 2.1 结构（v2 规则表设计的 UI 落地，数据同表不同类型）

- **固定使用**（既有单选器，原样保留，位置不动）：已验证 UX 不重测。
- **时段规则区**（新增）：
  - 规则列表：类型徽标｜模型｜时间窗｜启用（行内开关）｜操作（编辑/删除）——只列时段规则，固定使用不入列（选择器即其 UI 形态）
  - 「添加时段规则」→ 卡片表单（标签在上，同 v3 §3.2 形态）：模型（下拉，仅已启用条目，级联随供应商）/ 开始–结束（HH:MM 两输入）/ 启用（默认开）
  - 时区副注一行：「时区：北京时间（Asia/Shanghai）」——防跨时区误判

### 2.2 固定与时段的冲突语义（诚实呈现，防「设了没切」困惑）

- 引擎既定语义：**固定使用恒匹配压时段**（fixed 优先级压过时间窗）。
- UI 必须镜像此语义：**固定使用非空时**，时段规则区顶部显示常驻提示条「固定使用生效中，时段规则暂不参与；清除固定使用后按时段执行」（黄/灰提示，非错误）。
- **不做静默互斥**：设时段规则不自动清固定使用（突变比共存更伤信任）；清除动作始终显式（既有「清除固定使用」路径）。

### 2.3 校验与边界

- 时间格式 HH:MM；**start≥end 拒绝**，文案「结束时间需晚于开始时间」（跨午夜窗口本版不支持，候引擎能力确认后放开——CTO 确认项）。
- 模型下拉空态/级联/密文全部继承增补件 2 定义，零新例外。
