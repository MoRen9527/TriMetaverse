## ① 术语：厂商 → 供应商（采纳，全量替换）

- UI 全部出现处替换：模型信息表列头、添加/编辑条目表单字段名、级联相关文案。代码内 provider 字段名不改（内部标识），仅 UI 文案层。
- spec 层同步：v3 §3.2 条目列表列「厂商」即起更正为「供应商」。
- 理由备案（CEO 原话要义）：openrouter 类聚合方是供应商不是厂商——provider 的产品语义=「模型服务从哪里获得」，非「谁训练/制造」。

## ② 供应商→模型级联（归源 catalog，禁第二张静态表）

- **交互**：选供应商 → 模型下拉仅列该供应商模型集；未选供应商时模型下拉禁用+引导「先选供应商」；某供应商无模型时显示「该供应商暂无可用模型」。
- **映射维护方式定稿：catalog 动态派生**——model-catalog.ts 每模型条目增加显式供应商归属字段（现五名归族：deepseek-flash/deepseek-v4-pro→deepseek；GLM-5.3-Flash/GLM-5.3→glm；TMV→trimetaverse），UI 从 /v1/models 响应派生级联；供应商下拉选项=catalog 内供应商去重集（替换现 UI 硬编码三选项）。
- **禁 UI 侧自维护静态映射表**（双轨禁令，同 §3.5 密钥/§4 语义先例）：catalog 是模型与其归属的唯一真源，新增模型自动挂对供应商，零 UI 改动。
- 实现注记（CTO）：/v1/models 响应需携带每模型 provider 归属（或独立 catalog 端点），E3 五名逐字节断言随级联改写为分组断言。

## ③ base_url 字段语义：必填 + 按供应商自动填充 + 可改（混合案）

- CEO 两案（必填+默认建议 / 按协议自动填充可改）取并集，消解点在「默认值从哪来」：
  1. 字段=**必填**（不再可选折叠）；供应商选定后**自动填充**该供应商默认接口地址（可改）——常见场景（官方 API）零输入，聚合方/自建网关直接改。
  2. 默认值来源=catalog 侧供应商条目扩展可空 `default_base_url` 字段（零双轨：默认地址与模型归属同源维护）；catalog 无默认的供应商→空+必填校验+占位示例（如 https://.../v1）。
  3. 校验：保存时 URL 格式校验，错误文案=「请填写接口地址（以 http(s):// 开头）」。
- v3 §3.2「base_url（高级折叠，选填）」即起废止，以本条替代。
