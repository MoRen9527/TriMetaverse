## §二 · 定形决议（汇总人整合）

### 决议甲 · 任务书 schema（CTO 五字段 × CPO 五段合并）

**机读面五字段强制**（CTO）：`title / target / change / verify / rollback` + `opinion_id` + `run_id`——缺 target/verify/rollback=不可机械映射退回人工。

**卷面五段+一列**（CPO）：
1. 头部机械可读段：ID=`r<N>-task-<YYYYMMDD>`·来源=评审卷锚·**审批面字段（debug→CEO 批／test·prod→COS 代批·批语+时刻必填）**·TriRMC 拾取路由字段——**自动拾取前先校验审批面：无批=不拾取**
2. 改造项清单：逐条挂意见编号+动作+落点+依赖·红线条目必全带·**不夹带未评审项**（D-39 任务书纯净性同构）
3. 验收锚：逐项可机械复算·**考卷应考项 ⊇ 任务书验收锚 100%**（漏考=考卷缺陷退卷）
4. 回滚位：整单基线 commit/快照+逐项回滚动作+触发判据
5. 弃权/否决显式段：弃权席「弃权（无意见）」原样列不折为通过·否决/红线=编号+证据锚+最小修复建议·**未闭环不得进施工**·条件批列条件+解除判据（对应项状态=pending）
6. 状态列：pending/施工中/验收中/毕——毕=三件齐（改造毕+点火跑 run id+新卷骨架锚）

### 决议乙 · 自动拾取链（复用现役树协议·零新链）

- 任务书挂 `trees/<week>/trees/fade001-evolve-<ts>/` → TriRMC cron executor 现役拾取（CTO）
- 新件仅两处：a) 任务书生成器（opinions→五字段机械映射脚本）b) 点火触发（毕报后置步骤 or cron state 检查）
- 审批 gate 内嵌挂载点：生成→审批（approver 字段）→挂载→拾取=**审批前置非新流程**
- **auto_dispatch: true 字段**（CTO 红线二）：自动面显式授权标记·CEO 批面非默认·防误用扩大到非 fade-001 线

### 决议丙 · 停损与红线（CTO+COO 合并）

- **fail-safe 停不重试**：施工失败（测试红/构建红）→自动停+不点火+毕报挂候裁（人工介入·零自动重试）
- **自动施工范围=源码+测试**（CTO 红线一）：部署/重启/配置生效=人工窗位令照役·不碰不可逆面
- **顶点火权不下移**（COO）：自动施工毕=停「候验收」态·点火=批准权下游（CEO 批 debug/COS 代批 test·prod）
- **无人值守两红线**（COO）：不得自裁扩大改面范围（任务书边界=硬界）·**不得跳过 CTO 终审**
- 停损责任链四层：执行方（红即停）/COO（资源窗仲裁+督办读数）/CTO（技术终审）/CEO·COS（批准面）

### 决议丁 · 验收衔接（CPO）

- 改造完→点火跑=**新一轮 r<N+1> 考卷出卷**（段 3 出卷·卷绑新 run id）——**改造完不自己判自己**
- 判据=新一轮**全席达线制 ≥95**（非「改造完即过」）
- **防自评**：本轮施工席不参与该轮判卷；FUSE 融合意见作新卷应考项来源之一
- 轮次编号 r<N> 与 run id 双键并存（轮次号答「进化到第几轮」·run id 答「哪一拍」）

### 决议戊 · 启用时点（CTO+COO 一致）

- **第一步=人工闭环一轮验证（本次九点令=天然试跑）**——人工跑完一轮完整 loop（联审→任务书→施工→点火验证）再开自动拾取
- **自动拾取=P6 收口后启用**（COO：P3-P6 施工期互踩风险）·或 P4 设计达面后单列评估窗
- 灰度形同 P3 两步策略

### 决议庚 · 无人值守成本护栏三层（CFO·自动链路专用）

1. **L1 轮级 ≤1 CNY/轮**（既有护栏延用）
2. **L2 日级 ≤15 CNY 触线即停（主护栏）**——依据 1.9 CNY/h×8h≈15；**触线行为=拒绝自动拾取新任务·在跑轮次跑完不中断**（不杀进程防半成品）
3. **L3 ≤8 轮/日（双保险）**——触线=硬停+升级报 COO+CFO（非仅告警）
4. **余额门分层**：自动链路 **<30 CNY 停**（高于人工 <20·无人值守不可即时干预+可能批量触发）；**检查时点=拾取时**（TriRMC 拾取前查余额 <30 不拾取·任务留树不丢候人）
5. **fail 形态分化**：人工在场可 fail-open（402 兜底）；**无人值守 fail-safe——余额取不到只允许 1 轮试探后停**+连续 3 次失败升级告警
6. **成本可见性**：cost-log 每行增 `trigger=auto|manual`+task_id/树指针·日报双列（自动链/人工/合计）·自动链占比过快上升=预警
7. **内在依赖如实呈**（CFO）：额度自管=无充值自动回路——余额耗尽时自动链路自然停摆（API 402 兜底·不会无限烧）·恢复依赖 CEO 自管动作·30 CNY≈16h 预警量级

### 决议己 · COS 代批权护栏（本席自省 × CAO 六款合并·CHO 岗位面到面后复核）

**定性**（CAO）：「COS 代批 test/prod」**非新授权**——是 D-39 现行口径（2026-11-04 收口勘正：除三类外一切裁决归 COS）在 loop 批面的具形。

1. **分档批权**：debug 态=CEO 批（故障态多涉保留权）／test·prod 态=COS 代批（常规改造）
2. **COS 必回呈六项**（D-39 三类枚举化不扩张判据）：①重大不可逆 ②系统硬约束冲突 ③CEO 保留权 ④**改 loop 机制本体**（状态机/评分口径/阈值——机制自改机制必 CEO 面）⑤评审异常态（缺席未补评/分歧≥2 席未收敛/零变动告警未回应）⑥超派工批面
3. **代批五要件缺一无效**：批件落卷+三类判据零命中声明+「COS 代批」显式字样+时点+入台账——**缺一拾取面不得拾取**
4. **误批三型责任**：应回呈未回呈=COS 责／边界不清=回 CAO 铸条／任务书造假=主笔席责
5. **事后呈报知情+CEO 可翻案**
6. **评批分离（关键）**：同一主体不得既评又批——**COS 主笔任务书则批须回 CEO 或另指**（防自评自批·D-47 防自改考卷同理）——本席汇总定形卷=任务书主笔面，**故本批任务书的批权不在 COS 而回 CEO/另指**（自守）

### 决议辛 · 自动拾取纪律五款（CAO）

1. **缺批不拾取**：拾取面验批据字段·fail-closed 不靠自觉
2. **四段留痕齐=可回放**（拾取/施工始/逐段毕/点火）——缺段=自动停面
3. **停损三硬线**：异常即停警报不闯关／点火前置=施工全绿+验收锚齐机械可判／**连续轮零分数提升=自动停止**（防空转·CAO 与 CFO L2/L3 同向）
4. **审计**：自审卷+三席随时抽查权+抽查本身留痕
5. **面域**：D-83 款 4 河源现位（任务书评审批在本地域·两地分离）

### 决议壬 · D-85 衔接判定（CAO·形式张力解消）

- **判定=不冲突但须显式声明**：loop 内 7 席联审=**D-85 评审门等价形**（评审主体七席/意见独立/聚合决议/留痕齐全**四要件同构**）→loop 尾段出任务书合规非违例
- **三段映射**：需求=improvement_opinions→评审=7 席联审→任务书=评审产出经批放行
- **反向护栏**：四要件缺任一→该轮产出**不得称任务书**（降级「意见汇总」须补评审）——防「假联审真直出」
- **D-39 防误读注**：不得以「loop 特殊」扩大代批范围·debug 一律回 CEO
