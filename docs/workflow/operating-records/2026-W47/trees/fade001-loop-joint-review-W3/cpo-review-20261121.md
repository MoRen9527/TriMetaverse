## §一 · 七席评审卷格式（统一形·每席一卷）

- **文件形**：`<seat>-review-r<N>-<YYYYMMDD>.md`（本卷=W3 轮 CPO 卷）+ 元信息头（sourceOfTruth/syncMode/lastSyncedAt·卷面时戳锚=git commit 时戳[D-47 增补款正形]）。
- **卷体五段（缺段=退回）**：①席别+评审对象（轮次/被评版本/被评锚=commit）②评分卡（100 制·dim 表）③意见台账（编号/类型/条目/处置要求）④结论（达线/带条件/不达线）⑤依据（逐条引锚）。
- **弃权形（②七席必须七席的守门件）**：席位缺席/超时=卷内显式标「弃权（无意见）」——**弃权不得折叠为默认通过**，本席不交卷=不达线（防两席形悄悄复活）。
- **意见类型二值**：`红线`（阻断项·须闭环）/`改进`（建议项·可延下轮验证）。

## §二 · 100 制评分卡形（⑥·每席一张）

- **每席总分 100·dim 结构=各席自定 3-5 项（域视角）+ 三条共同硬锚**：①首项必为「本域核心判据」（该席最擅长判断面）②证据锚必附（commit/卷位）③红线项不折算（见 §五）。
- **不建议跨席统一 dim**：七席价值=视角差（CEO ②初衷）——统一 dim 会产出七份同质卷，反而退化回两席质量。
- **换算**：dim 原始分×权重→归一 100；dim 权重与取值理由须卷内显式（可复算）。
- **聚合（放行判据）**：**全席达线制**——7 席**每席 ≥95** 才算本轮达线（直接对接 CEO ③「test >95→prod」与「prod ≤95→test」）。并陈两读数：**最低席分**（放行判据单值·防均分掩盖）+**均分**（趋势读数·⑧「分数须提升」的观测值）。不用平均制——平均会把单席红线稀释掉。
- **单席分档**：≥95 达线／90-94 微差（仅改进项·下轮验证可放）／80-89 明缺（必回修）／<80 不成立（回 debug 联审）。

## §三 · 意见带入下轮 + 评审 catch 机制（⑦·需求形）

- **意见编号=跨轮主键**：`R<N>-<席>-<序号>`（如 R3-CPO-01）——台账逐条编号，禁自由文本流失。
- **下轮卷首「应答矩阵」=强制段**：逐条对上轮意见→采纳／不采纳（附理由）+落点（commit/卷位）——**红线条目未应答=下轮卷不予受理**；改进项未应答=列入下轮台账续跟。
- **机械 catch 四件（评审机制自补·CEO ⑦「评审本身要 catch」）**：落卷校验——①应答矩阵覆盖上轮意见 100% ②红线条目闭环 ③分数较上轮变化有据（变动归因句）④本轮新增意见编号连续——四项不过=卷退回重出。
- **分数轨迹表（⑧的机械观测面）**：每轮卷附「轮次/各席分/最低分/均分/变动归因」一行——**分数无变动或下降且无归因=评审空转信号**，升级 debug 联审议程。

## §四 · 考卷分形成（①段 3 plan_skill 出考卷·考卷=什么）

- **考卷=既有 rubric 体系的轮次实例化，非新物**：段 3 plan_skill（spawn cos）产出=周迁移 plan 清单+**本轮考卷骨架**（应考项清单+评分卡实例）；段 8 close_skill（spawn cos）收口=判卷结果+意见台账。**出卷与判卷同源一物**（卷号绑 run id），不两套。
- **考卷结构三件**：①卷面结构门=T1 三断言（run 身份/qualify/告警链·零权重判据形）②八族读数评分（A-H·100 分制·首拍/轮拍适配形）③本域主观题（I 族·独立附加分面）。
- **铁律**：**出卷≠改卷**——考卷内容变更走一次改卷制（注记位填充≠改卷生效·生效锚=施工验收毕）；**轮内不得改卷**（防考空/防改卷迁就分数）——本轮首跑即锁卷。
- **考卷与评审卷关系**：考卷=被判对象（器件）；七席评审卷=判官卷（人评）。两卷分离：考卷由段 3 生成·七席卷由各席独立出具（禁互看）。

## §五 · 评分暴露与否决换算口径（BOD ④）

- **评分全暴露**：7 席分数与 dim 明细互读公开（无暗票）——对齐⑤「T1-1 正则拒判不应折算遮掩」的同源精神：**一切判断显式留痕**。

## §八 · 任务书形（CEO ④新建议·二轮征集 16:57 应答）

**联审意见→任务书的内容形（最小 schema 五段+一列）**：

1. **头部（机械可读段）**：任务书 ID=`r<N>-task-<YYYYMMDD>`（轮次锚）；来源=本轮评审卷锚（意见编号全集）；**审批面字段**=debug→「CEO 批」／test·prod→「COS 代批」（批语+时刻必填）；**拾取路由字段**=TriRMC face 路由（挂周平面供自动拾取）——**自动拾取前先校验审批面字段：无批=不拾取**（自动拾取不得绕过审批门）。
2. **改造项清单**：逐条=意见编号（`R<N>-<席>-<序>`）→改造动作→落点（文件/模块）→依赖。**红线条目必全带**；改进项可裁量取舍，但须标「采纳/延后/不采纳+理由」。**不夹带**：未入本轮评审的改造项不得进任务书（D-39 附款任务书纯净性同构·候选件留候选面）。
3. **验收锚**：每条改造项对应可机械复算判据（对齐 LG-096 验收锚五条先例形）。**与考卷的关系（单向下行）**：**考卷应考项 ⊇ 任务书验收锚 100%**（任务书验收锚=考卷应考项的施工侧预报；考卷漏考任务书验收锚=考卷缺陷退卷）；反向不要求（考卷含常驻项 T1/八族等非任务书内容——常驻门恒在）。
4. **回滚位**：最小形=整单一个基线（commit/配置快照）+逐项回滚动作+回滚触发判据（何时回滚）。改造项可分项回滚的逐项列。
5. **弃权/否决显式段（不折叠）**：弃权席=「弃权（无意见）」原样列（不折为通过）；否决/阻红线=编号+证据锚+最小修复建议，**未闭环不得进施工**；若审批面明示「带条件批」→列条件+解除判据（条件未解除前对应项施工态=pending）。
6. **状态列**：pending／施工中／验收中／毕——任务书毕=三项齐（改造毕+点火跑 run id+新卷骨架锚）+回填 DEM-017 状态列（池行沿革）。

**自动拾取后的验收衔接**：

- 改造完→点火跑=**新一轮 r<N+1> 考卷出卷**（段 3 出卷·卷号绑新 run id）——**改造完不自己判自己**：点火跑是新一轮评审的输入，判卷归新一轮七席。
- **轮次编号延续**：r<N+1> 关系=评审轮;run id=执行拍（一轮可多拍·卷绑 run id 集合）——双键并存，轮次问「进化到第几轮」、run id 问「哪一拍」。
- **防自评**：本轮施工席不参与该轮判卷（评审独立性）；FUSE 融合意见作新一轮考卷应考项来源之一。
- **验收判据=新一轮全席达线制 ≥95**（承 §二）——不是「改造完即过」，而是「改造完→新卷考出 ≥95 才算过」。
