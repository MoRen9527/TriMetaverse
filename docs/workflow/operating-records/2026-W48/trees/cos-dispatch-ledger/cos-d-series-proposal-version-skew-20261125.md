## §三之二 · 判据精化（CAO 2026-11-25T04:51 精化·**原形会误报·必改**）

**原形问题**：「数据件 mtime > 链启动时间 → 告警/阻断」**混淆两种情况**：
- **件 mtime 晚于链启动 = 运行期更新（正常并行）**——**不是旧版**（链启动时读的可能是对的·件是跑起来后才改的）
- **真信号 = 「启动时本地版本落后于远端」**——pull 滞后/未 pull

**精化后判据**：
- **主判据**：`git fetch` 后**本地 HEAD 落后远端**（或数据件所指 commit 非远端最新）
- **mtime 仅辅助**（pull 后件未被改时可用）

**为什么必须改**：照原形落码，**每条正常并行的链都会被误报「版本时差」**——**误报多了机制就被无视**（同族「静默席不得被报」风险·tick 自检反例）。

**strict 形建议**（CAO 入卷·候 CEO 定）：**关键件（families/RACI）阻断·非关键件告警**——理由=「静默用旧件」默认不会被人发现。
