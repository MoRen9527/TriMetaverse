## §一 · 责任席字段（最小集·与 RACI 确认形一致）

| 字段 | 必填 | 说明 |
|---|---|---|
| `owner_seat` | **必** | 唯一主责席（=accountable·RACI confirm 同形）·七席+执行席枚举 |
| `backup_seat` | 选 | 缺席代行·**代行者不得对 owner 自维行使 A**（回避条款同构） |
| `responsibility_face` | 必 | 责任面分类（迁移/评审/批权/值席/岗位类）·防「主责一人但责任面含糊」 |
| `depends_on` | 选 | 前置任务书/挂账号 |
| **五件套关联** | **不内嵌·只指针** | 任务书=执行授权件·五件套=岗位真源——两物不混写；岗位变更类须载「源侧包增量清单+六环指针」（见 §二） |

## §二 · 岗位变更类任务书（硬要求·缺一不过门）

1. **令源锚**：CEO 批令/DP 号（D-88 挂账前置）。
2. **变更面清单**：动哪几件（agent-body/合同/roster/registry）+ 源侧 diff 预期。
3. **六环验收链**（source→support→binding→live→manifest→governance）逐环责任人+验证锚——**「已更新源侧」≠「已完成 live 变更」**，须显式列：发布副本同步项+制度化回填项（正例=COO 运维职责 ba1382c→1f2306310→6a74d588e→6cf248a 四锚）。
4. **生效条件行**：如「经 CHO 交接验收+CAO 制度化后生效」——防源侧改即宣告生效；岗位变更类**强制双签**（CHO 交验×CAO 制度化），禁单人闭链。

## §三 · 复杂度判定的组织面（三判据任一命中=复杂）

1. **跨席 ≥3 席**（跨 2 席=可由 owner+协作闭环，单任务书够；≥3 席起需排程面+交接面）；
2. **含岗位/编制/授权变更**——不论跨几席（单席执行但影响面是全员·必复杂形）；
3. **含不可逆/生产点火/门禁变更**（D-39 三类面·必复杂形+CEO 批）。
—— **跨席数只是三判据之一**：组织面的真实复杂源=「变更影响席位数 × 是否触治理面」；反向不复杂形亦机械（单席/单模块/可回滚/无岗位变更 = 四项全中才可简单形）。

## §四 · 交接 checklist 是否进 schema —— **分形**

- **不复杂任务书**：不内嵌全 checklist（过重违原则①），但**必留最小交接三问**（前手/后手/遗留件去向）= 3 字段 micro-checklist，防裸交接；
- **复杂任务书**：**必须**附 handoff checklist（十项·引 `chief-human-resources-officer-handoff-governance.md` §4）+ 状态机引用（同件 §5）作为附录卷指针。
- 理由：交接断点是复杂度放大器——简单形用 3 字段防裸交接，复杂形用全 checklist 防断链。
