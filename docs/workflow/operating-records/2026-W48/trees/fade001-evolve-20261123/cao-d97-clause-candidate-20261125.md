## 一 · 条款正文（候选·五款）

### D-97 版本时差 preflight 检查——数据件版本落后即报·防「读旧版跑」（2026-11-25，COS 建议·BOD 转·CAO 铸条）

**案由**：今日**三坑同源**（resume26 owner 映射未覆盖／resume28 两件 owner='' 漏／resume27 第三次）——共同根=**链启动时读的是旧版数据件，而数据件在链跑期间被更新**，无时差检查 → **静默用旧件**。另同族「读旧版」3 例（CHO 读旧版 D 族／CTO、BOD 各一）。

1. **检查项（preflight 增）**：链启动前，对**本轮声明的数据件输入**（families/RACI/plan 输入等）做版本时差检查——**本地件版本 vs 远端最新版本**。
2. **判据（本席精化·防误读）**：
   - **正形判据**=`git fetch` 后**本地 HEAD 落后远端**（或数据件所指 commit 非远端最新）→ **声明该件「可能旧版」**；
   - **误读防线**：COS 原表述「数据件 mtime > 链启动时间」**须慎用**——件 mtime 晚于链启动=**运行期更新（正常并行）非旧版**；真信号=**「启动时本地版本落后于远端」**。**mtime 可作辅助（若件在 pull 后未被改）·主判据用版本比较**（技术形归 CTO 定）。
3. **处置分级（strict 形候 CEO 定）**：
   - **告警（warn）**：声明「版本时差：<件> 落后远端 <n> 提交——链可能用旧版」+建议 pull 后重跑；
   - **阻断（strict·本席建议）**：若该件为**本轮关键输入**（families/RACI 等直接决定判据者）→ **阻断启动**（强制 pull）——理由：**「静默用旧件」是默认不会被人发现的错**（今日三坑全是事后才发现），**故关键件应阻断·非关键件告警**。
4. **同族定位**：**D-47**（时点面·怎么写时点）× **D-92 款 1**（时效状态查·转引前人工查现状）× **D-97 本条**（数据面·preflight 机器自动查）——三条构成「时点纪律三面」：写对、查对、**跑前自动验**。
5. **效力边界如实注**：本条=**纪律层+机械候选**（preflight 检查项实现归 CTO/SDE 施工面）——实现落地前依赖人查（今日三坑证明人查有漏），落地后转机械面（照 D-91 两阶段形·禁打包宣称）。
