## §一 · 格式对执行的影响（拆树/派工/进度跟踪需要什么字段）

| 执行环节 | 必需字段 | 缺失后果 |
|---|---|---|
| **拆树** | `目标`／`verify（可机械判）`／`依赖` | **无 verify=树无法拆到节点**（D-27 v4 树节点验收=verify 投影） |
| **派工** | `owner_seat`（唯一）／`工作量估计`／`权限门`（谁批） | 无 owner=孤儿件；无估=批不可分批 |
| **进度跟踪** | `item 状态五态`（D-88）／`证据锚`／`盯办席`（今日新建列） | 无锚=闭环不可验（「已发≠在链」族根因） |

## §二 · 复杂度判定建议（谁判·阈值）

- **谁判（本席建议四段）**：**CPO（产品面）＋CTO（技术面）联判** → **COS 复核**（编排面可否拆）→ **CEO 终裁**（争议或超三类保留权）。**执行编排视角=本席只给判据不占判定权**。
- **机械判据（建议：命中任一即 complex）**：
  ①**跨席 ≥3**（owner 席位≥3=多线程协调需求）
  ②**改动面 ≥双文件+跨仓**（单文件或单仓=simple）
  ③**依赖深度 ≥2**（item A→B→C 链）
  ④**预估 >1 席日**（≈4-6h·超=分批需要）
- **防复杂度膨胀**：**默认 simple**·超阈值=**PRD 产出义务**（complex 件无 PRD=任务书 fail-closed 拒收）。

## §三 · 简单 vs 复杂的执行差异

| 面 | simple | complex |
|---|---|---|
| **执行体** | **单席直干**（owner 一席·D-27 v4 直派·不挂树） | **多席并行+树协议**（挂周平面·face 路由·自动拾取） |
| **批次** | **单批**（≤3 items·一 commit） | **分批**（每批 ≤5 items·**批间可验**·序=依赖拓扑） |
| **任务书表达** | **完整 schema**（五字段 verify 齐·产品/技术方案内嵌） | **索引+摘要**（charter_id+PRD 指针+技术方案指针+树指针；摘要=范围/验收/分期） |

## §四 · 建议字段（含执行序/依赖/批次）

**通用必填**：`item_id`／`owner_seat`（唯一）／`verify`（**可机械判**·无=拒收）／`rollback`／`依赖`（items 或前置件）。

**编排扩展（本席建议新增五列·随 D-88 台账一体）**：
| 列 | 语义 |
|---|---|
| `执行序` | 批内序 + 批间门（批毕验通过才开下批） |
| `批次` | 批号 + 每批件数上限（simple≤3／complex≤5） |
| `盯办席` | 运维 owner（默认 COO）·巡拍节律 |
| `复杂度标签` | **simple｜complex（头部必填）** |
| `PRD 指针` | **complex 必填**（`docs/…/prd-xxx.md#anchors`）·**无指针=拒收** |

**落盘一致性注**：复杂度标签=**任务书头部单值**（整卷级）·非逐 item——**一任务书=一复杂度**（混装=拆卷）。
