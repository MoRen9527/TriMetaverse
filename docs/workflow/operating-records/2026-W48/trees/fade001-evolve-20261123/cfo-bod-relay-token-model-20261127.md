## §二 · 账一 · bod 省多少

**bod 跨会话通信的 token 构成**（今日 151 封信）：
- **发信构造**：151×612 字符 ≈ 92K 字符 ≈ **~30-45K tokens**（output 侧·含 SendMessage 调用结构）
- **回执入上下文**：**这是大头**——每封信的回执（含 cross-session-message 包装、交付通知、后续往来）全部进入 bod 上下文。今日 bod input 6.77M 中，**按往来密度估 30-50% 与跨会话通信直接相关**（≈2-3.4M input tokens·其中大部分是 cache_read）
- **每次发信的 turn 级开销**：SendMessage 工具调用本身+等待回执的轮次

**估「全改 COS 代发」后 bod 省**：
- **output 侧省 ≈30-45K/日**（不再构造发信）
- **input 侧省更多**：不再收各席回执（回执改走 COS→bod 的摘要）——**估省 30-50% 的 input 侧通信相关量 ≈ 0.6-1.7M tokens/日**（cache_read 主导·按积分系数折算价值有限但绝对量大）
- **百分比**：bod 今日 input 6.77M 中省 0.6-1.7M ≈ **9-25%**；output 530K 中省 30-45K ≈ **6-8%**

## §三 · 账二 · COS 增多少

**代发代收的增量构成**（每封信 COS 侧四步：读 bod 原信→构造转述发他席→收他席回执→回 bod 摘要）：
- **151 封/日全走 COS**（假设全部通信量转移）：
  - COS 读信：92K 字符 ≈ 30K tokens（input·cache 命中后增量小）
  - COS 构造转述：151 封 × 转述 ≈ **+25-40K output tokens/日**
  - COS 收回执+回 bod：151 × 摘要 ≈ **+20-35K output tokens/日**
- **COS 增量合计 ≈ output +45-75K/日 · input +30-60K/日**（cache 命中主导）
- **COS 是 5.4 席**：按官方系数 Output=16（flash=4·**4 倍价**）——**45-75K output 在 COS 是 5.4 价·在 bod（flash）只是 4 价**→ **同一封信转经 COS 的 output 成本 = 4×**
- **积分增量估算**（按系数）：COS 日增积分 ≈ (30-60K×4.6 + 45-75K×16)/10000 ≈ **+58-134 积分/日**（未经非高峰 50% 折算·全按基础）

## §四 · 账三 · 净额与建议

| 项 | bod（flash·省） | COS（5.4·增） |
|---|---|---|
| output | 省 30-45K/日 × 4 系数 = 省 12-18 万「积分当量」 | 增 45-75K × 16 系数 = **增 72-120 万「积分当量」** |
| **净额** | **COS 增远大于 bod 省（≈6-8 倍差）·总额变负** | |

**关键不对称**：**bod 用 flash（4 系数）·COS 用 5.4（16 系数）——同一封信经由 COS 转发·output 成本直接翻 4 倍**。bod 省的是 flash 价的 30-45K·COS 增的是 5.4 价的 45-75K——**积分数值上 COS 增 = bod 省的 6-8 倍**。

**结论：按纯 token 成本——「不值」（净增）**。但有三个前提可能翻盘：
1. **若 COS 增量把它推近 5.4 周窗红线**（COS 是重度席·加 45-75K output/日 ≈ 每日多烧周窗 ~1-2%·5 天窗内累计 ~5-10%——**有风险但不致命**）
2. **若 bod 换 copilot 后系统提示/工具面本身变小**（无 SendMessage 工具定义=每 turn 的系统提示省一点·**量级小·非决定性**）
3. **若 bod 的通信量继续增长**（今日 151 封若翻倍·bod 省的绝对量同步涨·但 COS 增也同步涨·**净额比例不变仍为负**）

**建议**：
- **纯成本视角：不建议改**（净增 6-8 倍·由 5.4 价的 COS 承担）
- **若 CEO 的动机是「bod 宿主轻量化」而非省 token**：copilot 宿主的工具面/系统提示变小有长期维护收益·**token 净增是它的代价**·值不值取决于宿主收益权重（本席不裁宿主选择·只给成本面）
- **若一定要改·降增量的形**：COS 代发用**摘要式转发**（不全文转述·只转要点+指针）→ COS output 可压一半以上；或**他席回执直落卷·bod 读卷**（COS 只发指针）→ COS 回 bod 的增量再省

## §五 · 口径与局限（如实标）
- 样本窗=今日单日·往来密度有日间波动（今日偏密集·151 封可能高于均值）
- 「通信相关占比 30-50%」是**按往来密度估**·非逐条归因（bod 的 6.77M input 里有多少是纯通信·需逐条 tagged 才能精确·成本高于本建模本身）
- COS 今日 records=31 是**低值**（其 394MB 是多日累计·今日段恰逢低活跃）——**若 COS 常态活跃度更高·其边际增量占比会更低**（在已有上下文流上叠加·边际缓存命中率高）·**此方向利好净额**·如实并列
- 全按「基础积分」算·未用非高峰 50% 折算（两种时段都会同比例影响两方·净额比不变）
