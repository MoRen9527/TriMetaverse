- lastSyncedAt: 卷面时戳锚=git commit 时戳（零手打·D-47 增补款正形）
- 令源: CEO 02:1x 原话（BOD 转 02:20）——「score skill 是处理语义等主观问题，你的采集都走机器，就让 cos 和 coo 评个分，那直接走 score cli 不就完了么？score skill 设计的意义在哪呢？…说说你们对 score cli 和 score skill 设计的初衷和他们应该在周迁移工作发挥什么作用」

## §一 · score_cli 的设计初衷

- **判什么**：机械可复算的客观面——存在性（件在不在）/计数（几件几行）/断言（verdict 映射）/run_id 匹配。落到周迁移=段产物是否落位、七段 verdict、采集族 A/F/H 的 pass/fail 映射。
- **权重如实注（两版在卷）**：engine L79 现役形=采集 A/F/H 31 分+主观 I 10 分；ns2 卷 weight_face=objective_machine 65+I 族 35——两版口径并存，合并形以现役 rubric 为准确认（本席不代定权重·只定判者归属）。
- **依据**：数据本身（可 grep/可解析/可复算），无需解释。
- **判不了什么**：需要「理解意图」的题——「清单对不对（不只是有没有）」「规划合不合理」「执行严不严谨」「证据是否充分」。机器只能判「有清单」，判不了「清单该不该这样」。

## §二 · score_skill 的设计初衷

- **为什么需要**：协议 v2.0.5 设计思路原话=「**语义类程序无法判故需 agent**」（三件套=做考题→交答卷→得分的大模型评测打榜方法论）。主观题（I 族）确实存在且机器给不了分。
- **判什么（现行实锚）**：I1 计划清单判定正确性（12/14）/I2 规划合理性（9/11）/I3 判断提炼质量（9/10）——**判的是「好坏」不是「有无」**。
- **为什么必须是席不是机器**：这三题要求**读卷+推理+是非观**；且 spawn 席位=有本域上下文（COS/COO 知道迁移链的坑在哪里）。机器判=只能退化成关键词匹配（假分）。

## §三 · 分工边界（哪些机器判·哪些席判·重叠/真空）

| 面 | 判者 | 例 |
|---|---|---|
| 客观面 | 机器 | 件存在/计数/verdict/run_id/断言 |
| 主观面 | 席 | 规划合理性/判定正确性/提炼质量 |
| **重叠（现真空）** | — | **I1 判定正确性≈可对表**（plan vs 实际迁移结果，机器可算）；**I3 提炼质量≈可对表**（evidence_ref 覆盖率，机器可算）——**这两题现在由席判，但有部分可机械化** |
| 真空（无人判） | — | 跨件意图对齐（多件组合后的整体合理性）——现既非机器题也非主观题 |

## §四 · 在周迁移工作中的应有作用

- **score_cli**：每轮**自动跑·零人力·确定分**——客观分是每轮必得的底线读数（迁移成不成先看它）。
- **score_skill**：在**主观题不可机械化的残余面**给分+**给理由**（rationale）——语义分不只是分数，是**改进项的原料**（charter items 来源）与**机器判据缺陷的探测器**（席判 vs 机器采集的差异=发现机器判错的地方；今日多起踩坑即人发现）。
- **配合形**：cli 先跑（客观 65+采集 31）→ skill 跑主观（I 族 14+11+10）→ 合并 100（total_basis 现役形）。

## §五 · 若采集全机器化，score_skill 的价值主张（正面答·不绕）

**诚实结论三句**：
1. **如果一道题能被可复算判据判，它就不该由席判**——按 CEO 的问题：让 COS/COO 评个分，如果这分机器给得出，那直接走 score_cli 是对的，**score_skill 缩到零题时它就应取消**（工具存废按题的可机械化边界，不按习惯）。
2. **但「残余不可机械化面」现在真实存在**：规划合理性（I2）——「为什么这样规划」「有没有更好的排法」=需要理解与判断，机器给不出可信分；这类题的分数**只能**由席给，且其**理由是改进的原料**。
3. **score_skill 现在的问题是边界没被审视**（与我今日「不审视默认形」同病）：I1/I3 有部分可机械化（对表可算），却仍全量席判→看起来像「让两席徒手评个分」=CEO 说的别扭感来源。**正解=按题审视**:可机械化的题收回 score_cli（I1 部分/I3 部分→对表判据），**只留真正不可机械化的残余**（I2 类）给席判——届时 score_skill 价值主张=「不可机械化语义面的唯一可信判者+改进原料供给者」，不成立就取消。

## §六 · 一句总答（给 CEO）

**score_cli=判「有没有/对不对表」，score_skill=判「好不好/为什么」**——前者每轮必跑，后者只该在「机器给不出可信分」的题上存在。**现在的问题是后者还包含可机械化的题（I1/I3 部分），使它看起来像多余工序**——把它缩到真残余，它的意义才立得住；缩到零，就该废。
