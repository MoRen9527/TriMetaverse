## 1. 本周项目背景

本周在 TriCade 装后态（TriPilot 面板 + TriLC daemon）进行 E2E 深度测试，重点是人机协作入口的真实使用体验。测试中 CEO 连续十轮实测暴露出一族高度一致的模型行为缺陷：**长工具链会话的收尾退化**——模型在多轮真实函数调用后，最后一轮以各种"伪工具调用文本"代替真正的 function call 并停在那里，用户看到的是"叙述了一堆、调了一堆工具、最后没有结论"。围绕这一族缺陷，我们建立了一套三层防御体系，本文记录完整的问题演化、修复过程与背后的工程原理。

涉及模块：TriLC（daemon 侧 SSE 流处理）、TriPilot（webview 渲染）、agent-core（共享工具运行时）。

## 2. 本周观察到的大模型能力问题与体验

### 2.1 核心问题：长工具链会话的收尾退化（伪工具调用文本）

- 现象：
  使用 DeepSeek v4 pro 承载总助（chief-of-staff）角色的多步核查任务（典型 15-40 次真实工具调用），模型在会话尾段反复出现四种退化形态，每场会话形态不同、且不断发明新变体：
  1. `[tool_use name=Read]` ——方括号族的工具调用文本模拟；
  2. `[｜｜DSML｜｜tool_use LS]`、无限重复的 `</｜｜DSML｜｜parameter>` 闭合标签洪水（单回合流式输出数分钟不停，观感如死循环）；
  3. `<invoke name="shell_exec"> <parameter name=...>` ——XML 族调用语法（Qwen 风格）；
  4. `[调用 shell_exec] {"command": ...}` ——学舌宿主 UI 自己的文案造的变体。
  此外还有两种"无语法"退化：工具后**纯静默**（叙述→工具→沉默，被判成功）；以及**纯承诺式结尾**（"最后确认一下 git 工作区"——说了要做但什么都没做，也没给结论）。
- 根因分析：
  - 模型侧：长多轮工具对话后，provider 的工具调用格式在上下文中高度富集，模型的生成分布"溢出"到 content 通道——把工具调用协议当成正文写出来。这是 reasoning/tool-use 模型在长上下文下的已知退化模式（格式漂移/format drift），不是随机故障，同一场会话内稳定复现。
  - 系统侧（我们自己的缺陷放大了它）：初版成功门禁统计的是**累计输出文本长度**，模型工具前的叙述（"让我先看看…"）被算作产出——"叙述→工具→沉默"被判成功；伪工具文本也是"有文本"，同样骗过门禁。
- 解决方案（三层防御，详见 2.2-2.4）：
  流中掐断 + 事后门禁 + 强制收尾，全部落在 daemon 侧（单一执行体），对客户端透明。
- 问题影响：
  不修的话，Agent 的每一场多步任务都有概率"空转完毕"——用户等了几分钟，看到一堆工具卡，最后没有可用结论。这是人机协作产品可用性的硬伤。

### 2.2 防御一：结构化检测（形状匹配取代枚举）

- 问题：
  最初逐个枚举变体拼写（`[tool_use name=X]`、`[工具输入]`……），每轮 CEO 复测模型都发明新拼写，枚举必输——典型的 whack-a-mole（打地鼠）反模式。
- 修复：
  观察到所有变体收敛为**两族形状**：
  - 方括号族：`[短标签] + 紧跟 { 的 JSON 载荷`——标签限字母/下划线/中文/空格（≤32 字符），字符类天然排除代码下标形态（`dict["key"] {`、`arr[0] {` 不误伤）；
  - XML 族：`<(tool_call|invoke|parameter|function_call)[\s>]`——四个工具标签名单分支。
  按形状匹配后，模型换任何标签词都逃不掉——它只能在两族语法内发明拼写。
- 涉及的理论/知识：
  - **结构化匹配 vs 枚举匹配**：对抗性输入（adversarial input）场景下，防御规则应匹配输入的"结构不变量"而非表面拼写。这与安全领域"攻击载荷变形、语义不变"的思路同源（SQL 注入防御从黑名单关键字进化到参数化查询是同一逻辑）。
  - **正则的误伤控制**：放宽匹配面必须配套反例测试（我们维护了 14 条单测，含 6 条反例：正常讨论 `<div>`、代码下标、markdown 链接、普通中文标注）。

### 2.3 防御二：流中掐断（mid-stream abort）

- 问题：
  闭合标签洪水变体在**单个回合内**无限流式输出，等回合自然结束再补救等于陪它死循环——用户看着垃圾刷屏数分钟。
- 修复：
  检测前移到 SSE 事件循环内：每回合维护增量缓冲区，正则一成形立即 `break` 事件循环（labeled break 跳出 for-await）、停止转发后续 delta、从累计产出中剥除该回合文本、用干净的重建 transcript 进入强制收尾。检测无缓冲阈值，泄漏缩到模式本身（约十几个字符）。
- 涉及的理论/知识：
  - **流式协议的事件不可撤回性**：SSE/WebSocket 已发送的帧无法回收（没有"撤销帧"），所以防御目标从"消除泄漏"降为"泄漏最小化 + 明确分隔"——已泄漏碎片后强制结论带 `\n\n` 分隔。这是所有实时流系统（直播弹幕过滤、交易风控）的共同约束。
  - **生成器协议（for-await-of 的提前退出）**：JavaScript 异步生成器的 `break` 触发 `generator.return()`，这是消费侧中途终止生产侧的标准机制。

### 2.4 防御三：强制收尾（forced conclusion turn）

- 问题：
  两种"无语法"退化没有工具语法可检测：纯静默（工具后零文本）；纯承诺式结尾（短文本 + "让我/接下来/最后确认一下…"意图尾缀）。
- 修复：
  - **重建 transcript**：daemon 侧从观测事件（assistant_message/tool_result）重建完整消息历史；
  - **无工具模式补一轮调用**：检测到无结论时，用重建的 transcript + 针对性纠偏指令（"你最后一条消息只描述了接下来要做什么，没有给出结论。请立即给出最终结论，不要再调用工具、不要再描述计划"）额外调一次模型，**不传 tools**——模型物理上无法再工具调用，只能产出结论文本；
  - **承诺式检测启发式**：短文本（<150 字）+ 行动意图尾缀（让我/我先/接下来/继续/最后/再查/下一步…）+ 无结论标记（结论/综上/已完成/通过…）→ 视为无结论。
- 涉及的理论/知识：
  - **约束驱动的输出整形**：不给工具列表 = 从能力面上移除工具调用选项，逼输出分布收敛到纯文本。比"恳求式 prompt"（"请不要调用工具"）可靠一个数量级——前者是结构约束，后者是软建议。
  - **启发式的精度/召回权衡**：承诺式检测会漏（长承诺文本）也会误（罕见结尾撞词），但误伤代价只是一次额外的收尾调用（结果仍是正确结论），漏检由下一轮人测兜底——**代价不对称时，启发式优于不设防**。

### 2.5 配套修复：这一族问题牵出的工程缺陷

- **事件重复发射（文本翻倍）**：agent-core 每轮同时发 `content_delta`（流式增量）和 `assistant_message`（完整内容），daemon 的处理分支无条件转发后者——每句话面板收到两遍。修复：按轮 `hadDeltaSinceLastTool` 标志去重。教训：**流式 + 批量双通道协议必须有幂等合并点**。
- **工具卡永远"运行中"**：客户端 begin 事件用随机 UUID、end 事件用会话短 ID——id 永远配不上。修复：daemon 事件携带 agent-core 的真实 `tool_call id`，两端配对。教训：**异步事件的关联必须用生产侧的稳定 id，不能用消费侧的临时 id**。
- **工具耗时恒 0ms**：agent-core 的 `tool_result` 事件不带耗时字段，daemon 兜底发 `?? 0`。修复：daemon 侧按 tool_call→tool_result 时间戳差自计。教训：**跨层字段契约要验证真值，`?? 默认值` 会把"缺字段"静默变成"合法的 0"**。
- **Windows 中文乱码**：cmd.exe 中文输出是 GBK（cp936），工具层按 UTF-8 解码成乱码。修复：严格 UTF-8 解码失败回退 GBK（Node 22 全 ICU 的 TextDecoder）。教训：**跨进程文本必须显式编码协商**，Windows 子进程的 locale 编码是独立于 Node 默认值的。
- **参数展示退化成逐字符索引**（`LS: 0: {, 1: "`）：工具参数是 JSON 字符串，客户端二次 stringify 后解析回字符串，`Object.entries(字符串)` 得到字符下标对象。修复：daemon 发送前解析成对象 + 客户端双层解析防御。

### 2.6 渲染层的配套迭代（体验侧）

工具卡从"一个聚合卡"迭代为"步骤组卡"：叙述回归正文文本卡；工具聚合为一张默认折叠的组卡，组头是**动态状态摘要**（旋转图标 + `正在调用: LS: xxx` → `✓ 已调用工具（5）: LS×3 · Read×2`）；卡内输入逐键值展示、输出按结果结构分流（Read 显文件内容 / LS 显排版表格 / shell 显 stdout/stderr/exit 分段）；结论 markdown 流式渲染（120ms 节流）消除"先原始格式后渲染"闪跳。另提供 `/demo-tools` 本地演示命令——不走 daemon/模型，驱动同一渲染管线，既是体验演示也是渲染回归测试。

当前经验：

- 项目经验：模型行为防御要做在 daemon 单一执行体上（对两入口透明）；每轮修复配 live 复现 + 反例单测；变体逃逸一轮收敛一次，两族形状收敛后已三轮无新逃逸。
- 通用经验：长工具链 Agent 的"收尾"是独立的可靠性问题，需要显式的结论保障机制（检测 + 兜底生成），不能假设模型自然会收尾。
