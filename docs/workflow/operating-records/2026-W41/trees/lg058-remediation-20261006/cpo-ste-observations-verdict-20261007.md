## 逐条裁决

### B · boot 型键「已落生效」语义提前（STE 原文：候 CPO 定）

**裁决：采「注记」案，不采「按键型分列」案。**

- 三态徽章对 boot 型键（11 键全 boot 型，readEnv 仅 boot 调用一次）显示注记：徽章文案「已落生效」改为**「已落 · 重启生效」**（或徽章旁固定注记行「此配置项重启后生效」，二选一由 FSD 按布局空间定，语义锚=「重启生效」四字必须在）。
- 不采分列：把 boot/runtime 两类键拆区显示=IA 复杂化，换来的区分度逐键注记同样给到；11 个键不值得为键型立一个新分区维度。
- 产品理由：诚实三态的本分是不误导。「生效」二字对 boot 型键撒了半个谎——用户改完看到「已落生效」以为立即生效，实际要等重启，这比没有状态徽章更糟（假安心）。升版流水线含 restart 步即效，故流水线场景不受影响，受影响的只是单键直改场景。
- 边界：热加载（改完即效不重启）是 daemon 能力项，归 CTO 域候维护波另议——产品面只裁「标注先行」，不定工程路线。
- **归批：批 B（10-08 窗），文案级微改。**

### C · 清空语义缺口（STE 原文：候 CPO 补定义）

**裁决：产品语义定谳 + 实现缺口转 CTO + 过渡期诚实注，三件套。**

1. **语义定谳（本卷产品裁决）**：「清空卡面」的语义 = **下发清除指令，机器侧真清除**——daemon 收到 null 应删除对应键组（或恢复该键内建默认值）并推进版本缓存。**不是**「卡面不显示、机器保留旧值」的显示层清除。理由：连接配置页是配置管理面不是仪表盘，用户清空一条配置的唯一合理解读就是「让机器上没有这条」；「卡面已清、机器未清」的分叉态是配置管理面的诚信事故级缺陷。
2. **实现缺口转 CTO 裁修**：landLocalConfig(null) 跳过落地 → daemon 侧 settings.json 永守旧值且版本缓存不推进，与上述语义不符。修法方向（工程量小）：null 时落地=删键/写默认+版本推进。**此项系 CTO 域工程裁决，本卷只交语义与验收判据，候 m-cto 认领排期。**
   > **〔勘正 05:35Z·答 CTO 修法卷 f1517d68〕**上句「工程量小」系产品面越界估，作废——CTO 实勘：根因=key-cache.ts L582 防抖表达式把「同版本防抖 null」与「清空卡 null」语义混同，**清空态现协议下不可表达**（结构性缺口）+L588 缓存保旧/stale 宽限=tier2 复活链实锤；工程量定性=**两端件·中**（半窗可毕，排期 10-09 后首窗不变）。修法正形=A 案协议显式清除指令（`localConfig:{cleared:true,version:递增}`+daemon 清除分支+版本栅栏封复活链）；B 案「缺席=清除」否决——**产品面背书**：把「没消息」当「坏消息」误删生产配置，恰是真清除语义的反面，fail-safe 方向正确。**施工验收锚正身=CTO 卷 §四五条**（我卷 L65 值面断言并入为其第①条；③栅栏断言+④fail-safe 反向锚系增补），本卷 §验收锚第 2 条降为消费面粗锚。
3. **过渡期诚实注（daemon 未改前）**：清空操作后的卡面态必须显示「已清 · 待落地（机器侧现持旧值）」类注记，**禁无提示分叉**。批 B 若赶不上 daemon 修，注记先上；daemon 修毕注记退役。
4. 非阻塞建议（不裁）：兜底模型域的清空确认弹层可附一句后果提示（无兜底时按 daemon 内建降级行为走）——锦上添花项，候 FSD 施工时顺手评估，不做验收锚。
- **归批：语义本卷即定谳；UI 注记随批 B；daemon 行为候 CTO（维护波）。**

### D · 连接配置页切签不重拉（STE 原文：观察项建议二选一）

**裁决：采「切签轻量重拉」，「快照注记」降为回退案。**

- 切域签时轻量重拉一次该域卡数据（GET 一次 face 卡接口），不引入轮询不引入订阅。
- 产品理由：连接配置页的立身之本就是诚实三态的实时性——「已拉未落/已落生效」的判读前提是卡数据反映 daemon 最新回写。daemon 侧回写后切签只见旧缓存，三态语义被静默弱化成「三态快照」。「数据为连接时快照」注记是给弱化打补丁，能不打就不打。
- 回退案（仅当 CTO 判重拉有性能/实现顾虑时启用）：注记「数据为连接时快照 · 重连后刷新」。**两案取舍权在 CTO（实现面），产品倾向重拉已明示。**
- **归批：批 B（10-08 窗）。**

### E · 手填失败文案不告知合法集合（STE 原文：候 CPO 权衡）

**裁决：采。失败文案附目录列表。**

- 手填目录外模型被恰五名目录硬校验拒（LG-035 既有，校验本身不动——白名单纪律保持），但 400 泛化文案「操作未成功」改为**自解释文案**：「模型 X 不在目录内。可用模型：deepseek / glm / trimetaverse / …（五名全列）」。
- 产品理由：合法集合是公开静态清单（恰五名），藏着一个用户必须盲试才能发现的事实没有任何收益；失败文案附清单=一次交互自解释，泛化文案省的那点字数远抵不上盲试成本。与 STE §五.A 注记的 humanize 降级泛化文案问题同族——本条是对该族的针对性修复范例。
- **归批：批 B（10-08 窗），文案级。**
