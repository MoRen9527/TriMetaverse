### 条 5 · 嵌套活动策略+字段组不可懂——信息架构级重设计（核心）

**实勘三区堆叠现状**（CEO「活动策略下面还有活动策略」痛点的结构真因）：

1. L257「活动策略」区：策略下拉+切换/清除按钮+**详情 kv（名称/目的/引用模型集/默认模型/引用规则）**+规则表
2. L270「策略列表」区：表格（名称/模型集/规则数/状态/操作）+新建
3. L286「生效时段规则」区：又一张时段规则表（与区 1 规则表内容重复——副文自证「当前生效=活动策略引用的规则」）

用户读感：区 1 展示一条策略的完整字段（看起来是策略本体），往下又出现一批策略（区 2）——「策略里套策略」；「目的/引用模型集/默认模型/引用规则」四词系数据关系描述（数据库视角）非用户任务语言。

**重设计方案（三块收敛+两步走）**：

- **目标结构三块**：①模型清单（有哪些模型）；②可切换素材（可切换模型集+模型切换规则两子块）；③**切换方案列表**（原策略列表扩权成唯一策略区）。
- **砍独立「活动策略」区**：生效态并入列表——生效行带「生效中」徽章；「切换至选中/清除/应用」按钮移至列表行内操作列；选中行展开详情（原详情 kv 下沉为行内展开）。一处列表同时答「有哪些」与「哪个在跑」，双区堆叠消除。
- **字段用户语言化**（关系词→任务语言）：目的→「用途说明」（选填备注弱化）；引用模型集→「使用的模型集」；默认模型→「默认使用」；引用规则→「包含的切换规则」。
- **砍独立「生效时段规则」区**（即条 7 处置，见下）。
- 两步走显式标注：**一步（建议本周窗）**=砍区 3+区 1 收敛入列表+字段改名（结构中等量，一窗可落）；**二步（候一期效果）**=列表行内展开的交互打磨。CEO 集成裁定时定步。
- before/after：三区堆叠+关系词字段组 → 三块结构+生效徽章行内化+任务语言字段。
- 验收锚：①页面策略相关区块=1（列表）非 2；②「生效中」徽章在生效行可见；③四关系词（目的/引用模型集/默认模型/引用规则）用户可见面零残留；④「活动策略」词汇退役（L2033 注释「词汇定稿」随批反转）。

### 条 7 · 「生效时段规则」概念处理——**裁：融合，不独立成词**

- 实勘：该区与区 1 规则表**内容重复**（同一张表两个标题），副文「只读——规则在『规则』区管理（层2 全量开放中）」自身就背着技术词。
- 裁定：砍独立区，生效规则展示并入条 5 重设计后的列表详情（选中方案的「包含的切换规则」展开即所见即生效）——「生效」是状态不是概念，用户不需要学第三个名词。
- 验收锚：`grep -c '生效时段规则'` 用户可见面=0。

### 条 8 · 总纲立整改原则：技术/运维/过渡态词汇一律不上 UI

- **原则正身**：用户视角优先——每个 UI 词过三问：用户任务里用得到吗（有用）/用户自然语言里有吗（自然）/描述用户看到的结果吗（结果导向）？三问不过=不上 UI。
- **可执行检查项**（结构词汇禁入 UI 纪律升格）：施工批验收新增「技术词扫描」——grep 清单=`层1|层2|过渡位|实例|条目（候裁）|引用|只读|全量开放|v4`，用户可见面（标签/按钮/副文/空态/提示文案）零命中；注释级不涉。
- 本批实勘超令发现（随批一并清洗）：L278「（层2 开放中）」+L279「（层2 开放中）」+L286「（层2 全量开放中）」——三处「层2」技术词漏空态/副文，CEO 未点名但同罪，随批清洗。
- 验收锚：扫描清单 grep 用户可见面零命中（批级验收锚）。
