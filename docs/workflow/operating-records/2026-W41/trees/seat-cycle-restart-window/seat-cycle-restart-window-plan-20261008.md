## 〇、摘要（大白话）

AI 员工的会话进程（claude.exe）长期不关会积累内存（自动压缩只清上下文不还内存给系统），跑得越久越慢。方案=**每周日凌晨给 13 席轮流「关机重启」一次**，挂在周日 23:00 周平面迁移维护窗的后面顺带跑（迁移干完的空档，不新开窗）。重启不是同时全灭——是一席一席来，有任务的席跳过、空了再补。重启后用已验证的复活 SOP 确认 13 席名址全回来。sg 服务器上的 13 席同题，纳入同一晚做第二批，头两轮多观察。预计单席 1-2 分钟，全窗 23:00-00:15 内完。

## 一、背景数据（BOD 10:4x 实勘）

- claude.exe 常驻 14 会话（10-05 起 72h+ 未退），内存 101-415MB/席合计 ~2.1GB
- auto-compact 只压缩上下文，heap 不全量还 OS——周级常驻显化为内存爬高+响应变慢，进程重启=唯一彻底回收
- 工具壳孤儿（conhost）3 天积 7 个（BOD 已清杀复验清零）——成因=工具进程退出后壳残留，周窗顺带扫一遍
- 名址复活 SOP 已实证：清 `CLAUDE_CODE_CHILD_SESSION=1` + 设 `FORCE_SESSION_PERSISTENCE=1` 后代起，03:29 案 13/13 复原

## 三、执行 SOP（窗内序列）

1. **T-30min 预备广播**：执行席向 13 席发「重启预备」令——各席回执自报在途状态+确认工作区零未提交面（D-45 款3「段落毕即 commit」已制度化，正好是本步的制度保障）；未回执席按 transcript mtime 静默>10min 判空闲。
2. **迁移窗毕信号确认**：周平面迁移链完成（周索引件落位/R-HY job 完成日志）后才开重启批。
3. **轮启**：按 §四批表逐席——停进程→清 `CLAUDE_CODE_CHILD_SESSION` + 设 `FORCE_SESSION_PERSISTENCE=1`→resume 起动→下席。
4. **逐席即验**：每席重启毕立即验：a) 名址注册在册（名册核对）b) 首响 ping 一句 c) 内存基线读数记档。
5. **窗毕总验**：13/13 名址复原核对（03:29 验证法）+conhost 孤儿扫描清零+读数汇总。
6. **止损**：单席复活失败→照 local-seat-relaunch SOP 排查（环境变量/剪贴板粘贴键入法）；**连续 2 席失败即停窗保现势**（未重启的席不动），候人工，不顺延硬跑。

## 五、resume 形态裁定（本卷关键技术裁量）

- **resume 优先**：`claude -r <session>` 续 transcript——上下文连续性是席位可用性的第一指标，内存最优让位。auto-compact 后 transcript 本身有限长，resume 加载代价可控。
- **已知限制**：resume 后进程内存起点可能高于全新冷起（大 transcript 加载）。接受此限制——若实测 resume 起点内存仍显著高于冷基线（>2 倍冷起），记录数据不返工（上下文连续性优先），留待 CLI 侧改进。
- **全新起仅限**：transcript 损坏/corrupt/resume 不可得——此时照 FADE-007 上下文水库 SOP 走快照重建，provisional 转正按其流程。
- 名址复活 SOP（清 `CLAUDE_CODE_CHILD_SESSION=1`+`FORCE_SESSION_PERSISTENCE=1`）与 resume 形态叠加使用——两件事：环境变量管「被识别为子会话不注册名址」，resume 管「上下文续接」。

## 六、sg 面裁定

- **纳入同窗第二批**（本机批毕后），同题：node 常驻进程内存爬高同理；sg 机还承载 TriMMC 8710 等服务域 daemon，内存竞争面更实，回收收益更高。
- **头两轮作观察轮**：每席重启后详细验证（名址+首响+tmux capture-pane 面核）；两轮数据后定常态形态。
- **风险对冲**：sg 席重启操作通道比本机脆（tmux send-keys Enter 吞噬/暗示提示判读两坑族）——执行纪律=每步 capture-pane 验证真实输入落位，禁凭发送成功即判成。失败率显著高于本机批→sg 侧改双周轮或转 SDE 值席窗另议（头两轮后复盘定）。
- watcher 协调：sg 席批尽量嵌在周平面迁移 watcher 仍冻结的空档（与迁移执行面协调时序）；不可得则解冻后做（席位进程重启不触 git 工作区，竞争风险低）。
- sg 面内存读数由 BOD/值席侧首窗现勘补基线（本卷不写死未经实勘的数字）。

## 七、度量与复盘（效能度量线落点）

- **重启前读数**（窗前 T-30min 采）：各席 claude.exe 内存+会话连续时长+孤儿壳计数。
- **重启后读数**（窗毕采）：冷/resume 内存基线+13/13 名址+首响时延感量级。
- **周中观察点**（周三，只读不重启）：内存 top3 席读数——积累「内存爬高周曲线」，支撑频次调整裁决（§二 频次行的数据出口）。
- **月度复盘**：四周数据并表——频次/批表/sg 形态三项复核，必要时修订本卷（修订走本席，版本递增）。

## 八、风险与残留

1. **深夜窗内信件丢失残留风险**：进程死亡时未投递的跨会话消息可能丢——选址深夜最低活动期+预备广播清待办已最小化；残余接受（发信方窗后未见回音即重发，属既有协作习惯）。
2. **resume 不可得席位**：上下文靠 FADE-007 快照重建，当席次日开工延迟——概率低（transcript 损坏罕见），止损线内人工兜底。
3. **重启窗与迁移窗耦合**：迁移晚点→重启窗压缩或顺延——迁移优先级高的既定原则不变，重启窗永远让位。
4. **孤儿壳周窗外再生**：周窗只清存量，再生速率若异常（如本日 VS Code 6204 窗格式化 runner 泄漏案 29 个/9 分钟）属工具缺陷面另行治理——各席注意勿在常驻终端批量跑「全仓格式化」类命令（BOD 随令提醒，本卷代为留痕）。
