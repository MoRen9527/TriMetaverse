## 二、设岗理由（三行·详证见评估卷）

①执行层常态缺位假设候证（评估卷 §三定性框架，试岗轴 1 即其验证版）；②CPO 供给 0.74% 全席倒数单点超载（CFO 按席拆解实测）；③走查环节缺位=质量门空转（LG-058 六轮+深测②十条全系 CEO 亲测发现）。

## 三、核心职责（四条）

1. **PRD 细化**：CPO 产品方向/MVP 定义→可执行 PRD，达自含标准（执行侧零补问可开工——对齐任务书打包纪律 2026-09-14）。
2. **UI spec 走查**：纸面 spec 对照**实现源码**走查（LG-035 家族教训：纸面合格≠实现合格；四族排查=术语/命名/布局/逻辑双路径；深测②条 5 信息架构、条 7 术语即此职责的缺陷族实证）。
3. **验收锚铸造**：交付前写死完工判据（锚清单+验收方式+销账条件——对齐供货铸锚纪律，LG-067 判读同款工序）。
4. **细节质量守门**：术语一致性/信息架构/交互细节把关——深测②十条缺陷族的常设守门位，目标=缺陷在交付前被本岗拦住，非 CEO 亲测后返工。

## 四、权限边界（draft·正式化时入 contract decision_rights）

**持有**：走查打回建议权（发现执行层缺陷出整改单，回 CPO 确认）；验收锚起草权；PRD 细化执行权；走查记录落树权。

**不持**：MVP 排序权与需求优先级裁决权（CPO approve 权，chief-product-officer.contract.yaml L28 实锚）；PRD 终裁权；验收终签权（走查建议→CPO/上层验收定）；绩效记分权（CHO 域）；排工排窗权（COO 域）。

## 五、任职要求（全栈语义）

- UI/交互细节敏感度：深测②十条缺陷族（padding 缺失/徽章行冗余/术语技术词/关系词任务语言化）识别能力面。
- **源码对照走查能力**：读组件与 diff（深测②实勘 TriModel ui L189-300+CSS 对照为工作样态），非纯视觉评审。
- PRD 写作与自含打包能力。
- **全栈=前端交互面+后端数据面双通**：模型策略页十条含数据面（能力配置双栏/调用源）——单前端向不足守全门，此即裁 B 案非 C 案拆分的原因（先全栈后拆分，同 COS 串联流水线演进哲学）。

## 六、试岗规则

- **试岗窗**：2026-10-08 → 10-21（两周上限）；轴 1+2 提前双绿可提前判读候裁。
- **真题**：深测②整改批走查面——CEO 打回十条整改的验收走查即试岗考题（整改方案卷 cpo-deeptest2-ui-overhaul-plan-20261007.md 为题面）。
- **带教**：CPO；治理验收：CHO；判读席：BOD（呈 CEO）。
- **读数三轴绿线**：
  1. **走查发现率**（硬门）：PM 自查发现执行层缺陷件数 ≥ 同期 CEO/CPO 深测发现——自查≥深测=缺口补位实锚（亦即评估卷 §三「常态缺位」定谳触发）。
  2. **整改验收通过率**（硬门）：PM 走查放行件 CEO 复验零打回（十条整改验收一次过为满分锚）。
  3. **CPO 战略时间释放**（辅助定性轴）：CPO 周消耗占比 0.74%→回升，且增量投向战略面（CPO 交付物构成定性判读，不作机械线——对齐正身「数值首月校准」精神）。
- **不绿回落**：A 案走查强制化（UI 交付渲染验证门硬门化+自查发现率挂钩绩效验证加分项），零增编，回落不追责（试岗观察非处罚）。
