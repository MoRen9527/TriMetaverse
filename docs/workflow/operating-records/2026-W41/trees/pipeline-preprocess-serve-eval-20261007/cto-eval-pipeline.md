### 唯一新组件：接单触发器（工期量级=中，半窗~1 维护波）

现势缺口=「值席 7×24 接单」的触发层：TriMMC duty-consumer 只投**信箱**（落箱=delivered），值席会话内「读信→接单」是会话行为，daemon 不能替它接。候选：
- **候选 a·cron 叫醒**：TriMMC cron job 周期扫树新件→send-keys 叫醒值席会话（复用现役 cron 面+sg 同机单行通道）——小工程，但 send-keys 面可靠性弱（今日 relay 伪令案家族），叫醒只发一行信号可接受；
- **候选 b·duty-consumer 扩展**：urgent 件触发面从 display-message 扩「信箱+树指针」投递增强，值席读信即见树指针——与 a 同为叫醒语义，载体更正规；
- **候选 c·全自动接单（无值席参与）**：daemon 直接派 TriRMC cronRequest 执行——**本评估期否决**：绕过值席=失去复核段（S2 复核 PASS 正是本轮质量闸），且「接单裁决」是判断行为非机械行为，7×24 自动化的边界应止于叫醒，不越权代判断。
- **裁决：a/b 择一（b 优先，载体同 notify 正名化主线），c 否决留档**。

## 二、维度②「可自动化任务」判据：资格门三查（机器可判）

预处理产出的质量闸门=**face 资格门**，判据全部机器可执行：

1. **结构查**：任务书 schema 断言——face 字段/材料清单/验收锚列表/回滚锚四要件齐备（MD 头部或 JSON 结构化字段，正则/解析可判）。
2. **自含性查**：材料引用全部 resolve——文件存在+commit 可达+路径断言（「manifest 身份验证」纪律机械化：一名多文件/支撑面-生成计划面-发布登记册三 identity 对表；教训锚=LG-024 伪阴性、grep 无命中≠未落盘）。
3. **锚可执行度查**：验收锚从「人读叙述句」升「机读断言」——exit code/值面断言/读数格式（「全量测试四项读数+既有失败逐族归因」式可验形态）。叙述锚=不过门。
- **并轨正形**：资格门预检脚本=COS 挂标签的前置 gate（过门才准挂 face=server-executable 上链）；与四 daemon 鉴权门形统一标准（S3 在途）不同层不混装——那是 daemon 面门，这是任务书面门。
- 工期量级：schema 0.5 天+预检脚本半窗。**这是三组件里性价比最高的**：一次投入，流水线质量闸永续。

## 三、维度③供货节律：树即队列，不建新队列组件

1. **队列正解=树即队列**：任务书挂树=入队（git 持久化+diff 审计+并发语义天然），值席拾取登记=认领，回流收口锚=完成态。**TriMMC cron 面不承载工作队列是对的**（cron=时间驱动，队列=任务驱动，语义不同不必改造成队列）。
2. 缺的只是**队列状态只读面**：现靠 git log 扫树，可加 TriMMC `/internal/v1/queue/status` 只读聚合（从树目录读 pending/claimed/done 计数+最老待件时长）——组件量小（半窗内），token 门内挂 S3 同窗。
3. **优先级**：树目录车道约定（urgent/ 车道+normal/ 车道）或任务书 priority 字段+拾取排序——纪律面定，零代码起步。
4. **空转语义诚实注**：「一直有任务跑」的节律瓶颈**不在服务域在预处理**——本地 COS 工作时段外不出件，服务域队列夜里空转=正常 standby 非故障。真 7×24 供货=预处理也需自动化补位（cron 兜底批，二期形态），一期目标应为「服务域 7×24 在线可接+白班供货不断」——这个目标现役件+三组件即可达。
5. daemon 资源面：TriMMC cron 10 jobs 现役健康（healthz degraded false 21:1x 读数），队列面增量零承载压力。

## 八、COO 五问直答（21:36 征集信，技术面口径）

1. **串联形态是否消解 LG-065 张力**——技术面看是**改而非增**：一轮对等双轨下 m-cos 需持「双轨裁决+对等受令」新职责（增量）；串联形态下 m-cos 职责主体不变（预处理+本地台账主干），新增的只是「出件过资格门」一段工序——且该工序由资格门脚本机械化（§二），人工增量=挂标签一个动作。张力消解方向对，最终归 CHO/COS 岗位面裁。
2. **「可自动化任务」判据谁定怎么定**——判据定义权归本席（技术可执行性=技术专业判断面，CPO 会签只在其涉产品语义时），制度化成文走 CAO 会签。判据内容=§二资格门三查（结构/自含/锚可执行度），全部机器可判；「供货质量命门」的技术答法=把质检从人眼移到 gate——预处理完善度不足的件**在挂标签前被脚本拦下**，不进流水线。
3. **挂标签执行位**——技术面建议：**COS 挂+资格门脚本前置**（机器先判三查，过门后人签标）——标签责任人=出件人（谁预处理谁挂），COO 编排面不打技术资格标（编排与技术分层），BOD 只在 gate 争议时裁。双查（机+人）形态与「门不豁免哲学」同构：generate（预处理）→gate（资格门脚本）→sign（COS 挂标）三序。
4. **预处理工序对本地班子工作量影响**——总账**中性偏减**：增=资格门脚本跑一遍（秒级）+挂标动作（分钟级）；减=出件后流转/转达/催办段大半自动化（notify 触发器替人工叫醒，P1 复核型 4min 读数即证）；且三查脚本把「完善到什么程度才算完」从自由裁量变为达标判断，返工率预期下降。
5. **DEM-003 改写还是原样+附注**——技术面意见：**改写**（需求描述随形态升级：一轮「信道补缺」项重述为「正名化+三组件」，扫描点从信道面扩到资格门/触发器/探针三件）；裁决归汇总面，本席意见供采。
