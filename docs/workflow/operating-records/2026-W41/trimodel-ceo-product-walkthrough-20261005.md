## 一、TriModel 是干什么的——一句话版

**全公司的「模型配置总闸」。**

公司里十几个 AI 席位、一堆后台小程序，干活都要调用 AI 模型（DeepSeek、Claude、GPT 这些）。调模型需要两样东西：**用哪家哪款模型**（路由决定）、**开门钥匙**（API key，一串证明「你有权用」的字符）。

TriModel 管的就是这两样：全公司用哪些模型、每家的钥匙、以及「谁的请求该走哪家」的规则——**一处管全司**。各个程序从它这里领配置，然后拿着配置直接去找模型厂商对话。

**它解决什么问题**（过去三天两头发生的事）：

1. **钥匙散放**：过去每台机器、每个程序各配各的 key——换一把钥匙要挨台机器改，漏一台就是故障；钥匙散在角落里也容易泄漏。
2. **各用各的没规矩**：谁用哪个模型全凭各处顺手写死，想统一「日常任务用便宜模型、重要任务用好模型」做不到。
3. **坏了不知道**：某家模型临时抽风，每个程序自己挂自己的，没人兜底。

现在这些全收进 TriModel 一个地方：钥匙一处管（加密存）、模型一处配、规则一处定、坏了一处看。各程序只认它一家，它再对接各家厂商。

**一个重要边界**：TriModel 只管「发配置」，不「传话」。各程序拿到配置后，和模型厂商的对话是直接进行的，不经过 TriModel 中转——所以它挂了不会让全公司立刻停摆（下面「降级梯」会讲它挂了怎么办）。

## 二、你现在看的页面——从上往下走一遍

页面左边（宽屏时）是一排菜单，一共七项；右边是选中项的内容页。我按你点下来的顺序讲。

### 2.1 「当前生效」（总览，默认选中）

打开页面先看到的。回答一个问题：**「整个系统此刻在用什么配置」**——默认模型是谁、有没有套策略窗、四个角落的健康摘要一行一卡。

设计理由：配置页最容易迷路的是「我改了半天，现在到底生效的是哪套？」——所以把「现状」放在第一屏，永远先看现状再动手。下面三层的求值顺序是：**策略窗命中 → 卡片默认 → 出厂默认**，好比「你定的规矩 → 管家的习惯 → 厂家出厂设置」，前面有答案就用前面的。

### 2.2 四张域面卡（核心，本页主体）

菜单里四张卡：**TriMLC·本机 / TriRLC·本机 / TriMMC·sg / TriRMC·河源**。

先解释名词。「域面控制器」（卡名里那四个 Tri 开头的名字）= **替一个工作地点管事的常驻小程序**——每台机器上有一个，负责本地任务的调度和治理，它们的配置（用哪个模型、哪个钥匙）都从 TriModel 这里领。

**四面两域**是公司的地理划分：

| | 云上服务器（服务域） | 你自己的电脑（本地域） |
|---|---|---|
| **管事的面（M 面：治理、决策、派活）** | **TriMMC** · 新加坡机 | **TriMLC** · 本机 |
| **干活的面（R 面：执行任务、跑作业）** | **TriRMC** · 河源机（周平面迁移就在它身上跑） | **TriRLC** · 本机 |

四张卡 = 四个角落各一个管家，各有一张「领配置的台账」。**为什么四张而不是一张**：这页面前身只有一张「TriMMC 信息」卡，出过著名事故——卡上挂着新加坡的名字，数据却是本机的，河源的配置也曾错挂进来。**卡名和它管的东西对不上，你改配置时根本不知道改的是谁**。这个页面是被你三次纠偏（9-28 产品方向令 + 9-28/10-04 两次终审）纠正成现在这样的，规矩就一条：**卡如其名——每张卡=「哪个角色·在哪台机器」，卡的每个区块都必须答得上「我服务哪条面、哪个域、数据真身在哪台机器」**。答不上=设计没完成，不许上卡。

**每张卡内部八个小节**（四卡同构，看懂一张就看懂四张）：

1. **拉取状态**：这张卡的配置从哪拉、上次什么时候拉的、成功没有、现在用的是第几层配置。数据是页面实时向 TriModel 服务端的管理接口查的，不是页面自己编的。
2. **现役配置**：现在实际生效的模型和钥匙——钥匙只显示末 4 位（防偷窥），生效形态（直连还是中转）和探针读数如实摆出。
3. **模板切换**：一键把这张卡的配置换成预设组合。四卡里目前只有 TriMLC·本机 的按钮是真的，其余三卡是「候建——入口随后续批次开通」的**文字说明，不是坏了的假按钮**（这是故意的：没做好的功能宁可明说没有，不放一个点了没反应的假按钮骗人）。
4. **备份与回滚**：改错了一键回到上一个好配置（自动留最近 5 份）。
5. **审计行**：谁、什么时候、干了什么、成没成功——每次配置变更都记一行。
6. **不可用时**：这张卡拉不到配置时怎么办（见下「降级梯」）。
7. **CLI 对照**：页面上每个操作对应哪条命令行命令——页面能做的，命令行也能做，学一套用两处。
8. **本卡特有**：这一台管家独有的信息（比如 TriRMC 卡上有周迁移的关联行，TriRLC 卡上有「寄居本机、未来分家」的如实注记）。

### 2.3 「TriModel 策略卡」（参照层）

这卡**不是**某个管家的，是 TriModel 服务端自己的家底：机器信息、模型清单、模型集（把几款模型打包成一组）、规则（什么任务走哪组）、活动策略（现在按哪套规矩跑）。标着「本机过渡位实例」和「常态只读」——TriModel 服务端将来要迁去独立服务器，现在暂时和页面同机部署，卡名如实说了这件事。平常看就好，编辑只在你明确要调策略时用。

### 2.4 「连接配置」（便利层）

管「本机的 Claude Code 连到哪个后端」——日常便利设置，页面上写明了「不担兜底」。它和四张卡是两回事：四卡是管家们领配置的台账，这里是给本机开发工具指路的便签。

## 三、三个设计，为什么这么做

### 3.1 诚实三态——「宁可难看，不许撒谎」

每张卡右上角有一枚彩色小标签（行话叫 badge，徽标），只有三种诚实状态：**在役=已生效；降级=待应用或失败；缺席=未配置或读取失败**。连接时你填错钥匙，页面显示黄色「已填入未验证」，绝不冒充绿色「已连接」。

为什么：**假状态比坏状态贵得多**。设备坏了你知道去修；设备假装正常，你带着假安心去干活，塌的时候才发现——那才是事故。这页面的验收标准里白纸黑字写着一条：「页面显示的状态和后台真实状态不一致即不合格，不问美观」。连「没做好的功能显示候建文字」也是同一哲学：如实说没有，好过假装有。

### 3.2 降级梯——总闸挂了，天不会塌

哪天某个管家拉不到配置（网络断、TriModel 重启），它不会当场瘫痪，按三层自动降级：

1. 先用**最近一次拉到的好配置**（本地有缓存）；
2. 缓存也没有，退**出厂默认**（基础可用）;
3. 恢复后自动回到正常拉取。

每张卡「不可用时」一节写的就是当前降级梯。配合开头说的「TriModel 只发配置不传话」，构成两层缓冲：总闸短时不在线，各角落照常干活，只是拿不到**新**配置。

### 3.3 双令牌——两把钥匙分级

你手上两把钥匙：**API 令牌**（日常钥匙）和**管理令牌**（管理钥匙）。

- API 令牌：各程序日常领配置用的，权限=读。给了它的人能用系统，改不了系统。
- 管理令牌：改策略、看管理面深层信息用的，权限=写。页面上的连接框要两把都填，就是防「只拿到日常钥匙的人顺手改了全局配置」。

为什么分级：**「能用的」和「能改的」分开，泄漏的代价就封了顶**。好比酒店房卡和工程万用卡——房卡丢了损失一间房，万用卡丢了是全楼的事故。日常钥匙高频使用易暴露，管理钥匙低频使用少暴露，权限跟着风险走。

## 四、上手三步（你现在的场景）

1. **看**：开「当前生效」——先知道现在系统用什么。再扫四张卡右上角的徽标：绿色「已生效」=健康；黄色/灰色=点进去看「拉取状态」和「不可用时」两节，页面会把原因用大白话写在那。
2. **连**：菜单进「连接配置」，把 API 令牌和管理令牌都填上点连接——连接点变绿=通；若变黄色「已填入未验证」，是钥匙没过验证（检查有没有粘错/漏字符），页面不会假装你连上了。
3. **动**（要改配置时）：进「TriModel 策略卡」调规则和活动策略；四张管家卡上看现状、做回滚。改错不慌——「备份与回滚」一键回上一个好配置，审计行里留了每一笔的底。

**如实注三笔**（免得你以为是故障）：① 四卡里只有 TriMLC·本机的「模板切换」是真按钮，其余三卡显示候建文字=按设计如实呈现，非缺陷；② TriRLC/TriRMC 卡上的「寄居过渡」「同机过渡位」注记=现役部署形态的如实标注（服务端将来迁独立服务器，届时只换拉取地址、卡片语义不变）；③ 你在河源机上看页面的同时，页面上四张卡的「现役部署位」写的本机/新加坡等字样不受你从哪台机器打开影响——卡的机位说的是**数据真身在哪**，不是谁在看。
