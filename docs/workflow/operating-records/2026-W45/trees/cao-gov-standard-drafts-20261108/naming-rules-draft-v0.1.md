## §二 · 规则草案（R1-R9）

1. **R1 通用形**：文件名/目录名一律小写 kebab-case·语义段连字符分隔·**禁空格禁中文入名**（中文入 title/正文·名面只英数连字符）。
2. **R2 日期尾缀**：快照/事件卷必须带日期尾缀；卷文件=`YYYYMMDD` 紧凑形为正形·`YYYY-MM-DD` 日缀形=legacy 容忍不回改（存量不追溯·新件从正形）。
3. **R3 周缀**：周常设件用小写 `-w<WW>` 短缀为正形（`-2026-W45` 全长形=legacy 容忍）——周平移换缀动作归迁移器标准件清单（产出③联动）。
4. **R4 滚动指针**：时序滚动最新态用 `-latest` 尾缀；**latest 件=指针非真源**——真源=带日期时序卷·latest 由生成机制滚动覆盖·禁手工直改 latest 绕过真源。
5. **R5 run/实例目录**：跑批实例=`<subject>-<cadence>-<YYYYMMDD>-<HHMMSS>`（时点戳到秒防同日碰撞·fade011-daily 形为正形模板）；worktree/生命周期实例=`<族前缀>-<subject>-<族中缀>-<hash12>`（hash 锚·生存期=实例生命周期非时点）——两形语义分野：时点形=一次性产物可归档·hash 形=有生命周期对 DB/registry 帐。
6. **R6 树目录**：`trees/<slug>-<YYYYMMDD>/`·slug=主题词 kebab-case·立树日尾缀。
7. **R7 编号与名分野**：编号（D/LG/DEM/OP）系引用锚不入文件名主体；文件名语义段自述内容·编号入正文/索引行。
8. **R8 禁改面（一致性铁律）**：已被机器消费面引用的路径（fade.db checkpoint.treeDir·cron job command·settings 挂载等）**禁单侧改名/搬移**——盘/账一致性优先·先改账后改盘·README-POINTER 案（2026-11-04 字面 {week} 排障产物）为铁律先例实锚。
9. **R9 批量产物标准位**：同类高频产物（FADE run 等）落「标准位置+模板形」——禁散落根目录制造零散垃圾（CEO 判直指·机制=产出② FADE 记录规范+产出③标准化选型联动）。

## §三 · 与现行制度关系

- D-16 附录·项目侧文件约定=本规则的**母族**（现役 4 条+agent 命名形）——本规则评审过即为其扩展增补·不另起册（选型候裁）。
- D-13 通信名址/命名宪法=**席位正名面**（通信地址域）·与文件名域分野不混写；D-68 机器名正名=控制器族名面·同属名纪律族互引。
- 跨平台整治（派工圆桌产出③）联动：脚本命名随 R1·POSIX 冒烟路径要求随 R9 标准位。

## §四 · 待确认面（诚实边界）

- **ew 中缀语义**：`fade-w-fade011-ew-<hash>` 之 ew 系 FADE run 树现役命名元素·语义定义实勘未见正身——**候 CTO 勘定**（机制侧命名权威），本稿只录形不定义义。
- 双日缀形（紧凑/日缀）与双周缀形（短/全长）收敛节奏：存量不回改铁律下的自然收敛 vs 一次性清理窗——候圆桌裁。

## §五 · 验证三问（需求池格式）

- 谁消费：全员席（落卷/寻卷成本·本规则消费面）+机器消费面（watcher 扫描域/迁移器模式匹配——命名可预期=机械可扫）。
- 为什么现在：CEO 令7 直令+今日双判指（零散垃圾判/跨平台整治判）+W45 周平面 11 文件实勘双形并存——命名债随文件量线性涨·现在立规则边际成本最低。
- 最小版本怎么验证：新落卷文件抽检对照 R1-R6 命中率（本周新件全数应命中）+存量 legacy 计数只降不升（自然收敛判据）；机器侧=迁移器/watcher 模式匹配零例外。
