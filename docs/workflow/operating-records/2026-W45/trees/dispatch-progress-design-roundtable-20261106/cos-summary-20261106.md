## §零 · CEO 七原则（原文照录·议题卷本体）

1. BOD 收到 COS 已挂出的任务自己把任务书和树记在 md 中；COS 自己负责的任务书和树也记 md；台账同理（双面记账+对账基座）
2. daemon 挂定时任务，检查未完成的任务书和树进度，通知 COS，COS 开始推进（机械盯进）
3. COS 完成的树和任务书，要与 BOD 销账（销账闭环）
4. 能做程序和脚本的，不用员工自己处理，固定执行比靠员工自觉靠谱（机械优先原则）
5. 任务书和树可以放周平面的任务进度大表，这样就都联动起来了
6. BOD 底稿（bod-duty-ledger.md·今晚新立制度位）可以记录需求，与周工作平面的需求大表对应（PM 维护），两个表对账；daemon 挂定时任务检查需求，提醒 CEO 哪些需求还没审核；也可以周日集中审核需求，进入下周周工作平面——CEO 附发现：周工作平面的 plan skill 没有考虑到需求审核和进入下周的已审核需求（已审核需求下周形成任务书），这个迁移规划没考虑，要补
7. 定时任务脚本最好跨平台，少用 windows powershell 脚本（只能本地域跑不跨平台），以前存在的问题本次集中整治
