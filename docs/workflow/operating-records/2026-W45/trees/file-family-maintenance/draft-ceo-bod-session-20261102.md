## 四、CEO 四问·BOD 答（20:2x 轮）

1. **范围**：只限 TriMetaverse/docs/（不是全仓）——代码/脚本/TriCompany 均不入图；域外被引用件记 external 只记不扫。
2. **内存/负担**：轻。流式逐文件读，峰值≈单文件+累积 dict；333 件秒级、产物 90KB；即便扩全仓 5032 件 md ≈15 倍量级，仍秒级-十几秒、内存几十 MB 上限——任务不过重。
3. **成环/乱码**：环无害。cites/citedBy=一跳邻接表，环是合法数据非故障；乱码属编码/截断家族与图环无关。唯一风险=未来做递归展开（传递闭包/级联知会）时无 visited 标记会死循环——现役只记一跳零递归零风险；进阶需求用 graphlib（stdlib·CycleError）/networkx（find_cycle）现成件。
4. **业界方案**：有。最同构=Obsidian backlinks 模型（md 双链+反向索引+图谱视图，本机制即其仓内最小实现）；Python 现成轮子=graphlib（3.9+ 标准库·拓扑排序自带环检测）、networkx；同思路旁族=madge/pydeps（代码依赖图）、Doxygen/Sphinx 交叉引用、企业级 Sourcegraph/LSIF/SCIP。结论：无自研必要，进阶全部有现成件。
