## 一、候批信信件规格

### 信封字段（notify 通道 schema 扩展，全部向后兼容）

| 字段 | 必填 | 说明 |
|---|---|---|
| `type` | ✓ | `pending-approval`（候批信，区别于 walkthrough/progress 既有类型） |
| `source_seat` | ✓ | 写信席（候批的产生方） |
| `target` | ✓ | **bod+coo 双投**（CEO 面经 BOD 转呈不直投——human in session 设计） |
| `task_ref` | ✓ | **双向映射键**=任务书相对路径+树节点 id（如 `2026-W38/task-charter-xxx.md#T3`）；无任务书的对话裁决型任务用台账条目号（LG-xxx） |
| `state` | ✓ | 候批态枚举：`pending-bod`（候董事会裁）/`pending-ceo`（候 CEO 批）/`pending-window`（候窗非候批，不进催办池） |
| `waiting_since` | ✓ | 进入候批态的绝对时点（UTC Z；催办时效锚计算基准） |
| `sla` | ✓ | 时效锚档位：`hard:<绝对时点>`（有明确窗口）/`normal:24h`（常规）——照 D-27 v3 时效锚双型 |
| `title` | ✓ | 「候批：<一句话>」 |
| `body` | ✓ | **三行结构**：①干了什么（一句）②候谁决什么（一句）③超时将怎样（超限后果——照 COO 催办三要素，只喊不加限=问候不是催办） |

### 触发时机

- **生成点=进入候批态的瞬间**：执行席节点收口时，若收口态含「候批」判定→**收口 notify 与候批信同刻自动双发**（服务域=值席批次制度化后由收口钩子自动写，零人工；本地域=席收口时半自动——台账挂账动作已含，信件随挂账生成）；
- **同刻双写**：候批发生即「台账挂账+信箱写信」双写（D-27 v2「发生即同步」义务扩展到信箱层——发生不同步即违规）；
- 重发规则：同 task_ref 候批信幂等（重发覆盖不叠加）；状态跃迁（如 pending-bod→pending-ceo）发**状态更新信**（type 同、state 新值、body 注明跃迁原因）。

### 状态映射（任务生命周期 ↔ 信件类型）

| 生命周期态 | 信件 | target | 进催办池 |
|---|---|---|---|
| 在办 | 无信（在办无信，催办走台账） | — | 在办超时才催（三层催办 §二-1） |
| 候审（席间联审） | `pending-review` | 联审席 | 不进 bod 信箱（席间互报免附规矩域） |
| **候批** | `pending-approval` | bod+coo | **进**（本命题核心） |
| 已批 | 原信标记 `resolved` | — | 出池；台账同刻销账/状态更新 |
| 收口 | 收口 notify（既有机制不变） | — | — |

## 二、三层催办机制细则

### 1. 催执行席（在办超时——既有 D-27 v3 制度，照录咬合）

- 触发：有 SLA 任务到点即催（hard 档）；无 SLA 在办 24h 软阈值；
- 执行者：COS（台账催办池扫描）；形态：三要素催办（超时事实+兜底绝对时限+超限后果）；终点照 COO 条②（首催→重申一次→到顶按已收意见先行汇总+缺席如实标注）。

### 2. 催审批链（候批超时——**本命题核心新增**）

| 层 | 触发 | 执行者 | 形态 |
|---|---|---|---|
| 催 BOD | 候批信 `waiting_since+sla` 到点未裁 | COS（自动，notify urgent「候批超时：<task_ref> 已候 N h」） | 三要素（超时事实+兜底时限+后果=升级 CEO 面呈报） |
| **BOD 提醒 CEO** | BOD 收 COS 催后；或候 CEO 批事项超 24h | **BOD（职责增项——CEO 诊断③对症）** | human-in-session 面主动呈报 CEO（在席即报；不在席照 bod 缺位缓存协议挂候裁区+周平面） |
| 升级 | hard 档到点／normal 档 48h 未决 | COS→COO | 进督办层（下条） |

- 时点表：hard 到点即催（不等 24h）；normal 24h 首催→48h 升级 COO 督办→72h 呈 CEO 面汇总（含缺席标注）。

### 3. 催督办面（COO）

- 触发：①候批升级态送达②**批量积压信号**（≥3 件同族候批=系统性瓶颈预警——单件是偶发，批量是流程断点）；
- COO 动作：督办读数（时限达成/逾期/升级建议——中央收口督办职责咬合）+节奏干预建议回 COS/CEO；
- 全程催办留痕（时间/对象/事由）=绩效效率源账面（COO 条④照录）。

## 三、台账与信箱双向映射

- **映射键=`task_ref`**：信件与台账条目共键（任务书路径#节点 id 或 LG-xxx）；
- **写向（发生侧）**：候批发生→台账挂账+信箱写信同刻双写——任一缺失即违规（D-27 v2 扩展）；
- **读向（裁决侧）**：BOD 裁决→信箱 `resolved`+台账销账/状态更新同刻双写；
- **COS 巡检=双态对表**（催办池扫描的机械动作）：信箱 pending 而台账无条=**漏挂**；台账候批而信箱无信=**漏写**；两态时差>5min=**不同步**——三型差口即 COS 告警源+修复动作触发；
- **闭环判据**：任意时刻「信箱候批态集合」与「台账候批态集合」按 task_ref 对表零差口=状态机健康。

## 四、与六席段的咬合点（候联审对表）

- **BOD 段**：提醒 CEO 触发条件（本件给骨架：收 COS 催或 24h 超时）候 BOD 定阈值/摘要形态；本地域人工保留点清单候 BOD 出；
- **COO 段**：督办读数与候批信咬合（本件 §二-3 给触发）候 COO 出时点表细则；
- **CPO 段**：信件 body 三行结构=「不吵」约束草案，候 CPO 体验标准校；状态呈现「一目了然」候 CPO 定信箱摘要形态；
- **CTO 段**：信封字段扩展（type/task_ref/state/waiting_since/sla 五字段）候 CTO 定 notify-mailbox 载体实现；服务域自动收口钩子=一期落地件；
- **CFO 段**：候批信零 LLM（纯状态机生成，无 token 成本）；催办轮询成本候 CFO 评；
- **CAO 段**：本件三节=制度正身素材，候 CAO 裁归口（D 系整合 or 独立成册）。

## 五、一期落地最小集（服务域全自动先行，候联审定稿）

1. CTO：收口钩子+信件生成（notify 通道扩 type）——sg 值席批次跑通一例全环；
2. COS：催办池扫描双态对表（台账侧现役，增信箱对表）；
3. BOD：提醒 CEO 职责运转（human-in-session 面无技术件，纯职责增项即日可生效）；
4. COO：督办读数接入（现役职责，候批升级态为新增输入）。

## 六、v2 咬合增补（2026-09-21 21:1x；合流素材随三方段稿收敛）

- **body 三行→四行**（CPO 合并提案采认）：`干了什么 → 候谁决什么 → 已候多久（时点+累计） → 批后会怎样+超时会怎样`（一信双后果预告）；不吵五律+升级节奏表 T+0→4h→1d→2d→5d 并入 §二时点表（与 hard/normal 双型对表：hard 按 SLA 独立、normal 沿节奏表）。
- **信封字段增补**：`track`（normal|blocked|red 三轨——COO 段硬依赖；red 直达轨永不积压按违时处理）；`waiting_since` 定义收敛=「素材齐备时点（候批信或台账较早者）」（COO T+0 起算锚）。
- **R2 模板化收敛**（CFO）：body 四行=四模板槽位（每槽≤40 字模板值，枚举型优先），禁长自由文本；信封字段全固定枚举——候批信零 LLM 生成。
- **留痕分层**（CFO 坑修正）：信箱层幂等覆盖可；**留痕层只追加**——字段=六+二（任务书号/状态/时点/催办对象/参与席/事由+首写时点/覆盖计数）；候批时长=已批时点−首写时点。

- **督办读数节律**（COO）：每日两轮挂晨窗+夜航窗；读数不发通知，动作集（催/升/异常上报）才发。
