## 〇、总纲：一个产品定谳贯穿四问

**我们的知识消费机制=启动注入（boot injection），不是检索。** 由此推出一条形态学结论：**wiki/知识页不该照抄搜索引擎时代的词条形态（互链知识网），而应是「注入页」形态**——结论前置、自包含、可整段用/整段弃。互链是检索范式的产物；注入范式的页面价值=「单独进上下文也成立」。四问答案全部锚在此。

## 一、a) 员工岗位知识 vs 全员学习知识：边界与流转

**边界（三问判域法）**：

| 维度 | 员工知识（inbox→schema→wiki） | 全员学习知识（org/shared） |
| --- | --- | --- |
| 回答什么 | 「我这个岗位怎么判断/怎么干活」 | 「公司是什么/全员该会什么」 |
| 读者 | 未来会话的自己+接手席 | 全部 13 席+未来新员工 |
| 注入面 | 该席启动（1 倍成本） | 所有席启动（**13 倍成本**——产品纪律必须更严） |
| 写权 | 本席本人（hermes 契约：不跨私域写） | 众创+单一收口（收口 owner 候 COS/CGR 定） |

**流转（两段管道+两次提炼）**：
1. `inbox → wiki`＝**吸收**（消化，本席内闭环）。
2. `wiki → org/shared`＝**升格（promotion）**：唯一上行通道。升格判据=**去域化检验**——「这条知识脱离我的岗位语境还成立吗？」成立→可升格；不成立→留私域。下行=org/shared 条目作为全员公共层参与各席注入；新条目对员工构成「新规学习」通知（可进其 inbox）。

**现状警示（实勘）**：`org/shared.md` 现役仅两条 2026-07-14 的 daily-close 摘要残留（且中文乱码）——它现在是「日志垃圾桶」而非学习知识。升格管道不立，它就是下一个垃圾桶。

## 二、b) wiki「沉淀」的产品定义

- **谁能写**：本席本人（wiki）；org/shared=众创提案+单一收口（禁任何单席直写，防打穿边界——hermes 契约 3 同旨）。
- **写给谁看**：第一读者=未来会话的自己（工作连续性）；第二=接手席；org/shared=全员。
- **怎么被消费（产品核心）**：启动注入，**非检索**。服从注入的四条格式约束：①结论前置（进上下文的是结论+判据，不是过程）②自包含（不依赖互链）③可整段用/可整段弃（每页独立价值）④**体积预算纪律**（注入=每会话固定 token 成本；token 实测口径下 bootstrap 已 47-48K/窗——知识注入面增长直接烧全席成本）。
- **分层建议**：私域 wiki 可整席全量注入（体积小）；**org/shared 必须分层**——核心层（全员必读）全量注入+扩展层按岗位注入。org/shared 单品判据：「这条不进会怎样？」不怎样=不进。

## 三、c) schema 层该「消化」出什么

**产品语义：schema=消化判据，不是内容容器。** 它对每条 raw 源做三个决定：
1. **归页**：进哪页（现有 source_filter 已有）；
2. **丢弃**：不进任何页的 reject 规则（**现缺——丢弃是消化的一半**，无丢弃规则=垃圾进垃圾出）；
3. **升级**：拿不准/高影响的源，提示人工裁决（现缺 escalate 规则）。

消化产物=现有编译五段（摘要+事实+判断+待确认+来源）——产品上这五段已对，缺的是**规则化**（什么条件产出什么、什么条件提示升级）。「待确认」段=消化留下的诚实体内债务，应汇入审计面而非静默丢弃。hermes 近邻 dialectic 蒸馏可对标（辩证产物≈事实+判断+待确认三段）。

## 四、d) 13 对文件 diff 去重：产品视角

**定谳：这不是产品设计问题，是发布管线卫生问题；产品侧只守一条红线——去重不得制造第三真源。**

- 原则：`TriCompany/source-agents/` 唯一真源；两个宿主位（`.claude/agents/`、`.github/agents/`）=发布拷贝，产物应可丢弃可再生（FADE 发布域渲染），不该手工双份维护。
- **正确顺序（去重前先收割）**：①diff 审计（拷贝里是否有未回流的有效改动——先改拷贝没改真源的漏改）②有效改动回调源侧 ③发布管线接管渲染 ④切断手工拷贝。跳过①=丢失在拷贝里发生的真实修正。
- **实勘补充**：`.github/agents/` 存在大小写双件并存（`CompanyGovernanceRegistry.agent.md` 与 `company-governance-registry.agent.md`、`TriMetaverseCodeRegistry.agent.md` 与 `tri-metaverse-code-registry.agent.md`）——13 对不是干净的 1:1，去重清偿单应含历史命名重复件。
- 反模式警告：以「比对两份手改差异再合并」方式做去重=承认双真源+制造合并中间件（第三份）。禁止。

## 五、验收锚（供合流件采纳）

1. 升格管道：存在明文的去域化检验+单一收口点；org/shared 新增内容不含单席日志类残留。
2. 注入页形态：wiki 页模板含「结论前置」结构+自包含断言（抽 3 页断网去链可读）。
3. org/shared 分层：核心/扩展两层定义+体积预算上限（数值归 CTO 测算）。
4. schema 三决定：reject 与 escalate 规则落位（哪怕先人工执行）。
5. 去重：diff 审计记录+回流 commit+发布管线接管声明三者齐；01 三份真源零出现。
