## 一、B 必答题：零漂移复制体为何不可持续（四条，含实证）

1. **漂移是进行时非理论**：双复制体无同步机制（无 pipeline 对账/无包引用），双维护靠人肉记忆——同模式先例 app.ts 复制体已实际漂移出 **5+5 红族**（认知层联审登记的既有债），今天 injector diff=0 只是复制时状态；
2. **每次演进双倍成本**：injector 任何改动（如首落② 若走信封新写）须双仓同改——演进速率减半、漏改率翻倍；
3. **语义归属模糊**：diff=0 无法判原件/复制体——bug 修复与特性落点无权威位（改哪边？另一边谁同步？）；
4. **审计一致性伏笔**：两 consumption 表结构今日对称，漂移后跨端聚合（命题 D 查询）失真——审计碎裂从结构分叉开始。

## 二、命题 B：形态三案并评——**裁案二共用模块单提，落 TriCode 包**

| 案 | 形态 | 判据逐条 | 裁 |
| --- | --- | --- | --- |
| 一·各 daemon 内嵌 | 现状（同构复制体） | 单一真源✗（双份）/维护✗（双改）/漂移风险✗（实证先例） | ✗ 否 |
| **二·共用模块单提** | 四件提为共享包，TriMLC/TriRLC 改包引用（各面进程分跑） | 单一真源✓（一份代码）/面隔离✓（**面隔离是运行时概念非代码仓概念**——包同源、实例分跑、DB 分库，M/R 面并行无退役不破）/维护✓（单份）/审计一致性✓（同构件同表结构天然对称） | ✓ **采纳** |
| 三·中心注入服务 | 单 daemon 集中供注入 API | 跨面调用（R 调 M 或反之）=新增跨面依赖+单点+会话初始化性能税；中心化伤面隔离 | ✗ 否 |

**落点位**：**TriCode 仓**（模块定位=Shared code runtime，`三元宇宙架构与模块说明` 正身位）——注入器四件提为 TriCode 共享包，TriMLC/TriRLC 以包引用替换自有复制体（复制体退役）。**渐进路径**：提包→双仓改引用→**行为零变化验证**（同输入同输出+consumption 表结构不变）→复制体删除（独立 commit 可回滚）。

**sg 服务域空格的架构红利**：案二下 TriMMC 若未来需注入面（CPO 产品裁）=**引同一包加端**，零新代码体系——单提的复利。

## 三、命题 C：决策权——混合制采认（CPO 三权分置）+技术落法

- **三权分置采认**：餐单规则归治理策展（保底=三层分发核心层+岗位标准+stable 页）/执行归 daemon（照单注入）/加餐归席位自请（走检索面按用付费，不入注入预算）；
- **技术落法关键一条**：餐单规则=**配置数据非代码**（profile/餐单文件，治理可编辑）——injector 现读 knowledge.db 各层已天然支持，「该喂什么」永不进 injector 硬编码（照单执行机构定位的代码面保证）；
- 现役触发面（三消费方调用点自动）=保底正餐通道，不加席位自请通道（加餐走检索面=另一条已区分的道，防 token 预算失控面）。

## 四、命题 D：审计对齐——分库保留+聚合统一（不建集中库）

- 两活跃端（MLC/RLC）knowledge.db 分库**保留**（实例分库合理——各面各记各的，与审计分域不混流原则同构）；
- 统一=**查询聚合面**：跨两库一查询的聚合脚本（MVP=jq/脚本级，零新依赖——不先建库纪律）；
- 首落② 判（consumption 现役覆盖）延伸：信封统一化（cae-…）候 P2 入库时**在共享包内一次性实现**——单提红利第二笔（信封改造一处落地两端生效）。
