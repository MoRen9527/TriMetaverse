## 〇、产品定位一句话

**注入器=p2 消化管道的出口对接口+三层分发的执行机构**——「13 席每会话的知识正餐」唯一厨房。产品命题「席位该被喂什么」不是运行时问题，是**餐单治理问题**：注入器只应照单执行，餐单由治理与策展决定。

## 一、实勘读数（产品语义视角，四点）

1. **注入五层固定序**（memory→colleagues→social→wiki→inbox）+来源语义标签（contract/content 域后缀防 curated 与契约混淆）——信封思想已萌芽（与认知资产审计信封同族，合流顺滑）。
2. **降级语义=fail-open**：缺库/无知识/异常→原 prompt 原样返回 injected=false 不阻断——「正餐缺席不致命」与兜底独立性同族（正确，重构红线：任何形态改动不得把注入失败变会话阻断）。
3. **消费审计现役**：knowledge_consumption 每注必记——四问之「注入可核对」已活体（认知资产联审首落②改判实锚）。
4. **身份纯度原则在码**：soul+agent_body 由 contract-resolver 保持不变，注入只发生 在消费挂接点——注入≠身份改写（原则正确，保持）。

## 二、命题 C 决策权：**混合制，权责三分**（核心交付）

### 三态判
- **席位全自请=否**：结构性盲区——席位不知道自己不知道什么（新席/复活席尤甚）；且 13×自由自请=token 预算失控面。
- **系统全自动=必要但不足**：保底正餐必须自动（零逐次人工决策、可审计、保基准）；但纯自动=过度注入+陈旧+一刀切。
- **裁=混合制**：

### 权责三分（对 CEO 第四问的直答）
| 权 | 归属 | 内容 |
| --- | --- | --- |
| **餐单规则** | 治理与策展 | 保底餐单=三层分发核心层（org/shared 核心）+岗位标准（employee-standard-capabilities）+p2 stable 页（过注入质量门）——「该被喂什么」由标准与策展决定，非 injector 私有硬编码 |
| **执行** | daemon 自动 | 照单注入，零逐次人工；inject 事件每注必记（四问可核对） |
| **加餐申请** | 席位自请 | 会话内按需拉取走**检索面**（不计注入预算，按用付费）；自请行为入审计 |

### 反馈闭环（本件最有价值的一条）
**同一席位反复自请同一主题=promotion 信号**→该主题成为 stable/核心层候选（下批注入自动带上）——自请数据反过来养注入决策：注入决策不是静态权威，是被喂出来的活规则。落点=自请审计带主题标记，promotion 候选链路有记录位（技术承载归 CTO）。

## 三、与学习腿/p2 的衔接（闭环图）

```
学习腿产 stable 注入页（p2 管道出口，质量门后）
   → 注入器照餐单喂席位（inject 事件必记）
   → 席位工作产出 → inbox → 消化管道 → 学习腿
```
- 认知资产联审判「inject 事件=唯一现役活跃消费方」即此意：**注入器=p2 第四段（wiki 对接）的消费对接口**。
- 三层分发映射注入策略：**核心=必注入／可选=按 profile 注入／目录=不注入（可发现）**——注入器=三层分发的执行机构，目录层零注入成本在注入侧成立。
- 体积预算门（p2 锚⑥）执行者=注入器：预算闸在注入侧收口。

## 四、命题 B 形态裁的产品判据输入（CTO 主笔裁，我供三条判据）

1. **喂食关系跟随被服务面**：谁被喂，喂食责任归谁的 daemon——TriRLC 组件喂 M 面 13 席的错位，修法方向=责任随消费者走（归属错位的修复判据）。

## 五、验收锚（产品面）

1. 保底餐单有治理出处（岗位标准+stable 判定记录可指），非 injector 私有硬编码。
