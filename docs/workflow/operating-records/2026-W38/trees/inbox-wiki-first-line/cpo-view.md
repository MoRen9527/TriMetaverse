## 一、员工纪律手册大纲（列全，13 席通用层）

**定位**：员工视角的「在此公司干活不打犁」手册——D-xxx（engineering-disciplines 系）为上游不改写，手册条目=员工视角一句话+指回上游条目号（索引非复制）。
**落点裁**：**knowledge/org/（组织知识库）首件**——13 席通用=组织层，正是 p2 promotion 目的地的第一件实货（架构自洽：手册天然是升格产物）。

```
员工纪律手册（discipline-handbook）大纲 v1
├─ 0. 开工纪律（接单与准备）
│   ├─ 0.1 接单三查：时点现查比对令文／任务书验收锚齐／归属路由（是否我的域）
│   ├─ 0.2 前置核查序：上级最新输入→域内真源→registry→governance
│   └─ 0.3 路径与文件：落点先查并行线／文档元信息头／「不存在」结论前全仓扫过
├─ 1. 执行纪律（干活中）
│   ├─ 1.1 留痕：先写后报／长任务分段落盘／事实引用带来源
│   ├─ 1.2 验证：独立重测+第二方法／键存在≠值面／全量读数含既有失败归因／断链即断流程
│   └─ 1.3 保守默认：新素材默认 working／源侧赢副本／推断显式标注
├─ 2. 协作纪律（席间）
│   ├─ 2.1 寻址正名：正名+别名表寻址／「已发已转」先查发信记录
│   ├─ 2.2 上报转达：大白话结构（干了什么→结果→候决）／已覆盖项不发确认件
│   └─ 2.3 边界：不越域代裁／分歧挂起候裁／派工直达不留便道
├─ 3. 交付纪律（收口）
│   ├─ 3.1 commit 卫生：提交前三查／统一 add／落盘即 commit 或明说
│   ├─ 3.2 文档收口：活文档追加制／历史冻结与真源可修分界
│   └─ 3.3 验证门：UI 交付渲染验证门／新端点真链路案／走查三遍
└─ 4. 复盘纪律（沉淀）
    ├─ 4.1 教训入册：行为记忆条／盲区单列／归因与归责分界
    └─ 4.2 经验升格：复现信号→纪律手册条款候选（对接经验线）
```
大纲列全原则：**节固定、条可增**——新纪律走 4.2 升格门入对应节，大纲骨架不做破坏性重排（版本化）。

## 三、schema 结构设计（零散→大纲位映射）

- **inbox frontmatter 扩展**（p2 模板上加三键）：`sourceType: discipline|experience`／**`outlineSlot`**（大纲位路径，如 `handbook/1.2`、`experience/chief-product-officer`）／`domain: local|service`。trustLevel 默认 working 照管道件。
- **page-specs 两条**：
  1. `discipline-handbook` spec：source_filter=sourceType:discipline → 编译五段写入 outlineSlot 对应节；**大纲位必填**（缺 slot 且无法推断=reject 记日志——p2 reject 阀门首实证）；只并入不改写 D-xxx 引用（引用条目号回指）。
  2. `experience` spec：sourceType:experience → outlineSlot=experience/<席>；同主题块自动聚合；**复现信号**（同主题≥3 源或 CEO/CAO 点名）→升纪律手册候选（promotion 动词，人工门照 p2）。
- **结构化沉淀质量指标（首线验收用）**：大纲节覆盖率（有内容节/总节）+零散件归位率（入 slot/总 inbox 件）+reject 率（漏斗健康度）。
