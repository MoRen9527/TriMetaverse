## 二、真源化形态：`TriCompany/scripts/ops/`（功能优先，机器参数化）

- **落点**：`TriCompany/scripts/ops/`（运维脚本域，与 docs/ 平级的真源域地位——脚本=设计落实物非二等堆放处）。
- **结构=功能优先**：`ops/<功能域>/<功能>/`——功能域建议 watchdog/notify/sync/dispatch/launch/fetch 六族起（按实锚件自然聚类）；**不按机器分域**（机器是部署参数不是功能边界）。
- **同功能跨机=同目录配对**：seat-watchdog 本机/sg 两版漂移教训的制度化反面——**逻辑同源的功能一份源+目标机配置化**（CTO 硬编码抽离联动）；实现真分叉的平台双件同目录显式配对命名（§三），配对即可 diff、漂移即可见。

## 三、命名规范

1. 基式：`<功能>-<对象>.<ext>`（seat-watchdog.ps1／notify-poller.sh——ext 是实现载体不入功能名）。
2. 跨平台同功能配对：`<功能>.windows.ps1` + `<功能>.linux.sh` 同目录并列——**配对即防漂移**（同目录显式兄弟件，比散落两机可 diff）。
3. 禁止：目标机名入功能名（sg-seat-watchdog 旧式=机器进了名字，改配置不改名）；部署位手改产出不入源。
4. 每脚本头注四件：用途/目标机/触发方式/真源位指针（deployed-from 注记——部署位件可回指源位）。

## 四、可移植性产品标准（四条件+金标准）

脚本资产「可移植就绪」=四条件全满足：
1. **源文件在 TriCompany 版本化**（有存档，git 史即演进史）；
2. **配置外置**（路径/席名/MAP 从配置读——硬编码清零）；
3. **部署位=渲产物/同步产物**（部署位文件可随时从源重建，禁直写）；
4. **头注四件齐**（§三.4）。

**金标准（验收判据）**：「换一台新机器，照源文件+部署流程能在 30 分钟内重建同等功能」——**重建演练**作为可移植性验收动作（每批真源化抽件演练一次，迁移日=全量演练）。

## 五、先源后部纪律的产品侧配合（对 CAO 纪律增条）

- 常态：**新脚本出生即源侧 commit**，部署动作=源→部署位同步（脚本走管线/同步，CTO 机制）——部署位直写=违规。
- **应急例外（同直连兜底语义族）**：紧急故障可手改部署位先恢复——**24h 内回写源侧+留痕**（应急可，漂移不可；回写截止过期=CAO 纪律条触发）。先源后部与应急回写两面合起来=「源位终局一致」。

## 六、运行数据边界（与 CAO 归档纪律衔接）

- .fade/（及 fleet 家）改名/清空前：脚本资产迁出+配置模板抽离后，**剩余=运行数据+渲产物**——ignore 状态维持（丢的是可再生内容），**但历史价值件单独归档**（notify-ledger 台账镜像类转 CAO 定归档节奏；纯 log 按轮转自然消亡）。
- 红线：运行数据不入真源域（防 scripts/ops/ 变成第二个垃圾桶——org/shared 垃圾桶教训的脚本域版）。

## 七、验收锚（产品标准面）

1. 三分类判据对 .fade+fleet 全件逐件落类（分类表可复核，无「未定类」残留）。
2. 脚本资产 100% 入 `TriCompany/scripts/ops/` 且头注四件齐。
3. 同功能跨机件配对命名或配置化合一（散落双版清零）。
4. 配置模板入源+实例值留运行位+密钥零入源（SEC 红线抽验）。
5. 重建演练一次过（金标准首演）。
6. 应急回写机制有首例或演练记录（源位终局一致实证）。
