## 二、四段产品语义详述

### ① 接入
- 来源三路：会话产出（自然沉淀）、人工投喂（inbox 放料）、事件接入（会议/收口/治理令）。
- **投喂信任分级**（现成资产：inbox frontmatter trustLevel）——confirmed 直入消化；working 入但标注处理深度；draft 仅暂存候确认。分级消费者=消化段。
- **来源标注强制**：无源的素材不可消化——溯源是注入可信度的前提（注入进上下文的知识若无可信来源=噪声）。
- 「什么资格进管道」上游=memory.md（员工该追踪什么），五件套映射已有，本段不新增。

### ② 消化（schema 所在段）
- **消化者=agent 本席**（CEO「agent 接入消化」）——schema 是给 agent 的**可执行判据**（含示例/反例），不是替代 agent 的机械匹配器。这是 schema 的产品形态定谳：判据文档，非规则引擎配置。
- 消化动作链：**提炼**（事实+判断+待确认——编译五段中段）→ **归并**（并入已有页为主、新建页为辅——「把零散的知识形成知识体系」=对号入座+更新已有，不是每次产出新页堆垃圾）→ **阀门三决定**（归页/reject/escalate）。
- 「体系」从哪来=page-specs 页面分类体系（由 memory.md 定义）——消化的对号入座按此体系归位。

### ③ 结构化输出
- 输出物=**注入页**（上件四约束保留：结论前置/自包含/可整段用整段弃/体积预算）。
- **输出两态**：working（新吸收/消化中）与 stable（稳定可依赖）——启动注入时两态可分级处理（stable 全量；working 标注态）。
- 溯源标注强制（每结论块带来源）。
- 节律升格：会话结束=自然消化点、周度收口=批量点——现 guide 节律建议产品侧认可，升格为管道标准节律。

### ④ wiki 对接
- 对接对象=**员工自己的 wiki**（私域，CEO 原话「对接如员工自己的 wiki」）。
- 更新语义：**累计并入为主**（页面是活的，非一次性产物）；新建页为辅（仅当体系内无归位处——且新建页本身要过「体系性」检验，防页面碎片化）。
- **吸收标记（幂等）**：被消化的 inbox 源须标记，防重复消化。
- 消费=启动注入（非检索）；下游出口=升格通道（wiki→org/shared，去域化检验）——管道端到端完整。
