## §1 机制总图（CEO 骨架展开）

```
员工席任务至候批态
  →①收口钩子自动写候批信（daemon 模板生成，零 LLM——R2）＋台账同刻挂账（D-27 v2 扩展）
  →②BOD notify 拉取即见（信箱=待办聚合器：候批/候办/待阅一入口）
  →③daemon 轮询判定超时（确定性代码，频次与 token 解耦——R1）→COS 事件出场地催（不靠记忆）
  →④BOD 提醒 CEO（候 CEO 批超时主动呈报——职责增项，human-in-session）
  →⑤CEO 批→信箱 resolved＋台账销账同刻双写→自动回流开工
```

**设计铁律（CEO 23:24 指正的机制化三件）**：轮询器自动触发催办（不靠 COS 记忆）＋催办信自动生成（不靠 COS 手写）＋状态文件自动更新（不靠 COS 事后整理）——判定全部在 daemon 层，席位只在事件触发时出场。

## §2 候批信信件规格

### 信封（九字段，notify schema 向后兼容扩展）

| 字段 | 说明 |
|---|---|
| `type` | `pending-approval`（候批信）/`pending-review`（候审，席间域不进 bod 信箱） |
| `source_seat` | 写信席 |
| `target` | **bod+coo 双投**（CEO 面经 BOD 转呈——human in session） |
| `task_ref` | **双向映射键**：任务书路径#节点 id 或 LG-xxx |
| `state` | `pending-bod`/`pending-ceo`/`pending-window`（候窗不进催办池） |
| `track` | **三轨**（COO 硬依赖）：`normal`/`blocked`/`red`——red 直达轨永不积压按违时处理 |
| `waiting_since` | **素材齐备时点**（候批信或台账较早者——COO T+0 起算锚） |
| `sla` | D-27 v3 双型锚载体：`hard:<绝对时点>`/`normal:24h`（援引不复制） |
| `title`+`body` | 见下（R2 模板槽位） |

### body 四行模板（CPO 合并提案定稿；每槽≤40 字模板值，禁长自由文本——零 LLM）

`干了什么 → 候谁决什么 → 已候多久（时点+累计） → 批后会怎样+超时会怎样`（一信双后果预告=审批人零追问）

### 触发/幂等/留痕

- **生成点=进入候批态瞬间**：收口 notify 与候批信同刻自动双发＋台账同刻挂账（发生不同步即违规）；
- 信箱层幂等覆盖（防膨胀）；**留痕层只追加**（CFO 坑修正：覆盖抹首写时点则候批时长永算不出）——留痕字段**六+二**：任务书号/状态/时点/催办对象/参与席/事由＋首写时点/覆盖计数；
- 状态跃迁发状态更新信（type 同 state 新值）。

## §3 三层催办机制（时点表）

| 层 | 触发 | 执行者 | 时点 |
|---|---|---|---|
| ①催执行席 | 在办超时 | COS（事件出场，轻量注入≤2K 可压 <1 万/次） | hard 到点即催／normal 24h 软阈值；三要素＋终点（首催→重申一次→到顶按已收意见先行汇总+缺席标注） |
| ②催审批链 | **候批超时（本命题核心）** | daemon 判定→COS 出场催 BOD | hard 到点即催／normal 沿 CPO 节奏表 T+0→4h→1d→2d→5d；**BOD 提醒 CEO**=BOD 收催后或候 CEO 批超 24h（不在席照 bod 缺位缓存协议） |
| ③催督办面 | 升级态＋批量积压 | COS→COO | normal 48h 升 COO→72h 呈 CEO 汇总；**积压三档**（COO 校准）：常规同族≥3／阻塞同族≥2 即触／red 不入档；族级升级=整族决策点+督办红档+晨报瓶颈段 |

- 不吵五律（CPO）：触发即一封／同主题单信不叠／标题扫读／禁催促语气／安静时段聚合；
- 催办对表三律（CPO）：催状态不催人／升级不改口／动作即清催；
- 超时≠批准（COO 保留条款）：缺位不产生默认同意；
- 督办读数节律（COO）：每日两轮挂晨窗+夜航窗，读数不通知、动作集才发；
- 全程催办留痕=绩效效率源账面（一次留痕喂流程健康读数+绩效审计两用）。

## §4 台账-信箱双向映射

- 映射键=`task_ref`；**台账=真源、信箱=投影**（CAO 双真源防线）；
- 写向：候批发生→双写同刻；读向：裁决→`resolved`+销账同刻；
- **COS 巡检=双态对表（机制化巡检，daemon 可代判定）**：信箱 pending 台账无条=漏挂／台账候批信箱无信=漏写／时差>5min=不同步——三型差口即告警源；
- 闭环判据：任意时刻两态集合按 task_ref 对表零差口=状态机健康。

## §5 成本红线（CFO，R1-R5）

- **R1 零巡检原则（唯一翻车形态防护）**：状态/超时/触发判定一律 daemon 确定性代码，**严禁定时唤醒 LLM 巡检**（=4,300 万/天现势四成）；事件触发全链 <0.1% 周增量（噪声级）；
