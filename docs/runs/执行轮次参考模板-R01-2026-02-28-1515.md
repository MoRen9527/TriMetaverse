# 执行轮次参考模板（先读后做，单文件回填）

版本：v1.1  
更新时间：2026-02-28

用途：
- 每天/每周启动新一轮任务时，先读本模板。
- 复制本模板并重命名为本轮执行文件。
- 整轮过程（读文档、计划、开发、提交、周会、复盘）全部回填在该文件。

---

## 0) 文件命名规范（必须）

复制本模板后，按以下规则重命名：

`执行轮次参考模板-R{第几轮}-{YYYY-MM-DD}-{HHmm}.md`

示例：
- `执行轮次参考模板-R01-2026-02-28-0930.md`
- `执行轮次参考模板-R12-2026-03-15-1400.md`

建议存放目录：`docs/runs/`

## 3.5 标准执行流程（0~8，逐项勾选）

> 目的：把“开始前→下一轮”的细节和命令固定下来，每轮都可复用并可审计。

### Step 0 开始前（环境与范围确认）

- [ ] 本轮只定义 1~2 个最小可交付项（例如：先完成 `#16` MVP）
- [ ] 明确“完成定义”：`可运行 + 可验证 + 有提交 + 有 issue 更新`

建议命令：
- `git -c gc.auto=0 status -sb`
- `git -c gc.auto=0 log --oneline -3`

### Step 1 读文档并拆成可执行任务

- [ ] 已填写“2.1 实际阅读文件”
- [ ] 已填写“2.2 理解摘要”
- [ ] 任务已拆成 3~6 个小步骤（每步 30~90 分钟）

建议动作：
- 把每个步骤写成“动作 + 验收”格式：`实现 X（验收：Y）`

### Step 2 开发前准备

- [ ] 分支正确且已同步
- [ ] 本地依赖和启动命令可用
- [ ] 已确认本轮不改动边界外内容

建议命令：
- `git checkout dev`
- `git -c gc.auto=0 pull origin dev`
- `git -c gc.auto=0 status -sb`
- （按项目需要）`npm install` / `bun install`

### Step 3 正式开发（小步快跑）

- [ ] 每次只实现一个小点并立即记录到“4) 执行日志”
- [ ] 卡住超过 30 分钟时，已记录 blocker 并降级目标

建议节奏：
- 25~40 分钟开发 + 5~10 分钟自查/记录

### Step 4 本地自测与验收

- [ ] 已执行最小验证命令
- [ ] 已执行关键路径验证
- [ ] 失败项已记录在“5.3 风险与阻塞”

建议命令（按项目实际替换）：
- `npm test`
- `npm run build`
- `bun test`

### Step 5 提交 Git

- [ ] 提交仅包含本轮目标相关改动
- [ ] commit message 清晰（`type(scope): summary`）
- [ ] push 成功

建议命令：
- `git add <files>`
- `git commit -m "feat(obs): ..."`
- `git -c gc.auto=0 push origin dev`
- `git -c gc.auto=0 status -sb`

### Step 6 更新 issue

- [ ] 已更新 issue 状态（`TODO/IN_PROGRESS/REVIEW/DONE`）
- [ ] 已写入 Done/Next/Risk

建议命令：
- `gh issue view <id> --repo MoRen9527/TriMetaverse --json number,title,body`
- `gh issue edit <id> --repo MoRen9527/TriMetaverse --body-file <file>`

### Step 7 开周会/日会

- [ ] 已输出 1 分钟口径（完成/进行中/阻塞/协助/下一轮）
- [ ] 若关键路径变化，已同步到周计划模板

建议口径：
- 完成了什么、当前卡点、需要谁支持、下一步是什么。

### Step 8 周会后进入下一轮

- [ ] 本轮结论已填写
- [ ] 未完成项已转入下一轮候选
- [ ] 已复制模板生成 `R{N+1}` 新文件

建议命令：
- `$ts = Get-Date -Format "yyyy-MM-dd-HHmm"`
- `$target = "docs/runs/执行轮次参考模板-R{N+1}-$ts.md"`
- `Copy-Item "docs/执行轮次参考模板.md" $target`

## 9) 使用示例（首轮可直接照抄）

1. 复制：`docs/执行轮次参考模板.md`  
2. 重命名：`docs/runs/执行轮次参考模板-R01-2026-02-28-0930.md`  
3. 先填第 1~3 节（先读、先计划、先确认必要性）  
4. 计划确认后，再填第 4~6 节（开发、测试、提交、issue）  
5. 周会后填第 7~8 节并归档  

> 这份“本轮文件”就是本轮唯一执行线：所有细节都回填，不分散到聊天记录里。
