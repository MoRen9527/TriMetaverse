LG-035 子栏三三版才定：v1 条目下拉（存储形状直译控件）→v4 平铺组合视图（chips+默认+规则铺在卡上=策略是卡的属性）→CEO 定谳「一个策略应该是针对一个或多个模型采用的不同规则，这个组合做一个命名才是一个策略」——策略是一等命名实体，切换=在命名策略间选择（卡=策略库+活动指针）。

**Why:** 未先识别领域一等实体时，界面会把实体降格为属性平铺——功能对但产品思维缺位；「类 CC Switch」原型（命名 profile 间切换）本可提前揭示此答案。
**How to apply:** 设计前先列领域名词表并问「哪些该是一等实体（有名字、可独立存在、可被引用/切换）」；实体=命名+可管理（增删改）+可被指向；原型工具类比（「类 X」定性）在概念建模时主动回查。

**二阶教训（2026-09-13，同线 LG-035）**：实体识别不是一次到位——我升到「策略实体」即止（规则/模型集仍内嵌策略），CEO 再推翻升为三实体（模型集/规则/策略）+引用关系：同一集/同一规则可被多策略引用，「组合爆炸降为组合复用」。口诀升级：**实体抽取持续到「引用替代嵌套」为止**——内嵌数组还在，就问「它该不该是下一个实体」。

**三阶实证（2026-09-14，治理二期）**：同族毛病第二次被抓——我把 schema 的「归页/reject/escalate 三决定」当 schema 全貌，CEO 勘正「不是简单的三选一」：schema=agent 接入消化→结构化输出→对接 wiki 的**完整管道**，三决定只是消化段的阀门。抽象层级误判的第二种形态=**局部机制误当全局管道**。通用口诀：**提交任何「定义/全貌」件前，先问「这是机制还是机制所在的过程」**——阀门/节点是段，段的串联才是管道。
