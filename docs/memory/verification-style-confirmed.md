2026-08-13 r10-2 收口回执中，小贾明确认可并点名表扬的验证做法：4.3 用 `git rev-list` 独立交叉验证 ahead 计数（不单信脚本输出）、O1/O2 两个观察项（脚本 dirty 检测盲区、agent-core schema 错位）属于"真正的独立发现，不是复述"。

**Why:** 收口方判断验证质量的标准不是"结论与执行方一致"，而是验证者是否用了独立证据源、是否发现了执行方声称之外的事实。

**How to apply:** 后续每次独立验证：1) 用真实代码而非复刻逻辑；2) 关键数值用第二独立方法交叉验证（如 rev-list vs 脚本输出）；3) 主动找声称覆盖范围之外的盲区/错位并单列观察项；4) 差异按阻塞性分级（D=文档差异、O=观察项），收口方可直接按清单处理；5) 发现数字/摘录不精确时**必须给出正确值**（勘误值会被直接采纳为清单证据，仅标记"不准"不够）——r12 收口即按我的实测值（ZIP 字节数、prompt 字节范围、注册表值）登记清单 v2026.W33.15；6) **提交边界纪律**：共享工作树下 commit 前先 `git status --short`，只 add 自己的文件——他人暂存区内容会被带入（r12+ 简报 commit 曾卷入小贾的 OP 登记 4 行，虽内容一致且被认可，但须主动报备）；7) **跨仓验证 harness**：跨仓 import（TriMC 代码经 agent-core→trimodel file: 符号链）在 tsx ESM loader 下触发 'd:' 协议错误——改用目标仓库自身 `node --import tsx --test` 跑临时测试文件（放 test/ 下、跑完即删，dot 前缀不被 npm test glob 计入）；golden 防污验证用 `git worktree add` 取旧代码旧合同重生成快照，注意 worktree checkout 的 autocrlf 会引入换行假差（对比时以当前工作树 LF 原态为准）。8) **测试期望独立推导**（r2-3 打回教训）：测试里的期望路径/期望值不得与实现同源复制同一表达式——同源复制会让两侧同错，且条件断言（existsSync 为假走 else）会掩盖缺陷、命中分支从未真实执行；期望必须独立推导或硬编码，命中环境断言走真分支才算回归守卫。9) **变异测试证明守卫真实**（r2-3 重验，小贾赞为"第二方法交叉验证的极致形态"）：对「条件断言可能掩盖缺陷」的场景，不要停留在代码走读层面声称"修好了"——做变异对照实验：旧（错误）实现 + 新（修正）期望，套件必须报红；修复实现下同用例必须全绿。一红一绿才证明回归守卫真实生效。**变异必须在真仓原位做**（bb72746 快核勘误）：位置依赖函数（如 sibling 探测按模块目录上跳）被搬到 scratch 会改变深度推导——scratch 深度若恰使旧实现落在正确目标上，变异环境即被污染（曾出现旧实现意外命中真 sibling 而测试全绿）。正确形态：真仓内 cp 备份 → 写入旧版本 → 跑测试（必须红）→ 还原备份 → 复跑（必须绿）→ git status 确认干净。位置无关的逻辑才可用 scratch 副本变异。10) **测试操作疏漏诚实披露**（r19 复验，小贾定评"诚实披露比完美结果更值信任"）：验证过程中自己的操作若碰了真实生产面（如测试实例短暂共享真实数据目录），必须主动披露——包括影响面核查结论（现役零影响）、副作用清单（日志追加/pidfile 瞬态）、自愈路径分析、以及后续改进承诺（显式 TRILC_DATA_DIR 隔离）。披露模板：①发生了什么 ②已止损动作与核查结果 ③副作用清单与自愈路径 ④改进承诺。不披露比结果不佳更伤验证信用。
