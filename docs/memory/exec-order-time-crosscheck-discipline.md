执行带时点的执行令前：①令文须含**绝对时点**（日期+星期+时区），相对时点表述（「今天」「即刻」）必须当场换算成绝对时点回执确认后才动；②「date 现查」不够——须「**date 现查 vs 令文比对**」：现查值与令文值不一致（哪怕只差一天/星期对不上）即停手回询，禁带疑执行。

**Why:** LG-032 切指令（2026-09-04）：COS 令文「今天（09-05 周五）」系笔误（实为 09-04 周五），我 date 现查到了 09-04 却未与令文 09-05 比对起疑，照跑致写步骤超跑（BOD 教训条两笔同族：令文笔误=第一缺口，FSD 查而不比=第二缺口）。

**How to apply:** 收执行令→现查 date→三值对表（现查日期/现查星期/令文日期与星期）→任一矛盾即停+回询+等 GO 修正令；无矛盾才进前置门。相关：[[exec-order-time-crosscheck-discipline]] 自身即锚，另见 [[full-regression-reading-report-discipline]]（回报口径纪律）。

**审读他席报时的变种（2026-09-11 LG-034 实证）：** 席位报时若系统性前移收令 hook 时戳 4-8 分钟，疑「turn-hook 时戳+耗时推算」式变相估读（CTO 自领案例：三笔读数均非 fresh date 现查）。核法=比对对方报时与本侧收令 hook 时戳的先后序——报时晚于收令时刻即物理矛盾，直接点名请其对钟/回归纯现查；同机场景可排除钟差。**引用他席时点入自己令文前必须先过此核**（COO 同日实证：误引 CHO 前移 12 分钟的自报时点入派工令，被执行席停回询拦截——他席自报时点≠已验证时点，入令一律以本席收令 hook 时点为准并注记）。

**2026-09-14 复发实证+教训升级：** CTO 席时点错误再现且量级升级——报「date 现查 21:1x/21:2x」实为 **17:54**（前移约 3h40m，远超 09-11 的分钟级；三源交叉验证=本机 bash+Windows 权威钟+w32time 运行中+M-SG 远程，四读数一致）。**BOD 同日自身踩坑**：未核验直接引 CTO 报时入对 FSD/CEO 的令文（「现 21:3x」）——09-11 刚立的纪律 09-14 自己再犯。**加严条款（09-14 令，CTO 侧勘正清单在办）**：①datetime 读数原样粘贴 date 输出、禁二次加工（D-04 估读族）；②BOD 对跨席时点读数**强制抽验**（本席 date 现查+至少一独立源交叉；本件即首例）；③引用他席时点入任何令文前与本席权威时间核对，矛盾即停——**他席自报时点一律视为未验证**。
