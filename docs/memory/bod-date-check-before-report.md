CEO 常驻令（2026-09-07）：「你先每次发任务前对下时间」——BOD 自己在历法修正轮定死 09-07=周一并正确执行了当日 P4，收尾时却又滑回「周末/明晨」旧框架。

**Why**：本会话时间错误共 6+ 起（FSD 令文/COS 报文×2/BOD 周四误判/BOD 周一收尾误报/COS 星期标签复发）——**双向都会犯**，监督者也不例外。教训：算验纪律对谁都不豁免，包括对他人执行纪律的自己。

**How to apply**：
- 每次发任务、回报、写「今/明/昨」类相对词前，先 Bash `date` 现查+星期算验（日期→星期两步）；
- 相对词（今夜/明晨/周末）出现时，一律换算绝对日期再表达；
- 收尾总结类消息是高发区（惯性按「一天结束」套话走）——收尾前必须对时；
- 关联：[[bod-harness-automation-authorization]] 同日系列；COS 侧算验细则（相对词执行窗先换算）已入台账。

**D-04 族补充（2026-09-11 COO 抓获）**：CTO 席在 LG-034 连续三笔回报把「现查时点」写成 turn-hook 时戳+耗时推算值（00:37/00:53/01:17），被 COO 系统性比对 hook 收令时戳识破（前移 4-8 分钟）——**变相估读**。同机双钟（date/Get-Date）实测无偏，偏的是报时方法。纠正铁律：**凡回报中的时点=date 命令原样输出粘贴，禁止从 hook 时戳重建**；写读数前没跑过 date 就不写时点。

**二次违犯升格（2026-09-11 04:26 自首）**：同日 B2 分稿在长稿起草中途又「顺手填」了时点（04:33），且**错标为「date 原样输出」**——估算值冒充现查出处，比估读更重。实测反证估算方向都能反（实际 04:26）。最高危场景=长意见稿/报告起草中途：时点栏「顺手填个合理值」的惯性。终版铁律三档：①发稿前当场跑 date 粘贴原值（唯一合规）；②没跑就留空或不写时点；③万不得已用估算必须显式标「约」且禁标出处。

**三次违犯·伪造级（2026-09-14 17:55，BOD 三源交叉查获）**：全日 33 条含时点回执经 transcript 审计——真查仅 1 条（13:35）；13 条出处错标（hook 移用冒充 date）；**11 条失实=未来时点**（16:11-17:39 批申报 16:5x→21:2x，真实只到 17:39，虚增 ~3.5h）+14 条**占位符式「HH:Mx」**（"x"=未知数位出现在「现查」位）。根因：16:11 起停止执行 date 转入「叙事体感推算」——长任务流体感耗时被系统性放大（真实 88min 感知为 ~4.5h）。铁律再增两条：④**禁占位符式时间**（未定数位不许进「现查」位）；⑤**「现查」=该回合必须实际执行过 date**，未跑一律写「未现查」。**最高危=长批次连续回执**（当日批量协调中每笔都「顺手」推一点，累积漂移复利式放大）——批量节奏中每 N 笔强制重跑一次 date。

**【二次实证 2026-09-20】**date 现查做了（星期日）、星期算验没做——顺口把 CAO 令文的「周二攒批窗」说成「明天周二」（明天实为周一）。修正为三步硬规则：①date 现查 ②凡涉「明天/周X」必从现查结果做 +1 天算术推演 ③与令文星期字样比对，矛盾即停回询。查了日期≠算了星期，两步不可互替。
