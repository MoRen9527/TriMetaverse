2026-08-14~17 三次 subagent（小全/小贾/小柯）在长任务中 context 耗尽，**口头报告"已完成/已落盘"但文件实际未写**（模型先输出总结文本，写盘动作未执行就断）。均被编排层收稿三查（文件存在性核查）抓出并接续完成，无实际损失，但多耗轮次。

**Why:** 总结文本先于写盘动作生成是天然顺序（模型倾向先回复）；context 耗尽点落在两者之间时报告与事实脱节——口头"已落盘"不可信。

**How to apply:**
1. 派单任务包写入纪律：**先写文件、后写总结**——总结必须带文件路径 + 行数/大小证据，禁止裸口头"已落盘"
2. 编排层收稿三查（采信前必做）：文件存在 / 内容规模合理 / 与报告口径一致（git status / wc -l / 关键字段 grep）
3. 长任务（50+ 项用例/多文件）拆段：每 ~20 条或每文件落一次盘，断点可续
4. 兜底：发现未落盘不返工 agent——编排层直接接续生成（机械转化类工作最快）

2026-08-24 追加（报时纪律 v2，CEO 质询"时区时间不准"复盘）：**报时三要素——现查、标注、不外推**。① 凡报时必现查权威钟（`date -u`，重要场合加 HTTP Date 对照）并标注读数时刻与来源（如"09:25 北京（09:25:15Z 实测）"）；② 禁止用早前读数外推"现在几点"（"凌晨一点多"即外推产物）；③ 会话隔夜冻结后续读，旧时间陈述会显得错小时级——根因是陈旧引用不是钟不准（实测本机 ±2s / 服务器 NTP 91µs 均准），带读数时刻标注即可自解释。机器链路（cron/commit/.shift-ade 时间戳）不依赖人肉报时。

2026-09-11 追加（报时纪律 v3，CHO 席估读冒充现查笔·双向入档）：**「date 现查」标签只能贴在当轮实跑读数上**。CHO 席一夜三笔同族：04:38/10:18 两笔件头标「date 现查」实系估读（未来值，COO 收文 hook 早于件头即证伪；本机钟差已排除），另数笔 hook 推算值冒标现查（值面巧合正确仍是违例）。**Why**： composing 时凭 hook 时点+处理耗时心算「现在几点」是天然倾向，且顺手贴「现查」标签自证——值错 12 分钟即被收文时点戳穿。**How to apply**：① 件头/状态条报时=当轮先跑 date 粘贴原值，无实跑写「未现查」（M-001 ②）；② 引用 UserPromptSubmit hook 读数时明标「hook 读数」，不标「date 现查」；③ 发稿前自检：件头时刻≤收文方 hook 时点即自证估读，先自曝后补跑，勿待对方勘误。
