# 「未发生」定性前必穷尽事件日志面+等状态机终态

**正形纪律**：对闸态/守护/异步状态机类系统做「X 未发生」定性前，两道必做——①**穷尽事件日志面**：grep 事件日志须含目标事件的**反向关键词搜索**（如定性「硬闸未触发」前必须搜 `gate-hard`，不能只查当前态端口读数）；②**等状态机终态**：带防抖/确认窗的闸（连续 N 次采样才翻态）探针打到中间态=瞬态，瞬态读数禁作终态定性，先算确认窗时长再探或隔窗复探。

**错误形态（BOD+STE 双实证 2026-10-08 LG-069 夜）**：BOD 01:07 探 healthz 见 gate=soft（防抖确认窗中间态）即定性「读数分叉致硬闸未触发、闸坏了」——实际 channel.log 三行事件链 gate-soft(29)→gate-hard(18)→gate-recover(15,ac=true) 证明硬闸已自触发成功、恢复链全自驱，BOD 人工停工令只是比闸自触发早数分钟先行；STE 同窗曾 grep channel.log 但未反向搜 gate-hard，验收卷缺陷①一度列「未自触发」为主因。两席误判同根：证据面未穷尽+瞬态当终态。

**结果损害形态**：定性错误会传导进验收卷/终判卷成为「缺陷修复」依据（本次 min() 修复歪打正着仍有稳健增益，但理由前提是错的）；误判上行呈报 CEO 造成「闸坏了」错误印象。

**识别信号**：探针读数与旁证矛盾（CEO 观察「未见停工」vs 探针 gate=soft）、系统带防抖/确认窗语义、事件日志存在但只查了态不查了事件。

关联：活体优先诊断法（liveness-first-diagnostics）——活体现探是第一步，但终态定性还需日志面+终态等待两道补完。
