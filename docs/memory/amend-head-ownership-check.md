# amend 前必验 HEAD 归属

共享仓多席并行，`git commit --amend` 前必须 `git log -1` 验 HEAD==自己上一提交的哈希。「未推 amend 合法」教条的前提不止"未推"，还有"HEAD 是自己的提交"。

**实证**（2026-09-29 23:40，lg-058 p2 树）：STE N26 ts 勘正（23:48→23:39）直接 amend——未料 CPO 并行提交 26854058 已落 HEAD，amend 把 CPO 提交改写为 08dfebab（CPO 判据件改动+STE 勘正行混入同卷，提交信息保留 CPO 原文）。内容零损失，但哈希改写且已随并行席 merge 2cf3206a 扩散至 origin/dev，历史不可再动，只能事故记档+哈希引用变更知会。

**规程**：
1. amend 前三查：HEAD 哈希==自己上一提交？工作区有无并行席在途改动？该提交是否已推远端？
2. 任一不满足→改用追加勘正提交（JSONL/账本类文件 append-only 更天然）。
3. ts 类勘正优先在**提交前**用动态生成杜绝：heredoc 里 ts 用 `$(date -u +%H:%M)` 生成，禁手写预填（D-04 同族根因：预写值必然漂移）。
4. 动态生成正形=`TS=$(date ...)` **独立赋值行**在前、heredoc 在后。变体坑（2026-09-30 实证）：`TS=$(date ...) cat >> f <<EOF` 环境前缀形式只把 TS 送进 cat 的 env，heredoc 展开读的是 shell 变量（未赋值）→ ts 落成空串，比漂移更隐蔽。落完 `grep '"ts":""'` 自证一次。
