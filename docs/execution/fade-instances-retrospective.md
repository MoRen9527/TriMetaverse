## 三、提炼：一般最规范的 FADE 实例必须件（v1 规约）

在十段之上，反向确立七条强制要件（无论何种宿主/架构，缺一即不入 FADE 档）：

1. **双层留痕**：任务包层（计划/树/材料 hash）+ 运行层（registry/hook 日志）必须分离且互引。
2. **确定性拾取门**：准入门为代码可复算的谓词（如三重门），不允许模型自由裁量入队。
3. **spawn 形态契约**：执行体工作目录直落任务仓 + 白名单显式声明 + 命令裸形式（D-11）。
4. **★节点收口报告（本次新增强制段）**：每个节点完成时落 `reports/node-<ID>.md` 于树目录内，必备十字段——nodeId/agent/起止时刻(UTC)/起始基线 commit/触发来源/动作序列(时刻|动作|commit)/工件清单(path+规模或hash)/门禁结果(命令+退出码)/异常与处置/断点交接。**缺此报告的节点翻转无效**。
5. **材料完整性（卷封制）**：sourceMaterials 预封 + 开工验卷 + 收口对卷 + 漂移二选一裁决；campaign root 收口存档。
6. **blocked 分层取证八股**：取原始拒绝文本定层（审批/权限/上游）→修复定向→自愈复工不复用污染进度。
7. **收口对账回执**：结果回填源计划文档（对账节）+ 生产部署等超范围动作单列移交。

## 七、第二次立法：段合同与实现绑定（2026-08-27，回应"runId 是否必须"争议）

CEO 追问触发：六实例同段异构（登记段四种载体），runId 字段未普遍存在——是否必须？

**裁定（ade-pattern-spec v1.4.0 §2.8）**：

1. runId **字段**非必须；登记段**四不变量**（唯一/去重/关联审计链/恢复锚）必须——六实例逐个检验全部满足；
2. 协议层管不变量与产物合同，**实例层管载体**（段-实现映射表入册 schema 化，登记册十段工件表即其形）；
3. 显式度分级立法：单一显式标识 > 分散组合（FADE-002 复评 7→10 为定位成本实证），多段复杂实例推荐显式 runId；
4. 整条生命周期（触发→登记→Qualify/Plan→DCE→Score→Close→终态）同样适用此分层：每段合同化，FADE 实例逐段灵活实现——标准化任务从此"循合同自由实现"，不再削足适履模仿任何前例的载体形态。
