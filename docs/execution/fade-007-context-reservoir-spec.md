## 一、问题定义

常驻中枢（小贾，xiaojia-hub）持有完整工作上下文，但长会话会遭遇：
1. **爆上下文**：任务降雨量持续大于上下文容量
2. **语义漂移**：多次自动压缩叠加，重点被静默丢弃
3. **不可控性**：自动压缩无从审核，丢了什么没人知道

## 二、角色模型（CEO 蓄水池隐喻）

| 角色 | 承担者 | 职责 |
| --- | --- | --- |
| 蓄水池 | 编排层（CEO 直连会话） | 承接降雨（任务流）、暂存原上下文（临时文档）、对比核验、放水 |
| 闹钟+记事本 | 编排层 | 监测运行时长/压缩次数，提醒 CEO 或直接触发清空流程；暂存过渡期摘要 |
| 河水水位 | 中枢上下文 | 实际工作记忆；水位判断依据 |

## 三、流程 A：受控压缩（爆上下文风险时）

```text
1. 触发：编排层判断降雨量+水位接近阈值（启发式：会话轮数/任务体量/中枢自报负载）
2. 蓄水：令中枢产出「全量自述快照」——结构化交接文档（任务状态/决策记录/挂账/关键
   hash 与路径/未完事项/人际关系与授权边界），存 .fade/hub-snapshots/full-<ts>.md
3. 放水：令中枢压缩上下文（基于快照重建精简工作记忆）
4. 对比核验：编排层取 full-<ts>.md（原）与中枢压缩后重产的 post-<ts>.md（新）逐项比对——
   重点丢失即打回重压；拿不准→升级 CEO 确认
5. 放水完成：核验通过后删除临时快照（或归档），压缩闭环
```

## 四、流程 B：清空过渡（运行过长/多次压缩后）

```text
1. 触发：运行时长超限或压缩次数 ≥2（闹钟职责），提醒 CEO 或按授权直接执行
2. 蓄水：同流程 A 第 2 步产全量快照
3. 核验：编排层比对（同上）
4. 过渡：核验后的摘要**留存编排层上下文**（记事本职责）——中枢清空为全 0
5. 问答期：中枢工作时有不懂可反问编排层（摘要在此）
6. 退役：中枢重新积累成熟后，编排层暂存摘要删除——清空过渡完成
```
