## 一、需求正源（CEO 原话四段逐字）

### 段 1·值班位服务器化（2026-09-05）
「我的建议，直接向C进发，本来我也需要服务器上，各个员工的session级会话常开，这样的话本地不在需要spawn一个cos，直接用服务器的session级cos顶上值班位，这样蓄水互备，有人值班都齐了，服务器和本地的两套班子还变成了同一会话下的互为镜像。交互多时，启用本地这套班子，值班自动化时启用服务器那套班子，所有历史还都保留，还能防止故障有服务器级恢复。」

### 段 2·先 M 面（2026-09-05）
「我们先在M面的mc和lc建好这套值班和交互位互备的体系，之后在研究R面，因为R面不是claude code，他是以claude code为基底做的agent-core，可能更好做，可以联审，但不需要现在动手。先把M面搞定。」

### 段 3·re-baseline 协议（2026-09-05）
「re-baseline是不是可以这样，以值班位每周期去检查磁盘，如果没有变化，就不需要re-baseline，这多发生在夜间，交互位没工作。如果有变化就re-baseline，多发生在白天。值班位写磁盘，频率不会很多，直接发消息给交互位，让他re-baseline。看看可行性和成本是否ok」
（BOD 升格注记：执行层由「值班位轮询」升为「daemon 机械文件监视事件驱动」，语义不变零 token 夜间——已入五组件之 5）

### 段 4·干掉两设计+patrol 裁定（2026-09-05）
「这个设计还可以干掉两个设计，组长可以干掉不用了，加在FADE-001里的每日会话进度兜底也可以干掉了」
「patrol独有价值，daemon互备要留住。」
（裁：组长岗吸收退役；patrol 留任 sg 侧=本机关机覆盖唯一来源；daemon 互备留作后续波次）

## 二、架构（双位图）

- **交互位**=本地 session COS（小贾，全工具，指挥链中枢，交互密集时段主）
- **值班位**=服务器 session COS（全工具，sg，急件处置+临时 spawn+通知归位，夜间/自动时段主）
- **共用蓄水池**（git 三端同步磁盘真源）：台账+常驻指令区（+主备标记）+快照+升级日志（值班位专写）+任务书/提案
- **主备标记轮换**：谁主事谁写主账

## 三、五组件

1. **双位定义**：双位同全工具无白名单
2. **蓄水池写分区**：交互位=主账+常驻指令区；值班位=升级日志分区（禁写主账）；主备标记=常驻指令区一字段
3. **交接协议**：轮换规则（交互密集→本地主；值班自动化→服务器主）；交接=翻主备标记+快照一记（≤1 分钟零对话搬运）
4. **re-baseline 协议**：条件式（磁盘有变化才刷）+靶向（只读变更分区）+推拉结合（值班位写盘→推消息给交互位；交互位自写不推=防环）
5. **机械 watcher**：TriMLC/TriRLC daemon 增文件监视（蓄水池分区 mtime/哈希，零 token）→事件唤醒对应位；夜间仅机械层值守
