# 训练系统与生产系统总体架构（v2 系统论）

> **v2 修正（CEO 二次裁决 2026-08-16）**：训练期/生产期不是「两个阶段」而是**两套永续系统**——训练系统持续迭代训练（不结束），向生产系统发布正式版本（dev→prod 环境关系，非阶段演进）。本文 v1 两阶段表述保留于后作为演进记录，以本节为准。

## 〇、系统论核心模型（v2，以此为准）

### 训练系统（永续，持续迭代）

| 域 | 角色 | 架构 |
| --- | --- | --- |
| 服务域 | 审核基准 | TriMC 套壳**任意先进 harness**（claude code / codex 等，**随官方版本随时更新**获取最新能力）——目的=审核拦截不成熟 TriLC 的问题 |
| 本地域 | 自研落地 | TriLC 始终自研迭代，**吸收服务域优秀 harness 能力**；agent-core 是核心能力沉淀池 |
| 本地研发仓 | 医生 | 修复训练系统**整个项目**的代码问题 |

- 训练系统持续训练整个项目（尤其 TriLC 能力），**向生产系统发布正式版本**
- agent-core 同时发布给**生产系统的 TriMC 和 TriLC 共用**——持续吸收训练系统 TriMC 套壳 harness 的能力改进自己

### 生产系统（正式运营，独立部署）

- TriMC 与 TriLC **互为镜像和 fallback**（同跑 agent-core 成熟版）
- **7×24 小时服务域运行 + 本地域无缝执行配合**
- 可随时接受 CEO 任务 → 标准商业流程分析 → **自动生产盈利软件、自动维护、自动运营**的 AI 系统

### 训练流程（v2.1，CEO 修正 2026-08-16——否决 v2.0 编成版，依三角循环文档改进）

> 依据：docs/training/trimc-trilc-devrepo-triangle-loop.md（三角优化循环）+ CEO 四点修正。
> v2.0（C-level 入 TriMC 派任务版）已否决作废。

**流程（TriLC 发起制——贴合生产系统实际使用场景）**：

1. **任务从 TriLC 端发起**（生产系统中任务从本地域进入——训练即生产形态）
2. TriLC 执行完成 → **发 TriMC 审核**
3. 审核分流：
   - **项目系统级问题**（需项目系统修复）→ 发**本地研发仓**改进修复（**走 git**）
   - **非项目系统级问题** → TriMC **发回 TriLC 重做**
4. **岗位一对一镜像审核**：两套舰队（TriMC 舰队 × TriLC 舰队），同岗位互审——TriMC 侧小贾审核 TriLC 侧小贾的产出，给出改进意见，**循环直到审核通过**——同岗镜像互审才叫训练系统

**医生（本地研发仓）职责收窄**：只修**项目系统级 bug**（走 git）；其他项目开发由 TriMC 和 TriLC 直接推进（不经医生）。

```
TriLC 发起任务 → 执行 → TriMC 审核（同岗镜像：MC小贾 ⇄ LC小贾）
   ↑                                    │
   └──── 非系统级：发回重做 ←──────────┤
                                        │ 项目系统级：发研发仓修复（git）
                                        ↓
                                   医生：只修系统级 bug
```

### 两系统关系

```
训练系统（永续）                    生产系统（运营）
  服务域 TriMC(套壳最新 harness)        
    └─ 审核拦截 ↘                      TriMC(成熟 agent-core) ⇄ TriLC(成熟 agent-core)
  本地域 TriLC(自研) ──能力沉淀→          互为镜像/fallback，7×24
    └─ 医生(研发仓)修全项目    agent-core        │
                                  ↓ 发布正式版本 → 接 CEO 任务 → 商业分析
                                                  → 自动生产盈利软件/维护/运营
```

## 二、两阶段划界（核心修正）

### 2.1 训练期（现在 —— ？）

**定义**：TriMC = 套壳 claude code 驱动舰队（不走 agent-core），TriLC = 自研 agent-core

**架构协作关系**：教练/审核关系（**非镜像非热备**）

**目的**：TriLC 训练成熟，能力沉淀进共同核心 agent-core

#### 训练期三角色模型（CEO 比喻定论）

| 角色 | 域面 | 职责边界 | 协作流 | 实证 |
|------|------|---------|--------|------|
| **医生** | 本地研发仓（claude code） | **全栈缺陷治疗 + 能力建设**（全工作区：TriLC/TriPilot/TriMC/TriMetaverse/TriCompany/agent-core 所有仓） | 发现缺陷 → 修复源码 → 回归验证 | r4 修复链（医生治疗实证） |
| **领导+教练** | 服务域 TriMC | 审核拦截（问题不流出）+ 指导正确工作（编排任务/纠偏） | TriLC 输出 → TriMC 审核 → 拦截问题/指导正确 | M2 能力验证期（教练审核实证） |
| **被训练者** | 本地域 TriLC | 在教练审核下工作，能力沉淀 agent-core | TriLC 工作 → TriMC 审核 → 医生修复缺陷 → 能力下沉 | 训练期全流程 |

**三角色协作流**：
```
医生（研发仓）→ 发现缺陷（全工作区）→ 修复源码 → 回归验证
                    ↓
领导+教练（TriMC）→ 审核 TriLC 输出 → 拦截问题/指导正确 → 编排任务/纠偏
                    ↓
被训练者（TriLC）→ 在审核下工作 → 缺陷由医生治 → 能力沉淀 agent-core
```

**关键特征**：
- TriMC 分叉：不走 agent-core，去驱动套壳 claude code
- TriLC 自研：基于 agent-core，能力成熟后下沉
- 两域关系：审核和教练关系（TriMC 审核 TriLC 输出，TriMC 教练 TriLC）
- **不互为镜像**：不同上下文，不同 agent 同时生效
- **三角色闭环**：医生治疗全栈缺陷（不限于 TriLC），教练审核把关，被训练者沉淀能力
- **医生能力建设**：含 agent-core 沉淀面的直接开发（能力建设而非仅缺陷治疗）

**里程碑（何时算成熟 → 生产期触发条件）**：
- TriLC 能力清单全勾
- agent-core 能力下沉完成（三角色：医生修复缺陷、教练审核把关、被训练者沉淀能力）
- M4 启动条件六条达成（待重新定义，呼应三角色协作成熟度）

### 2.2 生产期（目标态）

**定义**：两侧同跑 agent-core

**架构协作关系**：互为镜像（同上下文、单活、掉线顶上 active-passive 热备）

**目的**：TriMC 直接获得成熟能力，真正互为 fallback

**关键特征**：
- TriMC 直接使用 agent-core → 基本直接获取成熟源码能力
- 同上下文：两域共享同一上下文
- 单活：同一时间只有一个 agent 生效
- 掉线顶上：active-passive 热备协议

**前提条件**：
- agent-core 双侧部署
- 能力沉淀完成（训练期成果）
- 热备协议实现
