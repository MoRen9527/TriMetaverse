## 一、财务总判断

方案成本形态健康，方向 APPROVE 倾向，附三护栏（§三）。值班位**非常烧 token 回路**：组件 5 机械 watcher 零 token 夜间、re-baseline 条件式靶向、双活镜像被吸收为主备轮换（砍掉一份常驻上下文成本）、组长岗吸收退役（P1-P3 基建转用=沉没成本复用，零新增建设费）。增量成本=一次性施工会话投入（P1-P3）+事件驱动边际 token（P4' 后）+sg 侧边际资源。

如实标注：sg 服务器成本与 GLM 单价**均无实盘台账**（全仓勘过，见 §五）——本意见全部为框架与阈值建议，不含绝对金额判读；涉绝对金额的 APPROVE/FREEZE 判读升 BOD/CEO。

## 二、三块预读读数

### 1. 服务器会话常驻成本

- sg 为在役服务器（TriMLC/TriMMC M 面口径同侧+河源 TriRMC cron），值班位 claude 会话边际成本三项目前可识别：进程内存+磁盘（仓 clone+快照增长）+同步带宽。sg 固定成本是否已付、余量水位——**无台账，待确认**（候 CTO/COO 给规格与水位读数，不阻塞方向判定）。
- 快照是唯一无界增长项：交接=快照一记（组件 3）。建议 P3 交接协议实装件带**快照保留策略**（滚动 N 份+容量上限），防磁盘慢性膨胀。

### 2. GLM token 值班位耗用

- 值班位 token 形态=「事件唤醒次数×单次恢复上下文成本」，非线性常烧（提案件 BOD 升格注记：零 token 夜间已入组件 5）。主要财险=**唤醒频次失控**：白天写盘频繁→高频唤醒×每次 session 恢复重载上下文。
- P4' 观察周收「唤醒次数」读数并设周频次上限护栏（§三-2）；超限处置=watcher 去抖/事件批量合并，非停用。
- 值班位耗用须**单独记账**（key 归因或日志标记）——无账则 P4' 转正判据无财务读数可依。

### 3. 密钥治理口径（裁点②）

- **实缺口**：「Wave 0 治理」全仓无正身（grep 仅 LG-033 自引；keys.json 仅文件名级线索于 lg-022 勘察件）。照 D-16 指针质量口径（失联=验收不过），P1「密钥走 Wave 0 治理」现时为**空引用**。（**2026-09-08 清偿**：正身落 `TriCompany/docs/engineering/glm-key-governance.md`——CAO+CFO 两席联合起草候 CEO 批，本五件要件全数入正身 §二；本缺口判语冻结为历史留痕。）
- 财务面裁点②意见：**P1 密钥步骤放行前置=Wave 0 口径先落正身**，最小五件：
  1. 值班位 key **单列**（禁与本地开发 key 共用——盗刷隔离+审计可归因）；
  2. 平台侧支出上限/配额=**财务止损阀**（泄露损失从无界变有界的唯一机械手段，应作硬要件非最佳实践）；
  3. 禁现值入仓（提案件已有）；
  4. 轮换与吊销流程一行；
  5. 值班位耗用记账落点一行。

### 4. 分期投入产出

- P0 已毕（沉没）；P1 一次性施工（CEO 已令启动，财务不设闸，走当周 operating record 记账）；P2-P3 小额施工投入；**P4'=财务读数门**：一周观察收三读数（值班位周 token 耗用／唤醒次数与恢复成本趋势／sg 资源水位），转正判据建议加财务读数达标项。
- 产出四项（框架）：①服务器级故障恢复（对照基线=fade-007 SOP 重建成本）；②历史保留（上下文重代价减少）；③夜间值守增强（patrol 留任不受损，纯增量）；④组长岗退役（负维护成本项）。
- 投入偏差与 recurring 项直接适用授权矩阵现行分层（累计偏差 5%/15%、一次性 20/100 USD、recurring 10 USD·月），无需新立。

## 三、预算护栏建议（三件）

1. **P4' 转正门=财务读数门**：三读数（§二.4）+周唤醒频次上限；读数不齐不转正。
2. **值班位 key 止损阀**：平台侧配额上限+单列归因，作为裁点②硬要件写入 Wave 0 正身。
3. **快照保留策略**：滚动上限入 P3 实装件，防无界磁盘增长。
