## S1·IA 重构（§2 一 URL 三区+addendum 两件）

1. 页头：`TriModel 模型配置`+连接设置折叠组（API 令牌/管理令牌两输入+眼睛复用）——**addendum ①**：本机无已存令牌（localStorage 两键皆空）→首启自动展开一次+引导文案「首次使用：请填入 API 令牌与管理令牌（向管理员获取），填完点刷新」；已有令牌→保持折叠+页头「● 已连接」状态点（绿=两令牌在位/黄=缺管理令牌）。**禁**：弹窗/每次提醒/多用户分级。
2. 状态条「当前生效」：当前模型｜来源｜一致性 ✓/✗｜[刷新]——**零输入控件**（③②修：两令牌移页头，本区只读）。
3. 【TriMMC 信息】主卡首位卡片式（§1③ 命名采纳：栏=「TriMMC 信息」；区=机器信息/模型信息/模型切换策略；全 UI 禁「子栏N/候选池/规则表/固定规则」结构词汇）。
4. 【本机策略（高级）】折叠区：P1 策略列表/密钥状态原样收敛——**addendum ②视觉归属**：主卡=实线边框+云图标+卡头副注「保存后待应用」；本机折叠区=灰调边框+显示器图标+副注「本机改动即时生效」；两句副注即全部语义禁加术语解释。验收判据=不展开折叠区可视觉分辨两区。

## S2·TriMMC 卡实现（§3 全节）

1. 徽标中文映射（§3.1）：pending→待应用（橙）｜applied→已生效（绿，附最近应用时间）｜failed→失败（红+原因一行）｜无文档→未配置（灰）。禁英文枚举直出。
2. 机器信息：名称必填；连接档案预置只读折叠。
3. 模型信息条目交互唯一模式（§3.2）：列表列=条目名｜厂商｜模型｜密钥（尾 4 位）｜启用（**行内开关**——②⑥修：已存条目行内可切，非仅新增表单）｜操作（编辑/删除）。「添加模型条目」→卡片表单（标签在上一列对齐，纵向堆叠；字段=条目名必填/厂商下拉/模型下拉/API Key 必填密文眼睛/base_url 高级折叠选填）；编辑=行内按钮预填同表单（标题「编辑条目 X」）；**无覆盖语义**（同名=更新该条目）。删除被「当前使用」引用→阻断文案「该条目正被切换策略使用，请先改选其他模型」（禁「悬挂引用/400」黑话）。
4. 模型切换策略（§3.3）：「当前使用」下拉=**仅已启用条目**（选项文案=条目名（模型名））；空态=「暂无可用条目，请先在模型信息中添加并启用」；停用当前使用条目→自动回落默认+黄提示「已回落：条目 X 已停用」；时段/额度占位文案保留。

## S3·数据绑定硬规则（§3.4+①⑤根治）

1. 模型下拉=GET /v1/models 填充；渲染失败=错误空态+重试钮（禁静默空下拉）。
2. 一切选择器派生自实际数据；空态必有引导文案；加载失败必有人话错误态+重试。
3. **首启链重構（①⑤根治核心）**：boot 序改为「读 localStorage→有令牌则拉数据并显示 ● 已连接→无令牌则**全数据面板禁用态+引导展开连接设置**→令牌保存→**自动重拉全部数据**（去静默）」。任一 fetch 失败=面板内人话错误+重试钮，禁静默空。

## S4·语义统一（§4 架构裁决）

TriMMC 卡内一切写动作（条目增删改+当前使用）**只写卡片→待应用**；**废除卡内「选为固定使用」直写本机 policy 即时生效按钮**（v3 §4 实勘违规点）——固定规则意图随卡保存，COS 应用时落 sg 侧 policy。本机折叠策略面保留本机直写直生效（与卡无关）。卡内禁「即生效」类文案。

## S5·存储归并（§3.5 CTO 方案——本稿核心裁定）

**裁定：条目=provider key 唯一活源；keys.enc 一次性迁移后退役。**
1. 读链统一：`readKeys()`（/v1/config/keys 与 3334 代理共用 derive 函数）=**从 trimmc-card.json 已启用条目按 vendor derive**（同 vendor 多条目取最新 updated_at 者）；回落序=entries→env（.env 保留最终引导兜底）；keys.enc 退役不再读。
2. 一次性迁移：boot 时 keys.enc 存在→按 provider 合成条目（deepseek→deepseek-v4-pro/glm→GLM-5.3/trimetaverse→TMV，标记 auto_imported）→keys.enc 改名 keys.enc.migrated（不删，留证）；迁移幂等（.migrated 存在即跳过）。
3. P2 `PUT /v1/config/keys/secure` 端点**退役**（410 Gone+人话指引「请在模型信息条目中录入密钥」）；其 gate 测试族随退役改写（STE 域）。sg 侧运维通道同步改=sg /ui 条目表单录入（sg CC 访问 loopback UI 即可， ADMIN_TOKEN sg 值不变）。
4. SEC 不回退清单（全保留）：at-rest 逐条目加密/masked 尾 4/只写不读回（GET card 的解密仅 COS admin 通道）/损坏 fail-safe 回落 env/含 * 拒收/SEC-20260813-001 白名单（transition 记录零密钥材料）。

## S11·⑧按机分域架构（策略作用域=TriMMC 卡目标机）

**三选一裁决：取「按机 policy 文档+作用域求值」（a+b 合体），拒多实例引擎与生效路由。**
1. 存储：`policies/<machine>.json`（machine=卡 machine_name 规范化小写连字符；本机=固定名 `local`）。boot 幂等迁移：现存 policy.json→policies/local.json（改名式，同 keys.enc 族；迁移后原路径不再读）。
2. 引擎：`evaluatePolicy(machine, now)`——逐调用读对应机文档（零缓存零重启语义与 readSecureKeys 同族）；**单函数单实现，机为参数**——非多实例引擎。
3. 生效路由：3334 代理 env `TRIMODEL_PROXY_MACHINE`（sg 部署设 =其卡机名）→求值该机文档；本机 3333 状态条/本机策略面=`local` 域（P1 语义原样保留，折叠区目标不变）。
4. 卡与策略关系：卡 rules（引用清单）保存=pending 意图；COS 应用=把卡 rules 落到**目标机**的 policies/<machine>.json（经既有 sg 通道）——同 schema 双侧，apply=传输非转换，零双轨维持（每目标机一份真源，本机 local 域独立）。
5. 零双轨出证延续：单 evaluatePolicy 函数+rg 无第二模型输入源+固定规则自动贯穿代理（代理机器名参数化后同证）。
6. 迁移与兼容：本机折叠策略面（local 域）UI 不变；卡侧 rules 编辑 UI（S2 模型切换策略）写卡文档；两域 UI 入口分属两区不交叉。
