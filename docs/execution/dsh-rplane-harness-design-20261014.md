- **总形态：并存分层**——TriRMC（8710）保持机制层（cron/信箱/账本），dsh 作执行层 harness 新装河源；非替代非包装。

## 一、dsh 与 TriRMC 关系与装法（审点①）

### 1.1 关系定性：并存分层（机制层/执行层分离）

现役本地域拓扑对称参照：TriMLC（8713·机制层：cron/信箱/健康投影）+ agent-core（执行层 harness：席位会话运行底座）——两 daemon 两职责，互不替代。

R 面对称落位：

| 层 | 河源现役 | dsh 装设后 |
| --- | --- | --- |
| 机制层 | TriRMC 8710（cron 3 job·mcLedger·healthz） | **职责零变更**——不因 dsh 装设动机制域 |
| 执行层 | （无——R 面现无班组 harness） | dsh 新装：R 面班组席位运行底座 |

- **不替代**：TriRMC 不是被替代对象（它本就不做 harness）。
- **不包装**：dsh 不是 TriRMC 的插件/子进程——独立装设·独立生命周期·经信箱/树协议与 TriRMC 协作（同本机 agent-core 与 TriMLC 关系形态）。
- **同宿主盲区注**：dsh 与 TriRMC 同宿主（河源机）——宿主级故障（宕机/断网）时双盲·与 dev 机 l1 探针同构；跨面探针对补位属另一卡（今晨候立卡「sg 探 dev 向」对称面=「dev 探 R 面」已由 l2 覆盖）·本稿不重复处置。

### 1.2 装法

- **装设位**：河源机 `/srv/fleet/` 同构位（M 面 sg 工作区同构惯例·D-24 机位断言先勘后装）。
- **模型配置**：TriModel 配置层原生承接——key-cache 键族已含 DEEPSEEK API_KEY+BASE_URL（TriCode key-cache.ts:446-464 现役）；MMC 域四级梯第四级常量保底=deepseek-v4-pro 已在域。dsh 模型卡照 glm-5.3 三端配置点位先例接 TriModel 卡面（presets 真源字段）·选型登记入 TriCompany 技术选型登记（本席 owner 职责）。
- **装设烟测门**：TriRMC 信箱一来一回（8710 mailbox 投递→dsh 值席收→回执→TriRMC 记账）+ healthz 三读数（ok/mcLedger/cron）前后对表零扰动。

## 二、dsh 班组形态（审点②）

### 2.1 与 m-duty 班组同构性：同构降配·非全量复制

- **同构项**：值席制（duty 轮值/值席组稿与勘正权界照 D-27 执行层标准）·信箱接令·树协议落卷·毕报制。
- **降配项**：一期**不复制 13 席**——R 面班组本职=输入腿回流（差③）+河源机操作（差④），最小形态起步：

| 席位 | 一期（窗1） | 二期（窗2） |
| --- | --- | --- |
| 值席（R-HY duty） | **1 席**——河源 SSH 日常持有+窗况/施工力读数回流+信箱接令 | 轮值制（≥2 席对轮·消单点） |
| 施工力 | 0（河源施工暂走 BOD 特批 SSH 或候二期） | 候裁增编（FSD/STE 型 1-2 席·视 R 面施工量） |

- **席位定义面**：R 面班组走轻量五件套（source-agents/ 下新增 r-plane-duty/ 岗位定义——身份/职责/权界/前置核查/落点五要素齐备·不照 13 席全量；泛化报到制（今日联审方案）适用域判据含之——「有 session-only 运行态需重建+无人格 workspace 恢复链」→**入报到制适用域**·上线即到 CAO 处报到）。
- **正名建议**：席位通信名 `r-duty`（照 m-duty 命名族）·惯称候 CEO 定。

## 三、输入腿回流接口形态（审点③·差③销位）

### 3.1 谁报/经谁/频率

| 要素 | 定案建议 |
| --- | --- |
| 谁报 | dsh 值席（r-duty）——读数生产位 |
| 经谁 | **树协议为主**（TriRMC 侧落卷 operating-records 树→git 同步→M 面可读——现役先例=夜航01/批令执行波/周平面迁移·git-based 可审计）；**HTTP 直推为急件便道**（窗况急变时 TriRMC→M 面值席信箱·须退役时点条款照 TriRLC 转发壳先例） |
| 频率 | 定时 tick 30min（照 M 面 tick 节拍）+事件驱动即时报（窗况急变/daemon 异常/施工力状态翻转） |
| 对接面 | COO 四面统一盘 R 面列——读数最小集：窗况（在窗/候窗/空闲）·施工力（可用/占用/无）·daemon 健康（8710 healthz 三读数转抄）·在办事项一行 |

### 3.2 接口合同要点

- 读数报文格式固定（树卷模板·字段名/时戳形态照树文件路径规范+D-47 落款纪律）；
- 机位断言头必带（D-24：报文自报机位=河源/R 面·防跨机混读）；
- 断链豁免：河源→GitHub 通道故障时 tick 缺拍不告警（照 l1 睡眠冻结豁免形态·恢复后补报）；连续 N tick 缺拍（建议 4=2h）升级 M 面值席信箱。

## 四、河源通道权界与权限分级（审点④·差④销位）

### 4.1 三级分权

| 主体 | 权界 |
| --- | --- |
| **dsh 值席（r-duty）** | 河源 SSH **日常持有者**——日常操作/施工/daemon 运维/TriRMC 观测；差④正解承接位 |
| **BOD** | 直操**退役**（差④销）——保留**紧急回滚协调权**（照董事会宪章职能）：紧急窗特批直操或令 r-duty 执行·操作留痕入账 |
| **M 面（本机/sg）** | **不经 SSH 中转河源操作**——跨面交互走树协议/信箱（跨机操作路由原则照旧：哪个面的活走哪个面的通道） |

### 4.2 root 与密钥治理（候 CHO/安全会签项·窗2 落）

- 现状：root 单账号·密钥 BOD 持有（R-HY-key.pem）。
- 建议：①窗1 过渡期=现密钥 BOD 暂持+特批代开（r-duty 尚未起）·窗2=r-duty 换发**专用操作密钥**（独立 key pair·权限面候裁：独立操作账号+受限 sudo 优于 root 直用）②root 密钥轮换与持有权移交走安全审查（涉 CAO 安全面+CHO 生命周期面·两会签）③退役即清点：BOD 直操退役时点起·旧密钥 access 面撤销候裁。

## 五、与 agent-core 双 harness 并存的架构治理（审点⑤）

1. **分域原则**：harness 选型按面按域裁——本地域（M 面）=agent-core（claude 2.1.88 移植版·现役不动）；R 面服务域=dsh（deepseek 系）。判据=该面模型可用性/成本/合规（阿里云 cn-heyuan→deepseek API 近零延迟·低成本·国产合规）——**不搞全公司单一 harness**。
2. **接口合同先立后装**：dsh 须实现与 agent-core 同构的接口面方可班组上线——同构清单：①信箱协议（TriRMC mailbox 投递/回执/记账）②树协议读写（operating-records/briefs 落卷形态）③cron 等价面（若 dsh 席位需定时任务——session-only 特性对齐）④生命周期面（起停/复活名址注册——本机席位复活名址缺口先例照避）⑤SendMessage 等价面（跨席消息）。**验收门=同构清单逐项过**——缺项不上线。
3. **模型配置统一面**：两会话面模型键位统一走 TriModel 卡面（Provider/Model 统一配置层职责域）——dsh 不自建模型配置旁路（防配置分叉）；deepseek 模型卡照 presets 真源字段入卡。
4. **版本与升级治理**：dsh 版本线独立于 agent-core·升级走独立窗门（build+烟测+24h 观察·照四卡窗门禁形态）——两 harness 升级窗不互排（防同窗双 harness 同变）；选型登记与版本现势归 TriCompany 技术选型登记（本席维护）。
5. **观测对齐**：dsh 班组活性纳入探针族——窗2 落（8710 侧探针 dim 扩展或 l2 扩 dim·照卡④同款条款：additive/debounce/零敏感值面/上线后 24h 观察窗）。
