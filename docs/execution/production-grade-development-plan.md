## 二、运行模型：双环

### 2.1 生产环（日常运行面）

```
TriCade（桌面入口，CEO/用户操作）
  → TriLC 主力执行（安装态 MSI 版本，本地域）
  → TriMC 把关审核（服务器编排层：diff 审查、门禁核验、舰队独立审核结论）
```

- 服务器舰队官方 claude 在 M4 前仍存，承担审核面与 fallback（互为 fallback 契约不变）。
- 生产环会话载体：trilc chat 为生产面入口；生产面只落问题登记，**不就地改研发仓代码**（写方向单主体纪律，见 §四）。

### 2.2 研发环（问题修复面）

```
生产问题 → 落文档登记（§五 台账）
  → 归仓路由（§五 归仓路由表）
  → 本地研发仓修复（TriMC 仓问题直接改 TriMC；跨仓问题改研发仓后经 TriMC 审核）
  → push 裸仓 → 舰队审核
  → 版本门禁（§六）→ 发布回生产（新 MSI/ZIP + 服务器 dist）
  → 生产验证闭环
```

- 研发环会话载体：本地 claude code 会话为研发仓主力；与 trilc chat 并行分工，最终方案以文档为共享协调面（本方案 + parity 计划投影 + OP 周平面 + 周记决策登记），两边经同一 git 同步链路读取。

### 2.3 双环衔接点

双环唯一的物理衔接 = 发布动作。发布前必须过版本门禁；发布后生产环验证结果回流研发环（形成新一轮问题入口）。

## 三、共享周工作平面与写锁规则

OP 周平面、tree-op、树文件、brief 是生产环与研发环的共享协调面。写规则三条：

1. **树节点文件范围锁**：树节点持有其范围内文件（brief、相关状态文件）的写权；同一文件同一时刻只允许一个写者（谁持有节点谁写该节点范围的文件）。跨节点文件冲突由编排层裁决。
2. **OP / tree-op 编排层统一写**：OP 周平面索引（OP-YYYYMM-Wnn-001.json）与各树 tree-op.json 只由编排层（小贾 / TriMC 编排面）写入，执行节点只回写自己的 checkpoint/brief，不直接改 OP 与 tree-op。
3. **周平面文件维护权（方向例外）**：OP / tree-op / 树文件维护权在 TriMC 编排层——服务器侧可直接维护周平面文件（如定时周平面迁移在服务器执行时的写入），经 git 同步回流本地；**代码文件修改仍一律本地发起**（本地 → 裸仓 → 舰队克隆，写方向单主体）。周平面文件与代码文件两者方向不同，以文件类别为界，不混淆。

## 四、代码仓治理：分支-标签-审核-兜底

1. **分支**：中改、大改走 feature 分支（`feat/<scope>/<desc>`），审核通过后合并 main；小改可直接 main + 单票审核（见 §五 护栏）。
2. **标签**：每个发布版本打 tag（`v*` 触发 CI 构建惯例不变），生产环运行版本与 tag 一一对应，回滚 = 退回上一 tag。
3. **审核**：TriMC 审核面出具把关结论（覆盖质量、错误处理、纪律遵守）+ 独立验证（小柯式第三视角）；收口门禁 v2 照旧（判定 + 清单登记 + push 三仓同步 + 最终报告）。
4. **兜底（三副本灾备）**：代码三副本 = 本地研发副本（D:\Code\ai\*）→ 服务器裸仓（/srv/git/*.git）→ 服务器舰队工作克隆（/srv/fleet/*）。任一副本丢失可从其余副本恢复；舰队不可用时，研发仓小贾接手编排兜底（见 §九）。

### 5.4 自我改造护栏

| 规模 | 判定线 | 通道 |
| --- | --- | --- |

## 六、发布节律与版本门禁

- **节律**：按需发布（缺陷修复随时发）；当周有改动则当周至少一版（版本号递增）。
- **门禁（每版常设）**：过能力清单 5.x 生产链标准——5.1 MSI 构建全链路 / 5.2 安装态验证 / 5.3 服务管理 / 5.4 升级与回滚（M2-R12 已全过，从一次性验收转**每版常设门禁**）；另加独立复核（小柯式第三视角）。门禁不过不发布。

## 九、三小贾收敛设计

现状存在三个运行时承载的「小贾」实例：① 服务器舰队小贾（官方 claude 会话）② trilc 小贾（本地 TriLC 运行时）③ 研发仓小贾（本地 claude code 会话，过渡兜底编排）。收敛原则四条：

1. **身份是数据、运行时可替换**：员工身份由合同 + 五件套（soul/memory/skills/tools/contracts）数据定义，运行时只是执行容器。合同单一真源 r13 已达成（source-agents 14 份唯一合同真源）。
2. **五件套 memory 统一落点 TriCompany 仓**：待做，列为生产级开发期消化项（当前 memory 散落在本地 .claude projects 目录等分散落点）。落地后任一运行时装配同一份记忆。
3. **互斥上岗**：同一员工同一时刻一个 active 实例——由树节点文件范围锁保证（§三第 1 条）：谁持有节点谁写该节点范围文件，跨运行时不得并行写同一范围。
4. **研发仓小贾 = 过渡兜底，随四阶段淡出**：舰队/生产面不可用时接手编排（§四兜底）；阶段四完成时交出编排主力位，仅保留文档投影/计划登记职责。
