## 四、Score 载体方案（评估+建议）

**评估：patrol 自测 24 项不可直接升格为 Score CLI。** 层次不同：自测=构建期对**工具本身**的沙箱单元测试；Score=运行期对**每一个真实 run 产出**的覆盖检查（当日节在否/结构齐否/锚点合规否/三端达否）。把前者包装成后者=细则 10 违规（本包明令禁止）。

**建议方案：patrol 扩展 `--score` 模式（单实现防 §7.4 双实现）。**
- 复用 patrol 既有 parse/verify 助手（同一文件内），新增评分模式：对指定日期（默认今日）输出 §2.2 envelope——当日节存在/三节结构齐/锚点 ≥7hex 抽验/三端 refs 对齐（ls-remote）/巡检 commit 格式合规/skip 轮无空节。
- exit code 门=Verify 复用（一具两段同 FADE-007 先例）；结构化 JSON=Score 素材。
- 首跑=下一个真实维护事件（事件驱动写或巡检补写发生时即跑，非人造单独跑分）。
- Score Skill 成文：语义评定维度=叙事质量（粗粒度三节是否可重建可用）/治理对齐（分权制：触发权董事会、执行 patrol、助理主叙事）/单写者合规；双席抽验常设（利益声明同款——组织者=执行体，自证风险结构性存在）。
